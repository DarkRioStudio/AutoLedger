## 执行版总控

本计划从 2026-07-01 起进入执行版。后续开发按 GOAL 拆分推进，每个 GOAL 都必须能独立回归、独立提交、可回滚；跨 App / Worker / ASC 的能力先冻结合同，再落具体实现。

执行顺序：

1. `GOAL-2300` 先冻结 Free / Pro 边界、数据隐私边界和验收口径，避免后续实时 OCR、韩语、多币种、ASSN 或 ASC 自动化互相改变基础承诺。
2. `GOAL-2302` 固定 App i18n 发布矩阵，把每个语言都按商店可见、界面可读、基础识别可用、真实样本回归、地区支付 / 票据格式专项优化五项门禁管理，避免只翻译 UI 就对外宣传支持。
3. `GOAL-2312` 与 `GOAL-2309` 优先启动。ASC metadata-as-code 先做 audit / dry-run，`common-api` 先做 manifest、地点目录、汇率和天气响应合同；两者都先建立可重复验证的基础设施。
4. `GOAL-2310` 在 `common-api` / entitlement 合同稳定后启动，先实现 App Store Server Notifications 的验签、幂等和服务端 entitlement 状态机，不反向影响端上 StoreKit 即时解锁。
5. `GOAL-2305` 与 `GOAL-2308` 作为免费基础体验并行推进：实时 OCR 不进入 Pro gate，韩语 UI 和韩语识别包同时补覆盖门禁与 golden cases。
6. `GOAL-2315`、`GOAL-2320`、`GOAL-2330`、`GOAL-2340`、`GOAL-2345` 在基础设施和免费能力稳定后进入 Pro 自动化实现，逐项补免费替代路径、Pro gate 和过期后历史可访问验证；Pro 页面里展示的后续方向必须同步回本文档，避免 UI 与计划脱节。
7. `GOAL-2355` 与发布资产阶段一起推进 AutoLedger / AutoNotice 家族化品牌升级，先做 Icon Composer 多层源文件和导出规范，不在 ASC 1.5.0 审核热修中反复改图标。
8. `GOAL-2360` 在发布前作为隐私安全观测基础设施推进，只采集 allow-list 内的匿名聚合诊断 / 使用状态，用于判断启动、导入、购买、Common API 和隐私 payload 是否适合扩大 TestFlight / 商店宣传。
9. `GOAL-2350` 最后做 ASC 1.6.0 审核材料、截图 / App Preview 矩阵、Review Notes、隐私说明和 TestFlight smoke 归档。

执行门禁：

- 每个 GOAL 开工前更新范围、关联文件、测试命令和回滚方式；收尾时回填 `process/iteration-log.md` 与 `CHANGELOG.md`。
- 涉及 App 代码的 GOAL 至少通过 `git diff --check`、本地化覆盖、相关离线 / golden 回归和对应平台构建；纯文档 / ASC 脚本 GOAL 至少通过 diff 检查和 dry-run / audit 输出验证。
- 涉及 Cloudflare Worker 的 GOAL 必须提供本地测试、wrangler 配置边界、secret 不入库证明和 production / preview 部署回滚路径。
- ASC 写入脚本默认 dry-run，只有显式 `--apply` 且输出 diff 已人工确认后才写入 App Store Connect；第一版不自动提交审核。
- `common-api` 只处理公共目录、汇率、天气和订阅生命周期所需的最小字段，不接收账单原文、邮箱内容、酒店 PDF、截图图片或个人消费明细。
- 涉及 analytics / dashboard 的 GOAL 必须先更新事件 allow-list、禁止字段 guard、PrivacyInfo / ASC 隐私口径和 Worker 合同测试；任何包含金额、商户、截图、PDF、邮箱、酒店标识、精确位置、OCR 原文、StoreKit 交易标识或支付方式的 payload 都必须被拒绝。
- 任一 GOAL 若改变免费能力、历史数据访问或 Pro gate，必须同时更新 `docs/pro-access-audit.md` 并补回归。

## 0. 定位

`v1.6.4` 的 Pro 内容主要围绕酒店水单、邮箱候选、专属收件箱、批量候选和高级去重，解决的是酒店消费模块里的重复劳动。

`v1.7.0 / ASC 1.6.0` 承接八条主线：

1. 把首页“票据扫描”从当前拍照后识别升级为实时 OCR 扫描；不支持实时扫描时，回退到现有拍照识别照片 / 相册导入路径。
2. 在现有简体中文、繁体中文、英文、日文基础上，新增韩语 `ko` App 界面本地化和韩语账单识别语言包，并用独立 i18n 发布矩阵管理后续语言的商店、界面、识别、样本和地区票据优化。
3. 建立可在多个个人 App 复用的 `common-api` Cloudflare Worker 基础设施，用 manifest 热更新常用国家和地区 / 城市目录，提供汇率查询，并迁移既有 WeatherKit 能力，为酒店消费提供符合入住日期语义的历史天气摘要。
4. 接入 App Store Server Notifications，建立 Pro 服务端订阅生命周期闭环，让云端水单收件箱等服务端能力能主动响应续费、过期、退款、撤销、账单重试和宽限期。
5. 建立 App Store Connect 发布材料自动化，把商店元数据、推广文本、描述、新增功能、隐私链接、Apple TV 隐私正文、订阅本地化、截图和 App Preview 变成 repo 内可审计的 metadata-as-code。
6. 承接更广义的 Pro 自动化扩展，把 Pro 从酒店水单自动化推进到全账本效率层，重点补商户名称归一化、分类学习和数据清洗建议。
7. 建立隐私安全发布观测：用 allow-list analytics、D1 聚合和只读 dashboard 辅助判断启动、导入、汇率、购买、Pro 边界和隐私 payload 是否稳定；该能力不是营销卖点，不用于追踪用户。
8. 升级品牌资产：AutoLedger 与 AutoNotice 采用同一套 Apple 原生多层图标家族语言，但保留各自清晰的产品识别。

> 免费版继续完成完整记账流程，Pro 帮用户在账本增长后更快查找、发现异常、生成月结资料，并批量应用规则。

本版本优先完成首页票据扫描体验升级、韩语多语言扩展、`common-api` 基础设施第一版、Pro 服务端订阅生命周期闭环、ASC 发布材料自动化第一版、隐私安全发布观测、品牌资产升级规划，并实现 `v1.6.4` Pro 页面路线图预告中的非酒店模块能力；其中数据清洗主线需要从 Mac 端继续推进，同时保证 iOS 端可复用同一套模型与采纳结果。

### 1.1 首页实时 OCR 票据扫描

目标：用户点击首页“票据扫描”后，默认进入实时 OCR 取景框，对准纸质小票、支付凭证或屏幕上的账单即可看到识别状态；当系统或设备不支持实时 OCR 时，自动回退到当前拍照识别照片路径。

计划能力：

- 首页“票据扫描”默认打开实时 OCR 扫描界面，而不是先打开系统相机拍照。
- 识别过程中显示取景框、文字命中状态和“识别到账单信息”的轻提示。
- 对识别文本做短时间稳定 / 去抖，避免每一帧都触发解析。
- 用户确认后将稳定 OCR 文本送入既有 `LedgerTextInterpreter` / `LedgerStore.importRecognizedText` 流程，沿用当前 OCR 导入、摘要和调试记录策略。
- 支持手动切换到“拍照识别照片”和“从相册选择”，方便弱光、长票据、屏幕反光或实时识别失败时使用。
- 对不支持实时 OCR 的环境自动 fallback：不支持 VisionKit 实时扫描、相机不可用、权限被拒绝、Mac Catalyst、模拟器能力缺失或系统报告扫描不可用时，回到现有 `CameraPicker` / `PhotosPicker` 路径。

建议工程方案：

- 新增 `LiveReceiptScannerView`，优先使用 VisionKit 实时文字扫描能力；用 `#if canImport(VisionKit)` 与平台条件隔离，避免影响 Mac Catalyst / 截图模式构建。
- 新增 `ReceiptScanMode` 或等价状态：`.liveOCR`、`.cameraPhoto`、`.photoLibrary`、`.unsupportedFallback`。
- 新增 `ReceiptScanCapability` 探测：相机权限、实时扫描支持、实时扫描可用状态和当前平台。
- 实时 OCR 输出只保存短期内存态，不落库、不上传、不写入调试记录原文；用户确认导入后才沿用现有调试 / 导入链路。
- 复用当前 `OCRService` 和 `CameraPicker` 作为 fallback，不重写拍照识别照片链路。

免费边界：

- 实时 OCR 票据扫描属于基础记账入口，继续免费。
- 单张截图识别、拍照识别照片、相册导入、手动确认和历史查看编辑删除继续免费。
- 不把实时扫描放入 Pro gate。

验收口径：

- 支持实时扫描的 iPhone 上，首页“票据扫描”进入实时 OCR 取景框。
- 实时识别到有效账单文本后，用户确认可进入既有 OCR 导入链路，生成账单或现有失败 / 摘要状态。
- 权限拒绝、实时扫描不可用、无相机或 Mac Catalyst 环境下，入口能自然回退到拍照识别照片 / 相册导入，不出现死路。
- 相册截图入口仍保留，不被实时扫描替代。
- 扫描取景过程中不自动保存账单，仍需要用户确认稳定 OCR 文本后才进入导入链路。

当前执行进度（2026-07-02）：

- 已新增 `LiveReceiptScannerView`，首页“票据扫描”入口优先打开实时 OCR 全屏扫描页；支持环境下使用 VisionKit `DataScannerViewController` 做多行文字实时识别，并对扫描结果做 550ms 稳定 / 去抖后显示识别预览。
- 扫描页已提供“确认”“拍照识别照片”“从相册选择”三条操作；实时扫描不可用、Mac Catalyst、无相机或系统报告不可用时，自动展示 fallback 操作，不会出现空白或死路。
- 拍照和相册兜底继续复用既有 `CameraPicker` / `PhotosPicker` + `OCRService.recognizeTextWithConfidence`，并与实时扫描一样进入当前 `LedgerStore.importRecognizedText` 导入链路；新增五语 `live_receipt_scan.*` 文案。
- 已补齐 App 内 OCR 导入确认页。实时扫描、拍照识别、相册导入和剪贴板图片识别在解析出单笔账单后，会先进入“确认账单”表单，用户可复核商户、金额、币种、来源、分类、时间和备注后再保存；跨币种时复用当前汇率预估卡片，保存成功后才正式写入账本。
- 确认页只通过 `requiresConfirmation` 显式启用，当前仅 `InboxView` 的 App 内首页导入入口传入；`QuickLedgerIntent`、`VoiceLedgerIntent`、App 启动剪贴板自动导入、订阅截图识别和 iPad 工作台既有调用保持默认直接导入语义不变，避免影响快捷方式记账。
- 当前仍未覆盖订阅识别结果确认页和多笔账单拆分。真实设备相机授权 / 拒绝态、实时取景 + 确认页串联、弱光长票据和屏幕反光场景仍需 TestFlight smoke 补证据。
- 已通过 `git diff --check`、五语 `.strings` lint、`python3 scripts/check_localization_coverage.py`、`bash scripts/run_offline_regression.sh`、`bash scripts/run_golden_regression.sh` 和 iOS 26.5 iPhone 17 Simulator Debug build。构建仍保留既有 warning，本轮未处理。

### 1.2 韩语 App 本地化与韩语识别包

目标：把韩语从“后续候选语言”提升为 `v1.7.0` 明确落地范围，同时覆盖用户界面和账单识别两层能力，避免只翻译 App UI 但识别链路仍不理解韩语账单。

计划能力：

- 新增 `ko.lproj`，覆盖主 App、Watch App、Watch Widgets、Control Widget Extension、Share Extension、App Intents / Shortcuts、Widget 文案、错误提示、设置页、Pro 页面、酒店消费、多账本、订阅管理和截图模式关键文案。
- 更新 Xcode project `knownRegions`、本地化覆盖检查脚本和 release smoke，让 `ko` 与 `zh-Hans` / `zh-Hant` / `en` / `ja` 走同一套 key 覆盖门禁。
- 在 App Store / ASC 发布材料中新增韩语本地化范围：推广文本、描述、新增内容、关键词、Review Notes 中与功能验证相关的必要说明，以及对应平台截图文案。
- 在 `AutoLedgerCore` 新增韩语识别语言包 `ko`，保持纯 Foundation / 纯数据结构，不引入 UIKit、SwiftUI、网络或远程热更新依赖。
- 韩语识别包覆盖常见金额格式和币种写法：`₩12,300`、`12,300원`、`KRW 12,300`、`합계`、`총액`、`결제금액`、`승인금액`、`소계`、`부가세`、`할인` 等金额标签。
- 韩语识别包覆盖商户 / 门店 / 订单线索：`매장명`、`가맹점명`、`상호`、`주문번호`、`승인번호`、`카드`、`일시`、`결제일시` 等字段。
- 韩语识别包覆盖基础分类关键词，例如餐饮、咖啡、便利店、交通、地铁、公交、住宿、购物和订阅类常见词。
- OCR 语言提示新增 `ko-KR + en-US`，并保留英文 / 数字混排 fallback，适配韩国收据和国际酒店水单中的混合文本。
- 新增韩语 golden cases 与离线回归样例，覆盖韩文小票、韩文支付通知、韩元金额、商户 / 分类解析和低噪声 / 多行金额场景。

免费边界：

- 韩语 UI 和韩语识别包属于基础多语言能力，不进入 Pro gate。
- 韩语用户仍可免费使用手动记账、单张截图识别、拍照识别照片、相册导入、基础搜索、基础订阅、基础导出和历史查看编辑。
- Pro 仅继续 gate 新增自动化、批量整理、异常检测和高级导出能力，不按语言区分权益。

验收口径：

- 系统语言为韩语时，主 App、Watch、Widget、Share Extension、Shortcuts 关键路径不出现明显缺失 key、英文占位或未翻译的用户主路径文案。
- `scripts/check_localization_coverage.py` 或等价门禁把 `ko` 纳入覆盖检查，并能定位缺失 key。
- 韩语账单识别包能解析样例韩文账单的金额、日期、商户和分类，且不破坏现有 `zh-Hans` / `zh-Hant` / `en` / `ja` golden cases。
- 韩语 OCR hint 在支持环境下优先使用 `ko-KR + en-US`，不支持时自然回退到现有识别链路。
- ASC 韩语本地化文案和截图素材进入发布前人工审校清单。

### 1.2.1 App i18n 发布矩阵

目标：把多语言从“翻译任务”升级为可发布、可回归、可持续维护的产品能力。每个语言都必须按 `versions/v1.7.0-i18n-release-matrix.md` 中的五项门禁管理：商店可见（ASC 增加语言）、界面可读（App）、基础识别可用（语言识别包）、真实样本回归、地区支付 / 票据格式专项优化。

计划能力：

- 当前公开支持语言继续维护 `zh-Hans`、`zh-Hant`、`en-US` 和 `ja`，但分别补齐样本和地区专项缺口，不把“已有 UI 翻译”误认为“所有地区都已优化”。
- `ko` 作为 `v1.7.0 / ASC 1.6.0` 核心新增语言，必须同时完成 ASC、App UI、`AutoLedgerCore` 识别包、韩语真实样本和韩国支付 / 小票 / 酒店 folio 专项。
- 西班牙语、巴西葡语、法语、德语、印度支付专项、印尼语、泰语、越南语、马来语和阿拉伯语进入候选池；只有完成四项基础门禁后才能进入 ASC 公开语言。
- ASC metadata-as-code 的 audit 输出需要能按语言列出 ASC locale、App locale、截图 locale、订阅 locale、App Preview locale 和 stale locale。
- 截图管线和 App Preview 管线必须从同一语言矩阵读取计划语言，避免 tvOS、visionOS 或 Watch 截图退回中文。
- 真实样本必须脱敏或合成但保留真实版式特征，不能提交真实个人交易、酒店订单、邮箱、二维码或支付凭证。
- App 设置页必须保留清晰可见的语言切换入口；`v1.7.0` 将“区域与语言”拆为单独“语言与区域 / Language & Region”分组，避免被外观主题设置埋住。

验收口径：

- 新增语言进入 ASC 前，至少通过 App 本地化覆盖、识别包 golden cases、截图语言矩阵和 ASC metadata audit。
- 用户可在设置页直接找到“语言与区域 / Language & Region”，并切换跟随系统、简体中文、繁体中文、English、日本語、한국어；切换后根视图 locale、Common API 地点目录展示和酒店地点 fallback 同步跟随。
- README 与版本计划对外支持语言只列 Ready / Build 完成后的语言；Candidate / Later 只作为路线图，不写成已支持能力。
- 语言识别包继续属于免费基础能力，不进入 Pro gate。

### 1.3 Common API、地点目录、汇率与酒店历史天气

目标：在开发 AutoLedger `v1.7.0` 的同时建立可复用的 Cloudflare `common-api` 基础设施，把多个 App 都可能用到的轻量公共能力从单一 App / 单一 Worker 中拆出来。第一版聚焦三件事：常用国家和地区 / 城市目录热更新、汇率查询，以及酒店消费详情中的入住日期历史天气摘要。

计划能力：

- 新建或迁移为独立 `common-api` Cloudflare Worker，避免把城市目录、天气等公共能力继续绑在酒店水单专属收件箱 Worker 中。
- 迁移现有 `MyWeatherLine/Api` 中的 WeatherKit provider、签名 JWT、缓存层和 provider 抽象，保留 OpenWeatherMap / mock provider 作为后续 fallback 或测试路径。

### 1.5 ASC 发布材料自动化与 metadata-as-code

目标：把当前需要在 App Store Connect 页面逐个平台、逐语言手工填写的一整套发布材料收敛为 repo 内结构化源文件和可重复脚本，降低中简 / 中繁 / 英 / 日 / 韩以及后续更多语言的维护成本，并能在提交前自动发现缺失、残留或不同步的 ASC 状态。

计划能力：

- 新增 `tools/asc-metadata/` 工作区，保存 ASC 元数据源文件和脚本；建议包含 `metadata.yml`、`privacy.yml`、`subscriptions.yml`、`screenshots-manifest.json`、`app-previews-manifest.json`、`audit_metadata.py`、`push_metadata.py` 和 `README.md`。
- 使用 App Store Connect API key 调官方 API 管理可官方自动化的发布数据，优先覆盖：
  - `appInfoLocalizations`：App 名称、副标题、隐私政策 URL、Apple TV 隐私政策正文。
  - `appStoreVersionLocalizations`：推广文本、描述、关键词、支持 URL、营销 URL、What's New / 新增功能。
  - `appScreenshotSets` / `appScreenshots`：各平台、各语言、各尺寸的商店截图成品上传或一致性审计。
  - `appPreviewSets` / `appPreviews`：iPhone 等平台的 App Preview 视频上传或一致性审计。
  - `subscriptionGroupLocalizations`、`subscriptionLocalizations`、`inAppPurchaseLocalizations`：订阅组、月付、年付和其它 IAP 的展示名与描述。
- 第一版先实现 `audit`：读取 ASC 当前状态，输出 app info locale、version locale、订阅 locale、截图集、App Preview 集和隐私文本的矩阵，标记缺失字段、空值、未覆盖平台、未覆盖语言、仍存在但计划删除的 stale locale，例如 `en-GB` 残留。
- 第一版再实现 `push`：从 repo 内 YAML / JSON 批量写入商店信息、推广文本、描述、关键词、新增功能、隐私政策 URL、Apple TV 隐私正文和订阅本地化；默认 dry-run，显式 `--apply` 才写入 ASC。
- 截图与视频不直接把所有成品塞进普通 Git 历史；脚本支持从 `tools/appstore-screenshots/output/store/`、App Preview 输出目录或版本化 zip / GitHub Release artifact 读取，按 manifest 上传并校验尺寸、文件名、平台、语言和截图集类型。
- 自动化需要理解当前平台矩阵：iPhone、iPad、Mac、Apple Watch、Apple TV、visionOS；不同平台的截图数量、尺寸、App Preview 支持状态和本地化集合都由 manifest 显式声明。
- locale 策略由配置文件固定：当前 ASC 1.5.0 维护 `zh-Hans`、`zh-Hant`、`en-US`、`ja`；`v1.7.0` 新增 `ko`；不再默认维护 `en-GB`，但 audit 必须能发现 ASC 后端或旧草稿里残留的 `en-GB` 并提示处理。
- 支持把同一份英文文案按策略复用到多个英文 locale；如果未来决定保留 `en-GB`、`en-AU` 等地区英语，脚本应能显式复制 `en-US` 文案，而不是要求人工重复填写。
- 生成提交前 checklist：哪些字段已同步、哪些字段只能人工确认、哪些平台仍缺截图 / 预览、哪些订阅商品仍处于元数据缺失或准备提交状态。
- 只把 Apple Developer API key 的 key id、issuer id 和 p8 存在本机安全位置或 CI secret 中；repo 只保存 `.example` 配置和字段 schema，不提交真实私钥。

边界与注意事项：

- 官方 App Store Connect API 能管理大部分 App 信息、本地化版本信息、截图、预览、IAP 和订阅本地化；但 App Privacy nutrition label 的数据收集问卷本体官方 API 覆盖不完整，第一版不把问卷自动发布作为 P0。
- `Privacy Policy URL` 和 `Apple TV Privacy Policy` 属于 `appInfoLocalizations`，可以纳入官方 API 同步；当前 ASC 1.5.0 遇到的 Apple TV 隐私正文 / stale locale 校验问题，应优先用 audit 定位真实 locale 状态。
- 自动化第一版不直接自动提交审核；提交审核仍由人工在 ASC 页面确认，或在后续确认稳定后单独接提交 API。
- 脚本写入 ASC 前必须给出 diff 预览，包含平台、语言、字段、旧值摘要和新值摘要，避免一次覆盖大量线上元数据。
- 任何截图、App Preview、隐私政策、订阅描述和 Review Notes 都不能包含真实个人消费、真实酒店订单、邮箱地址 token、交易凭证或 API secret。

验收口径：

- `audit_metadata.py` 能列出所有 ASC active / stale localizations，并能发现某个语言缺少 `privacyPolicyUrl`、`privacyPolicyText`、描述、关键词、What's New、订阅描述、截图或 App Preview。
- `push_metadata.py --dry-run` 能基于 repo 内配置生成完整变更预览，不访问或输出 p8 私钥。
- `push_metadata.py --apply` 可批量更新至少一个 sandbox / 当前 App 版本的 `appInfoLocalizations`、`appStoreVersionLocalizations` 和订阅本地化，并在更新后再次 audit 通过。
- 截图 manifest 可校验全平台多语言截图矩阵，确认 store PNG 和 App Preview 视频存在、尺寸正确、非空且语言 / 平台命名一致。
- 当 `en-GB` 不在计划维护语言中但 ASC 仍存在残留时，audit 能明确提示是 stale locale，而不是让提交前才被 ASC 红框拦住。

工程状态：

- 2026-07-07：`tools/asc-metadata/metadata.yml` 已成为 ASC 1.6.0 五语 App Info、版本文案、订阅组和月付 / 年付订阅本地化的 repo 源文件；订阅描述静态约束在 ASC 55 字符限制内。

免费 / Pro 边界：

- 单条商户编辑、基础商户别名、分类学习、手动分类修改和已采纳规则对后续记账生效继续免费。
- Pro 提升的是“分析整个账本并批量提出 / 应用整理建议”的自动化效率层，包括模型辅助建议、批量预览、低置信度集中复核和高级规则候选。
- 到期后不锁已采纳的别名、分类学习和历史规则；只暂停新的 Pro 级自动分析、批量建议生成和云端 Worker 辅助。

验收口径：

- 同一份脱敏账本样例在 Mac 和 iOS 上生成一致的建议 id、建议类型、目标商户名、影响记录集合和置信度。
- 采纳商户归一化建议后，历史记录按预览结果更新，并且新导入的同类 OCR / 快捷指令 / 语音账单会在保存前应用该别名。
- 忽略或撤销建议后，不再影响后续记账；撤销能恢复历史记录和规则状态。
- Worker 模式未开启时，整个分析闭环可以完全离线运行。
- 如果启用 Worker 模式，网络失败只影响云端建议，不影响本地免费记账和本地规则。

当前执行进度（2026-07-08）：

- 本地建议闭环已落地：iOS 和 iPad / Mac 工作台复用 `DataCleaningPreviewPlanner` 生成商户归一化、分类修正和疑似重复建议，支持单条采纳、批量采纳、忽略、撤销和最近清洗记录；采纳商户归一化后会写入商户别名并反哺后续 OCR、快捷指令、语音、Share Extension 和手动新增账单。
- Worker 辅助仍处于本地合同阶段：`DataCleaningAssistPayloadBuilder`、`DataCleaningAssistResponse` / mapper 和 `DataCleaningAssistRequestPolicy` 已定义脱敏 payload、hash-only 响应和请求 eligibility；App 侧只保存“云端辅助建议”本机授权偏好并展示 eligibility，不会调用 `common-api` 或上传账本数据。
- 2026-07-08 TestFlight 真机点击“数据清洗”崩溃已修复。根因是商户别名 / 分类修正经大小写、空格和符号归一化后可能落到相同 hash，旧实现用 `Dictionary(uniqueKeysWithValues:)` 假设 key 唯一。当前 `DataCleaningAssistPayloadBuilder` 已改为重复 key 稳定合并，离线回归新增重复归一化别名 / 分类修正用例。
- 下一步如果正式接入 Worker，需要先补服务端 endpoint、用户可撤销授权、配额 / 冷却持久化、最小日志、删除策略和威胁建模；上线前仍不得上传真实商户名、金额、备注、OCR 原文、交易 UUID、订单号、手机号或账单日期。

### 1.12 隐私安全发布观测与运营 Dashboard

目标：为 `ASC 1.6.0` 第一版主宣传版本建立最小可用的发布观测闭环，辅助判断启动、功能入口、导入、跨币种、Pro gate、购买流程、Common API 和隐私 payload 是否稳定；该能力只服务 QA / 发布决策、运营卡点判断和未来年度总结中的匿名 App 层综合数据，不作为用户侧功能卖点，也不用于追踪。

计划能力：

- 在 `AutoLedgerCore` 维护固定 analytics event catalog，所有事件字段必须先进入 allow-list；客户端构造事件前先做禁止字段检查。
- 在 `common-api` 提供 `POST /v1/analytics/events`，只接受 `app=autoledger`、schema 版本、事件名、App 版本、build、OS major、设备类别和 allow-list payload。
- 在 D1 中保存匿名事件行，字段仅用于聚合：事件名、事件 ID、App 版本、build、OS major、设备类别、payload JSON、接收时间和 schema version。
- 在 Worker 侧提供只读 dashboard data，输出 30 天窗口内的聚合计数、比率、事件分布和版本分布，不返回原始事件行或 payload JSON；面板正式入口使用 `getautoledger.app/dashboard/` 并通过 Cloudflare Zero Trust Access 规则保护，裸路径 `getautoledger.app/dashboard` 只做跳转兼容，Worker 侧额外拒绝非受保护 host 上伪造的 Access 邮箱头。
- 观测指标第一版覆盖启动成功率、匿名功能入口打开次数、导入完成率、导入错误码、确认页放弃率、汇率查询成功率、酒店 PDF 导入完成率、Common API 状态分布、购买失败率、Pro gate 边界风险、隐私 payload 拦截次数、崩溃诊断信号、慢操作数量和性能操作分布。
- App 端第一版已经接入匿名启动、Tab / 页面入口、实时 OCR / 截图 / 相册 / 酒店水单导入、确认页保存 / 放弃、汇率查询、Release Notes / 地点目录 / 酒店天气 Common API、Pro gate、Pro / Support 购买、月结包、月报分享、数据清洗入口、MetricKit 崩溃 / hang / exception 诊断和关键 UI / store refresh 性能事件；所有事件均使用固定枚举和 bucket，不上传账本内容。

隐私边界：

- analytics payload 禁止包含金额、商户、截图、照片、PDF、文件名、邮箱、酒店名、房号、经纬度、精确位置、rawText、OCR 文本、票据原文、交易 ID、Apple ID、App Account Token、StoreKit 交易标识、支付方式或账单地址。
- dashboard 只展示聚合计数和比率，不展示 raw payload、事件行、用户级轨迹或可还原个人账本的信息。
- analytics 失败不得影响 App 启动、记账、同步、Pro entitlement、酒店消费、分享图或月结包导出；上传失败只写本地 log 并跳过。
- 不做广告追踪、不跨 App 识别用户、不把 analytics 与 Apple ID、订阅交易、iCloud 用户或酒店水单 token 关联。
- 年度总结引用 analytics 时只能引用全体匿名聚合口径，不得把服务端 analytics 与单个用户的账本、设备、iCloud、订阅或云收件箱 token 关联。

- 到期后不锁历史数据，只暂停新的 Pro 自动化能力。
- 服务器成本能力继续使用服务端 entitlement 校验，客户端 gate 只作为本地 UI 边界。

## 5. 非目标

- 不实现团队版 / Business。
- 不实现会计协作。
- 不把实时 OCR 扫描做成后台持续扫描或自动入账。
- 不上传相机画面、OCR 原文或小票图片到云端。
- 不移除相册截图入口。
- 不实现远程语言包热更新。
- 不通过 common-api 远程替换账单识别规则、韩语识别包、Pro gate 或 StoreKit 权益判断。
- 不维护全量世界城市库；地点目录只覆盖较大城市、旅游城市和常见酒店城市。
- 不允许 common-api 地点目录第一版只做四语或单语 fallback；公共地点名称从第一版开始必须覆盖 `zh-Hans`、`zh-Hant`、`en`、`ja`、`ko`。
- 不把汇率换算作为投资、结算、报税或交易依据；只用于个人账本内的消费金额归一化展示和统计准备。
- 不把历史酒店账单展示成当前天气或即将入住天气。
- 不为没有坐标或超出 provider 覆盖范围的酒店记录编造天气摘要。
- 不自动上传用户韩语纠错数据或真实韩文账单样例。
- 不把只有 UI 翻译、没有识别包和样本回归的语言写进 ASC 公开支持语言。
- 不把 Worker 变成用户邮箱代登录服务。
- 不把 App Store Server Notifications 作为 `ASC 1.5.0` 当前提审 blocker；该能力从 `v1.7.0 / ASC 1.6.0` 开始建设。
- 不用服务端通知替代端上 StoreKit 购买、恢复购买、管理订阅和即时 UI entitlement 刷新。
- 不把 ASC metadata 自动化第一版做成无人值守自动提审；发布前仍保留人工确认。
- 不用非官方接口强行自动发布 App Privacy nutrition label 问卷；第一版只自动化官方 API 可稳定管理的元数据、截图、预览、订阅本地化、隐私 URL 和 Apple TV 隐私正文。
- 不把 analytics / dashboard 做成用户画像、广告追踪、跨 App 识别、付费转化强推或自动化决策输入。
- 不采集、上传或在 dashboard 展示账单金额、商户名、截图、PDF、邮箱、酒店名、房号、经纬度、OCR 原文、交易 ID、StoreKit 交易标识、支付方式或任何可还原个人消费明细的数据。
- 不在未更新 PrivacyInfo、ASC App Privacy、官网隐私政策和 Review Notes 的情况下扩大 analytics 事件采集面。
- 不在 `ASC 1.5.0` 当前审核或热修二进制里改 App Icon；品牌资产升级从 `v1.7.0 / ASC 1.6.0` 开始收口。
- 不把 AutoLedger 与 AutoNotice 做成同一个图标；只统一家族化视觉语言。
- 不自动正式入账。
- 不锁历史数据。
- 不改变 `Support Developer` 赞助内购。
