# v1.7.0 App i18n 发布专项计划

更新日期：2026-07-02
文档状态：规划版 / Release Matrix
内部开发线：v1.7.0
App Store 对外版本：ASC 1.6.0
关联文档：`versions/v1.7.0-plan.md`、`tools/appstore-screenshots/README.md`、`versions/v1.6.2-ja-release-review-checklist.md`

## 1. 目标

AutoLedger 的多语言策略不能只停留在“App 里能看到翻译”。每个计划公开支持的语言，都必须按五项发布门禁推进：

1. 商店可见：App Store Connect 增加对应语言，并补齐 App 信息、版本信息、订阅本地化、截图和 App Preview。
2. 界面可读：App、Watch、Widget、Share Extension、App Intents / Shortcuts 和截图模式主路径可读，不出现明显缺失 key 或错误 fallback。
3. 基础识别可用：`AutoLedgerCore` 有对应语言识别包，覆盖金额、日期、商户、分类、币种和 OCR hint。
4. 真实样本回归：有脱敏或合成但贴近真实版式的支付截图、小票、订阅、酒店水单样例，进入 golden / offline regression。
5. 地区支付 / 票据格式专项优化：针对当地常见支付方式、税费、找零、折扣、发票、酒店 folio、币种和日期格式做专项规则。

发布目标是“覆盖大多数人群可用”，而不是堆语言列表。一个语言进入 ASC 公开展示前，至少要做到商店、界面、基础识别和样本回归四项可验证；地区专项优化可以分阶段加深，但必须在矩阵里有明确缺口和下一步。

## 2. 状态定义

| 状态 | 含义 |
|---|---|
| Ready | 当前可作为公开支持能力维护，后续只做样本和地区规则增量 |
| Build | `v1.7.0` 计划内落地，需要进入 GOAL 和回归门禁 |
| Audit | 已有部分基础，但需要审校、样本或专项规则补齐后才能扩大宣传 |
| Candidate | 高价值候选语言，先进入调研和样本池，不立即进入 ASC |
| Later | 有价值但复杂度或维护成本较高，暂不进入当前版本 |

## 4. 发布准入规则

- 不能只因 `Localizable.strings` 有翻译就把语言标成“支持”。App Store 页面、App 主路径、基础识别、样本回归至少四项都要可验证。
- ASC 新增语言前，必须先有该语言的 App UI 覆盖检查和至少一组真实样本回归；否则商店会承诺过度。
- 对外宣传的“支持语言”只写 Ready / Build 完成后的语言；Candidate / Later 只能写进路线图或内部计划。
- 识别包属于免费基础能力，不按语言做 Pro gate。
- 真实样本必须脱敏：不能包含真实完整姓名、邮箱、订单号、银行卡号、酒店确认号、个人地址、二维码可扫内容或 API token。
- 地区专项优化允许分阶段，但每个公开语言都必须有本地币种、日期格式、总额 / 税费 / 折扣标签和至少一个地区支付场景的回归样例。

## 5. v1.7.0 执行拆分

### 5.1 P0：建立矩阵门禁

- 把本文件作为 `GOAL-2302` 的验收源。
- 在 `tools/asc-metadata` 的 audit 输出中增加语言矩阵视图：ASC locale、App locale、截图 locale、订阅 locale、App Preview locale、stale locale。
- 在 `scripts/check_localization_coverage.py` 的后续扩展中区分“UI locale 已支持”和“识别包已支持”，避免误报语言整体支持。
- 为 `tools/appstore-screenshots` 增加语言清单来源，避免 tvOS / visionOS / Watch 截图再次退回中文。

### 5.2 P1：韩语落地

- 新增 `ko.lproj` 与 `ko` 识别包。
- 新增韩国支付 / 小票 / 酒店水单 golden cases。
- 导出全平台韩语截图，并补齐 ASC 韩语 metadata。
- 在 `common-api` 地点目录中从第一版开始包含 `ko` 名称，避免酒店国家 / 城市下拉混用英文。

### 5.3 P2：扩展候选评估

- 先选一个高覆盖语言进入 discovery，不同时开太多语言。
- 推荐顺序：西班牙语 -> 巴西葡语 -> 法语 / 德语 -> 印度支付专项。
- 每个候选语言先收集 20-50 条脱敏样本，确认 OCR 与规则可行，再决定是否进入 ASC。

### 5.4 P3：自动化和维护

- ASC metadata-as-code 管理商店文案、推广文本、描述、新增内容、关键词、订阅本地化、截图和 App Preview。
- 截图 / App Preview 成品按版本归档为 GitHub Release artifact 或版本 zip，不直接把完整 ignored output 目录纳入 Git 历史。
- 每个语言维护一个术语表：App 术语、支付术语、票据字段、酒店字段和 Pro 文案边界。
- 每个语言维护一组最小 smoke：新建账单、截图识别、语音 / 文本输入、酒店消费、订阅、设置、Pro、截图模式。

## 6. 非目标

- 不在 v1.7.0 一次性公开十几种语言。
- 不维护全量世界城市库。
- 不远程热更新账单识别规则或语言识别包。
- 不自动上传用户真实票据、OCR 原文或纠错数据。
- 不把候选语言提前写进 App Store 描述当作已支持能力。
- 不把地区支付格式优化做成税务、报销或金融合规承诺。
