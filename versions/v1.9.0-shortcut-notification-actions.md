## 行为

- 现有截图与语音快捷记账成功通知注册系统 category，展开后提供“编辑”和“撤销”。通知正文点击继续打开账本。
- “编辑”使用 foreground action，传递通知中的精确账单 ID。根视图等持久化快照加载完成后呈现原 `TransactionEditorView`，保留金额、商户、日期、分类、备注和账本；保存沿用既有更新逻辑，取消不写数据。记录已删除或不存在时显示说明。
- “撤销”使用 authenticationRequired + destructive action；锁屏时先解锁，随后可后台完成，不要求打开编辑界面。独立 SQLite 连接执行原软删除 SQL，写入 deleted_at 和同步 revision；回收站和恢复流程保持兼容。
- 软删除增加 active 条件并返回实际受影响结果；重复点击与不存在的 ID 不重写删除时间或同步版本。只有成功提交后才反馈已撤销；数据库错误提供失败反馈。
- 成功后移除原成功通知，刷新 Widget/Watch，并沿用外部入口的 iCloud 待推送标记。未启用同步或当前无法推送时保留本地删除事实，由现有流程后续重试。
- 外部写入后的刷新先等待已启动的快照结束，再读取新快照，避免快捷指令或撤销与启动水合交错时采用旧内容。

## 设备验收边界

以上证明源码构建及自动回归通过，未替代以下真实设备验收：

1. 前台、后台和 App 未启动时，通过真实快捷指令产生成功通知，长按显示两项操作。
2. 锁屏点击编辑/撤销需要解锁；编辑直接打开正确账单，取消保持内容，保存更新原记录。
3. 撤销后原通知消失，金额汇总与回收站正确；从回收站恢复后内容一致。
4. iCloud 开启时，另一台设备最终反映删除与恢复；离线后恢复网络也一致。

本轮未执行 Archive、TestFlight 上传、商店发布或 Worker 部署。回退源码即可撤销功能，无 schema 迁移。
