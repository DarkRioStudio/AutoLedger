# v1.5.0 开发线规划

更新日期：2026-05-28
文档状态：第一版规划草案，随开发进程持续校正
内部开发线：v1.5.0 / v1.5.x
App Store 对外版本：v1.4.0
承接版本：App Store v1.3.0 / 内部 v1.4.0 发布基准
关联设计：`versions/v1.4.0-plan.md`、`versions/v1.4.0-RELEASE(draft).md`、`AutoLedger_Watch_Design.md`

## 1. 版本定位

v1.5.0 是 AutoLedger 在内部 v1.4.0（对外 App Store v1.3.0）已过审发布之后，面向下一轮 App Store v1.4.0 的开发线。

本轮不只是继续补 OCR 规则，而是把 AutoLedger 从“手机上的截图记账工具”推进到“多设备账单整理工作流”：

1. Apple Watch 第一屏改为更有用的“今日支出”摘要。
2. Watch 向左滑第二屏显示当前账本关联的最近支出。
3. 设计并实现表盘小组件适配，让今日消费信息能在手表表盘上被快速查看。
4. 增加 iPad 端，把 iPad 定位为统计分析、批量导入、批量识别、数据清洗和多账本管理的主工作台。
5. 评估 iPad 端能力向 Mac 端复用的边界，优先复用数据、解析和 SwiftUI 结构，不把 Mac 作为首版硬目标。
6. 继续优化识别链路，拓展更多真实账单场景。

## 1.1 版本号策略

v1.5.x 是内部开发线；App Store 对外发布版本是 v1.4.0。

开发过程中允许使用 v1.5.1、v1.5.2、v1.5.3 等内部阶段号拆分任务、生成 TestFlight 构建和记录回归节点。用户最终在 App Store 看到的是：

```text
AutoLedger v1.4.0
```

| 场景 | 版本规则 |
|------|----------|
| 内部开发文档 / Git Tag | v1.5.x |
| TestFlight | App Store 版本保持 1.4.0，Build Number 持续递增 |
| App Store | 对外发布 1.4.0 |
| 承接基准 | 内部 v1.4.0 tag / App Store v1.3.0 已发布版本 |
| 后续开发线 | 另起 v1.6.0 或后续版本计划 |

## 2. 产品目标

### 2.1 核心目标

- Watch 端从“可操作入口”升级为“随手看今日支出”：
  - 第一屏显示今日支出总金额。
  - 显示今日支出笔数。
  - 显示最近一笔商户。
  - 左滑第二屏显示当前账本关联的最近支出列表。
  - 保留快速记账和最近账单入口。

- 表盘小组件完成第一版适配：
  - 在表盘上显示今日支出金额或今日支出笔数。
  - 点击小组件进入 Watch App 今日支出页。
  - 支持隐私隐藏、空状态和数据过期提示。

- iPad 端完成第一版产品框架：
  - 统计分析。
  - 数据批量导入。
  - 批量识别。
  - 数据清洗整理。
  - 结构化成账单。
  - 多账本管理。

- 截图与发布资产管线覆盖 iPad：
  - 当前 App Store 截图管线只覆盖 iPhone 与 Apple Watch，不生成 iPad 截图。
  - v1.5.0 需要把 iPad 端纳入截图管线，覆盖关键页面与 App Store 发布资产。
  - iPad 首版 UI 需要从设计阶段就考虑截图可展示性。
  - iPhone、Watch、iPad 三端截图口径统一管理。

- 识别链路继续拓展：
  - 覆盖更多支付、订单、票据、订阅和跨场景账单。
  - 让“识别 → 复核 → 入账 → 清洗 → 统计”的链路更稳定。

### 2.2 非目标

v1.5.0 第一版规划不把 AutoLedger 扩展成完整财务系统。

本轮暂不包含：

- 服务端账户系统。
- 多人协作账本。
- 银行级资产负债管理。
- 预算、投资、贷款、发票报销等完整财务模块。
- 不经用户确认的历史账单大规模自动改写。
- 付费能力边界设计。

## 3. Apple Watch 主线

### 3.1 第一屏：今日支出

Watch App 打开后的第一屏改为“今日支出”，让用户抬腕就能确认当天消费状态。

第一屏信息结构：

| 信息 | 展示要求 | 说明 |
|------|----------|------|
| 今日支出总金额 | 最大视觉层级 | 使用当前账本默认币种；无支出时显示 0 或空状态文案 |
| 今日支出笔数 | 次级指标 | 显示 `共 N 笔`，便于判断今天消费频率 |
| 最近一笔商户 | 次级摘要 | 优先显示商户名；无商户时显示分类或账单来源 |
| 同步状态 | 轻量提示 | 仅在数据过期、同步失败、等待 iPhone 时显示 |
| 操作入口 | 底部或卡片按钮 | 快速记账、语音记账、最近账单 |

基础状态：

- 空状态：今天还没有支出，保留快速记账入口。
- 加载状态：本地数据读取或等待 iPhone 回传时显示轻量占位。
- 离线状态：显示上次同步时间，允许继续本地暂存记账。
- 隐私状态：用户开启隐私隐藏时，金额显示为占位符，点按后进入 App 可查看。

### 3.2 左滑第二屏：账本关联最近支出

Watch 今日支出页向左滑进入第二屏，显示当前账本关联的最近支出。

第二屏信息结构：

| 信息 | 展示要求 | 说明 |
|------|----------|------|
| 当前账本 | 顶部轻量标识 | 显示默认账本或当前选中账本名称 |
| 最近支出列表 | 主体内容 | 展示最近 3～5 笔支出，按交易时间倒序 |
| 单笔摘要 | 金额 + 商户 / 分类 | 空商户时用分类兜底 |
| 时间提示 | 今天 / 昨天 / 日期 | Watch 小屏上避免完整时间过长 |
| 详情入口 | 点按单笔进入详情 | 第一版只读详情，复杂编辑留给 iPhone / iPad |

数据口径：

- 只展示当前账本关联的支出记录。
- 默认使用用户当前默认账本；多账本上线后，可跟随 iPhone / iPad 最近使用账本。
- 如果账本没有最近支出，显示空状态并保留快速记账入口。
- Watch 上不做账本切换的复杂管理，最多提供轻量账本名称提示。

交互原则：

- 第一屏负责“今天花了多少”，第二屏负责“最近花在哪里”。
- 左右滑动不应隐藏核心操作，快速记账入口仍需容易到达。
- 第二屏列表不承载批量清洗、分类学习、账本移动等重操作。

### 3.3 数据口径

今日支出应按用户本地日历日统计，不按 UTC 自然日统计。

统计范围：

- 只统计支出，不统计收入、退款或非消费记录。
- 多账本能力上线后，默认统计当前默认账本；后续可扩展为“全部账本今日支出”。
- 最近一笔商户按交易时间倒序取第一条；若交易时间缺失，则按创建时间倒序兜底。

### 3.4 Watch 交互原则

- Watch 上只做轻量查看和快速记录，不做复杂账单清洗。
- 今日支出页优先保证一眼读懂，不堆图表。
- 编辑、批量操作、数据清洗统一引导到 iPhone / iPad。
- VoiceOver、大字号、减动、增强对比度必须在主路径可用。

## 4. 表盘小组件适配

### 4.1 第一版范围

表盘小组件先围绕“今日支出”做最小可用集：

| Widget Family | 第一版内容 | 备注 |
|----------------|------------|------|
| Accessory Inline | `今日支出 ¥88` | 适合文字型表盘区域 |
| Accessory Circular | 金额缩写或笔数 | 空间不足时显示 `¥88` / `3笔` |
| Accessory Rectangular | 今日金额 + 笔数 | 可附带最近商户一行 |
| Accessory Corner | 金额缩写 | 视实现成本决定是否进入首版 |

### 4.2 更新时间与隐私

- 小组件不追求秒级刷新，按 WidgetKit / watchOS timeline 能力做合理刷新。
- 新增账单保存后尽量触发刷新，但不能依赖实时刷新作为唯一正确性来源。
- 默认显示金额；如果后续增加隐私开关，小组件应支持金额隐藏。
- 当数据超过一定时间未同步时，显示轻量过期提示或回退到最后一次有效数据。

### 4.3 验收标准

- 表盘小组件能显示今日支出金额。
- 点击小组件能打开 Watch App 今日支出页。
- 今日无支出、同步失败、离线、隐私隐藏都有明确状态。
- 简体中文、繁体中文、英文文案可本地化。
- 小尺寸表盘区域不出现文字截断或金额不可读。

## 5. iPad 主线

### 5.1 产品定位

iPad 端不是简单放大 iPhone UI，而是 AutoLedger 的“账单整理工作台”。

用户在 iPhone / Watch 上负责快速记录，在 iPad 上完成更重的整理工作：

1. 批量导入截图、图片、文件或文本。
2. 批量识别候选账单。
3. 复核、清洗、合并、去重和分类。
4. 结构化为正式账单。
5. 按账本、月份、分类、商户做统计分析。

### 5.2 信息架构

建议第一版采用 iPad 常见的三段式结构：

| 区域 | 内容 | 目标 |
|------|------|------|
| 左侧边栏 | 账本、月份、导入箱、清洗任务、统计入口 | 快速切换工作上下文 |
| 中间列表 / 表格 | 账单、候选记录、批量识别结果 | 支持批量选择和排序筛选 |
| 右侧详情 / 检查器 | 识别字段、原图预览、清洗建议、账单详情 | 让复核和修正不离开当前页面 |

### 5.3 统计分析

iPad 统计分析优先服务“看懂钱花到哪里”：

- 月度支出总览：总金额、笔数、日均支出、环比变化。
- 分类分析：分类金额、占比、趋势变化。
- 商户分析：Top 商户、重复消费、订阅类消费。
- 账本分析：个人、家庭、旅行、工作等账本维度的对比。
- 时间分析：日历热力、周内分布、月内峰值。
- 异常提示：大额、重复、疑似误识别、分类异常。

第一版不追求复杂图表堆叠，优先保证筛选、钻取和数据可信。

### 5.4 数据批量导入

第一版导入场景：

- 从系统照片选择多张账单截图。
- 从 Files 拖入图片、PDF 或文本文件。
- 从剪贴板粘贴多条账单文本。
- 从分享入口进入 AutoLedger 导入箱。

导入后先进入“候选区”，不直接写入正式账本。

候选区字段：

- 来源类型。
- 原始文件名或截图来源。
- 识别状态。
- 识别置信度。
- 候选金额、商户、时间、分类。
- 是否疑似重复。
- 是否需要人工复核。

### 5.5 批量识别

批量识别采用队列模型：

1. 导入文件进入队列。
2. 逐项 OCR / 文本解析。
3. 生成候选账单。
4. 标记置信度和异常原因。
5. 用户批量确认或逐条修正。

队列需要支持：

- 暂停 / 继续。
- 失败重试。
- 识别结果重新解析。
- 按状态筛选：待识别、待复核、可入账、失败、疑似重复。
- 大批量导入时不阻塞 UI。

### 5.6 数据清洗整理

数据清洗是 iPad 端的重点能力。

第一版清洗项：

- 商户统一：把不同写法归并为同一商户。
- 分类修正：批量修改同类商户或同类记录的分类。
- 重复检测：按金额、时间、商户、来源相似度提示疑似重复。
- 字段补全：时间、商户、分类、备注缺失时提示补齐。
- 金额异常：识别金额与文本上下文冲突时标记。
- 来源整理：记录账单来自截图、文本、手动、Watch、快捷指令等路径。

所有批量清洗动作都必须有确认步骤，并尽量提供撤销或可回滚路径。

### 5.7 结构化成账单

候选记录进入正式账本前，应经过结构化确认：

| 阶段 | 状态 | 说明 |
|------|------|------|
| Raw Input | 原始输入 | 图片、PDF、文本、剪贴板内容 |
| Candidate | 候选账单 | OCR / 文本解析后的结构化草稿 |
| Reviewed | 已复核 | 用户确认字段正确 |
| Transaction | 正式账单 | 写入账本并进入统计 |
| Rejected | 已忽略 | 非账单或用户放弃 |

第一版可先在 UI 和存储层建立清晰状态，后续再逐步增强自动化。

### 5.8 多账本管理

多账本用于把不同生活场景分开：

- 个人账本。
- 家庭账本。
- 旅行账本。
- 工作 / 报销账本。
- 临时项目账本。

第一版能力：

- 创建、重命名、归档账本。
- 设置默认账本。
- 导入时选择目标账本。
- 账单可在账本间移动。
- 统计分析可按单账本或全部账本查看。

暂不做多人协作和服务端同步。

## 6. Mac 端复用评估

iPad 端程序可以为 Mac 端提供较高复用基础，但不建议在 v1.5.0 第一版直接承诺“无成本复用到 Mac”。

### 6.1 可直接复用的部分

- 账单数据模型、账本模型、候选账单状态模型。
- OCR 后文本解析、商户别名、分类学习、重复检测等 core 逻辑。
- SQLite / 本地持久化层中与平台 UI 无关的部分。
- iCloud Drive 备份、导入导出、离线回归样本和 Golden Case。
- SwiftUI 中足够纯粹的列表、表格、筛选器、详情检查器组件。
- iPad 截图管线中用于准备演示数据、固定状态和多语言文案的脚本思路。

### 6.2 需要单独适配的部分

- Mac 窗口、菜单栏、快捷键、工具栏和多窗口行为。
- 文件导入体验：Mac 更依赖 Finder 拖拽、菜单导入、文件夹批处理。
- 表格密度和键盘操作：Mac 用户会期待更强的批量选择、复制、撤销和快捷键。
- 沙盒权限、文件访问、安全范围书签等 macOS 细节。
- App Store 截图、审核说明和平台能力描述需要单独准备。
- Watch / Widget 联动在 Mac 端不是核心卖点，不能简单复制 iPad 叙事。

### 6.3 产品判断

v1.5.0 首版建议按“iPad 优先，Mac 预留”处理：

- iPad 工作台先跑通批量导入、批量识别、清洗和多账本。
- 所有核心业务逻辑尽量放在跨平台模块，避免绑死 iPad UI。
- SwiftUI 组件拆分时考虑 macOS 可用性，但不为 Mac 牺牲 iPad 首版体验。
- 当 iPad 端候选账单、清洗队列、多账本管理稳定后，再评估 Mac Catalyst 或原生 macOS App。

结论：工程上可以复用大部分业务层和部分 SwiftUI 组件；产品上不建议把 Mac 端放进 App Store v1.4.0 的首版承诺，只把它作为后续 v1.5.x / v1.6.0 的可扩展方向。

## 7. 截图与发布资产

当前截图管线尚未覆盖 iPad 端。`tools/appstore-screenshots/README.md` 中也明确记录现状：管线支持 iPhone 与 Apple Watch，但不生成 iPad screenshots。

v1.5.0 需要把 iPad 截图扩展作为正式发布资产工作项，而不是在发布前临时手工补图。该工作项应与 iPad 信息架构、演示数据、横竖屏布局和多语言文案同步设计。

第一版截图覆盖建议：

- iPhone：快速识别、账本列表、月报、设置 / 支持入口。
- Watch：今日支出第一屏、左滑最近支出第二屏、快速记账、表盘小组件。
- iPad：统计分析工作台、批量导入队列、候选账单复核、数据清洗、多账本切换。

iPad 截图管线扩展范围：

- 在截图配置中增加 iPad target size、设备候选和输出目录，例如 `raw/ipad/{locale}/` 与 `store/ipad/{locale}/`。
- 增加 iPad 专用 screenshot host 或让现有 host 支持 `--screenshot-platform ipad`，避免直接放大 iPhone 画面。
- 为 iPad 工作台准备稳定 fixture：账本、月份、分类、商户、候选账单、批量导入状态和清洗建议。
- 渲染脚本需要支持 iPad 横屏主画布；必要时保留竖屏关键页，但第一版以横屏工作台为主。
- `preview.html` 需要把 iPhone、Watch、iPad 三端分组展示，便于发布前目检。
- 导出脚本需要支持 `--ipad-only`，以及与现有 `--ios-only` / `--watch-only` 不冲突的组合。

截图管线要求：

- iPad 截图必须使用稳定演示数据，覆盖批量与统计场景。
- 三端截图中的金额、商户、分类、账本名称要保持同一套演示口径。
- iPad 截图需要验证横屏主场景，必要时补充竖屏关键页。
- 简体中文和英文优先准备；繁体中文可沿用本地化能力，是否上传截图按发布节奏决定。
- 截图导出后继续保留黑屏 / 空白页 / 文字截断检查。
- 在 iPad 管线完成前，App Store iPad 截图不得标记为已准备完成。

## 8. 识别链路优化

### 8.1 目标

v1.5.0 继续强化“识别 → 解释 → 复核 → 入账”的可信链路。

重点不是让系统永远自动判断正确，而是在不确定时明确告诉用户：

- 哪些字段可信。
- 哪些字段需要复核。
- 为什么被归到某个商户或分类。
- 是否可能重复。
- 是否适合批量应用同样规则。

### 8.2 场景拓展

优先补充以下场景样本和规则：

- 微信支付、支付宝、Apple Pay、银行卡消费通知。
- 电商订单和支付详情。
- 订阅服务账单。
- 餐饮、小票、外卖、咖啡、便利店。
- 出行、打车、地铁、停车、酒店、机票。
- 海外消费、多币种金额、汇率备注。
- 邮件 / 短信 / 剪贴板文本账单。
- 长截图、多张截图组成的一笔账单。

### 8.3 质量门禁

每次拓展识别场景时，应同步增加：

- Golden Case。
- 离线回归样本。
- 误识别反例。
- 低置信度展示规则。
- 分类 / 商户别名回归检查。

## 10. 验收口径

### 10.1 Watch

- 打开 Watch App 首屏即能看到今日支出总金额、笔数和最近商户。
- 向左滑第二屏能看到当前账本关联的最近支出。
- 今日无支出时状态清晰，不误导用户。
- Watch 新增账单后，今日支出能在合理时机刷新。
- 表盘小组件显示今日支出，并能跳转到 Watch App。
- 大字号、VoiceOver、隐私隐藏场景可用。

### 10.2 iPad

- iPad 上可以完成一批截图或文件的导入。
- 批量识别结果进入候选区，而不是直接污染正式账本。
- 用户可以批量确认、逐条修正、忽略或重试。
- 用户可以对商户、分类、重复项进行清洗整理。
- 候选账单确认后能结构化写入指定账本。
- 统计分析能按账本、月份、分类、商户查看。
- iPad 截图管线能导出稳定的工作台、批量导入、清洗和多账本页面。
- iPad 截图产物能进入统一 `preview.html`，并能按 locale 分别目检。

### 10.3 Mac 复用

- 核心业务模块不绑定 iPad UI，可被 Mac 后续复用。
- 文档明确哪些能力可复用、哪些能力需要 macOS 单独适配。
- App Store v1.4.0 不把 Mac 端作为发布承诺。

### 10.4 识别链路

- 新增场景必须有样本和回归。
- 低置信度结果必须清楚标记。
- 批量规则应用前必须让用户确认影响范围。
- 商户别名、分类学习、重复检测不能破坏既有账单数据。

## 11. 风险与待确认问题

- Watch 小组件刷新频率受系统限制，不能承诺实时金额。
- 今日支出口径需要与多账本能力提前对齐，避免后续迁移成本过高。
- Watch 左滑第二屏与快速记账入口的导航层级需要实机验证，避免常用操作变深。
- iPad 批量导入可能引入大量候选数据，需要设计失败恢复和取消路径。
- PDF、长截图、多币种等场景复杂度较高，需要明确首版支持边界。
- 多账本涉及现有账单数据迁移，必须先设计默认账本和兼容策略。
- 数据清洗动作可能影响历史账单，必须有确认、预览和回滚思路。
- iPad 到 Mac 可以复用大量业务层，但 macOS 交互、菜单、文件权限和窗口体验需要单独设计。
- App Store v1.4.0 是否同时发布 iPad 截图、Watch 小组件截图，需要根据实现质量再定。
- 当前截图管线不支持 iPad；v1.5.0 若要发布 iPad 端，必须预留足够时间实现、导出并人工复核 iPad 截图。
