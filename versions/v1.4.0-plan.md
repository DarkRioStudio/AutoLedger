### 0.2 编译阻断项（Phase 0 前必须解决）

**阻断项 A：`OCRService.swift` 须移出 AutoLedgerCore**

- 当前路径：`AutoLedger/AutoLedgerCore/Sources/AutoLedgerCore/Services/OCRService.swift`
- `OCRService` 依赖 `Vision.VNRecognizeTextRequest`，watchOS 不提供 Vision
- 解决方案：将 `OCRService.swift` 移至主 App target：`AutoLedger/AutoLedger/Domain/Services/`
- 移动后：AutoLedgerCore 内所有剩余文件均为 Foundation-only，可在 watchOS 编译

> 注意：`OCRService` 目前被 `ReceiptParser.swift`（Core 内）引用。需确认 ReceiptParser 是否直接依赖 OCRService，或两者只在 App 层组合调用。若有直接依赖，需先解耦。

## 1. 版本定位

v1.4.0 / v1.4.x 是 AutoLedger 面向 App Store v1.3.0 的内部开发计划线。

本轮对外发布版本仍然是 App Store v1.3.0。内部使用 v1.4.x 拆分开发阶段、TestFlight 构建、回归测试和发布候选，不代表用户会在 App Store 看到 v1.4.x 小版本。

本版本重点不再只是继续堆 OCR 规则，而是把用户可感知体验做完整：

1. Apple Watch 端上线。
2. 完整辅助功能专项落地。
3. 快捷指令 / App Intents 入口增强。
4. OCR / 语音 / 手动输入三类记账路径稳定收口。
5. 为 App Store Accessibility Nutrition Labels、Watch 截图、审核说明、商店文案做准备。

## 1.1 版本号策略

v1.4.x 是内部开发线；App Store 对外发布版本是 v1.3.0。

开发过程中允许使用 v1.4.x 作为内部小版本号 / 阶段里程碑，例如 v1.4.1、v1.4.2、v1.4.3 等，用于拆分开发任务、记录阶段成果、生成 TestFlight 构建和回归测试节点。

这些 v1.4.x 内部版本不单独发布到 App Store。App Store 最终只发布一个对外版本：

```text
AutoLedger v1.3.0
```

建议约定如下：

| 场景 | 版本规则 |
|------|----------|
| 内部开发文档 / Git Tag | v1.4.x |
| TestFlight | App Store 版本保持 1.3.0，Build Number 持续递增 |
| App Store | 只发布 1.3.0 |
| 下一轮内部开发线 | 另起 v1.5.0 或后续版本计划 |

因此本文中的 v1.4.1、v1.4.2 等只表示内部阶段，不表示 App Store 对外小版本；用户最终看到的是 App Store v1.3.0。

## 2. 版本目标

### 2.1 核心目标

- 实现 Apple Watch 端第一版：
  - 语音记账。
  - 今日支出查看。
  - 最近账单查看。
  - 快速分类记账。
  - 与 iPhone 主 App 同步。
  - 可选 Complication / Smart Stack Widget。

- 完成辅助功能专项：
  - VoiceOver。
  - Larger Text / Dynamic Type。
  - Voice Control。
  - Sufficient Contrast。
  - Differentiate Without Color Alone。
  - Dark Interface。
  - Reduced Motion。
  - Switch Control 基础可用。
  - OCR 结果可解释。

- 将 v1.3.5 的 core 引擎能力正式用于 Watch：
  - `LedgerTextInterpreterCore` 可在 watchOS target 编译。
  - 语音文本可复用 core 解析。
  - iPhone 与 Watch 解析结果保持一致。

- 为 App Store v1.3.0 发布做收口：
  - Watch App 截图。
  - 辅助功能声明。
  - 隐私说明检查。
  - TestFlight 测试清单。
  - Review Notes 准备。

### 2.2 非目标

本版本不追求把 AutoLedger 做成完整财务管理工具。

v1.4.x 内部线的重点是“更容易记一笔”，不是“更复杂地管理资产”。因此预算、多账户资产、报表大屏、服务端账户、订阅收费等内容全部延后。

## 4. 产品范围

### 4.1 iPhone 端

iPhone 端在本版本不做大规模 UI 重构，只做必要增强：

- 账单列表辅助功能优化。
- OCR 结果确认页辅助功能优化。
- 手动记账页辅助功能优化。
- 快捷指令入口增强。
- 与 Watch 同步状态展示。
- 低置信度识别结果提示增强。
- 大字号、暗色模式、低动态效果适配。

### 4.2 Apple Watch 端

Watch 端定位不是完整记账 App，而是“最快入口”。

第一版只做高频轻操作：

- 语音记账：
  - 用户在 Watch 上说：`咖啡 28 元`
  - 解析为：支出 / 餐饮 / 28 元 / 今天
  - 用户确认后保存。

- 今日支出：
  - 展示今日总支出。
  - 展示今日分类分布。
  - 展示最近几笔账单。

- 快速记一笔：
  - 常用分类：餐饮、交通、购物、数字服务、生活缴费、其他。
  - 支持快速输入金额。
  - 支持最近分类复用。

- 最近账单：
  - 显示最近 5～10 笔。
  - 支持查看详情。
  - 第一版不在 Watch 上做复杂编辑。

- Complication / Smart Stack：
  - 显示今日支出。
  - 点击进入 Watch App。
  - 如果复杂度超出预期，可拆到后续 v1.4.x 内部阶段；如果最终仍未达发布质量，则不进入 App Store v1.3.0 范围。

### 4.3 Shortcuts / App Intents

继续强化“一键记账”的核心卖点：

- `AddTransactionIntent`
  - 添加一笔账单。
  - 输入：金额、分类、备注、商户、日期。
  - 可被 Siri / Shortcuts / Spotlight 调用。

- `ParseLedgerTextIntent`
  - 输入自然语言文本。
  - 返回解析结果。
  - 可用于快捷指令自动化。

- `OpenQuickAddIntent`
  - 打开快速记账页。

- `ScanReceiptIntent`
  - 打开扫码 / 拍照小票入口。
  - 如果系统限制不适合直接启动相机，则打开 OCR 入口页。

## 5. Track A：Apple Watch 端实现

### 5.1 目标

实现 AutoLedger Watch App 第一版，使用户不拿出 iPhone 也能完成轻量记账。

Watch 端应满足：

- 3 秒内打开主界面。
- 常见语音记账 10 秒内完成确认。
- 无网络情况下仍可记账。
- 与 iPhone 同步失败时可本地暂存。
- 不引入复杂账户、预算、图表等重功能。

### 5.2 Watch 信息架构

```text
AutoLedger Watch
├── 今日概览
│   ├── 今日支出总额
│   ├── 今日笔数
│   └── 最大分类
├── 语音记账
│   ├── 启动听写
│   ├── 解析文本
│   ├── 确认结果
│   └── 保存
├── 快速记账
│   ├── 输入金额
│   ├── 选择分类
│   └── 保存
├── 最近账单
│   ├── 最近 5～10 笔
│   └── 账单详情
└── 设置 / 同步状态
    ├── iPhone 连接状态
    ├── 未同步数量
    └── 帮助说明
```

### 5.3 Watch 主界面

主界面建议使用卡片式布局：

```text
今日支出
¥ 128.50

[语音记账]
[快速记一笔]
[最近账单]
```

设计原则：

- 不做复杂 Tab。
- 不做复杂图表。
- 不做长表单。
- 不在 Watch 上强制登录。
- 不在 Watch 上做历史账单管理。
- Watch 只承担快速输入与轻查看。

### 5.4 语音记账流程

```text
用户点击「语音记账」
      ↓
系统听写 / Dictation
      ↓
得到文本：今天咖啡 28 元
      ↓
LedgerTextInterpreterCore 解析
      ↓
确认页展示：
  金额：28.00
  分类：餐饮
  备注：咖啡
  日期：今天
      ↓
用户点击保存
      ↓
本地保存 / 发送 iPhone 同步
```

解析策略：

- 优先本地解析。
- Watch 端复用 core。
- 如果 Watch 端 core 编译困难，可降级为：
  - Watch 端只采集文本。
  - 发送给 iPhone 解析。
  - iPhone 不在线时暂存原始文本。

### 5.5 快速记账流程

适合不想说话的场景。

```text
快速记一笔
├── 选择分类
│   ├── 餐饮
│   ├── 交通
│   ├── 购物
│   ├── 数字服务
│   ├── 生活缴费
│   └── 其他
├── 输入金额
└── 保存
```

金额输入方案：

- 第一优先：系统数字输入。
- 第二优先：预设金额 + 微调。
- 不建议第一版自研复杂数字键盘。

### 5.6 WatchConnectivity

同步策略：

```text
Watch 新增账单
      ↓
本地生成 transactionDraft
      ↓
尝试发送给 iPhone
      ↓
成功：iPhone 入库，Watch 标记 synced
      ↓
失败：Watch 本地 pending，后续重试
```

需要设计的数据模型：

```swift
WatchLedgerDraft
- id
- amount
- category
- merchant
- note
- date
- source = watch
- rawText
- confidence
- createdAt
- syncStatus
```

同步状态：

| 状态 | 说明 |
|------|------|
| synced | 已同步到 iPhone |
| pending | 暂存在 Watch，等待同步 |
| failed | 多次同步失败，需要用户检查 |

第一版不做双向复杂冲突解决。Watch 创建的账单以 iPhone 入库为最终状态。

## 6. Track B：完整辅助功能专项

### 6.1 目标

让用户可以通过系统辅助功能完成 AutoLedger 的核心任务：

1. 手动添加一笔账单。
2. OCR 识别小票并确认保存。
3. 使用语音文本添加账单。
4. 查看今日 / 最近账单。
5. 修改识别错误字段。
6. 删除或撤销一笔账单。
7. 在 Watch 上完成一笔轻量记账。

### 6.2 VoiceOver

需要覆盖：

- 首页。
- 快速记账。
- OCR 识别结果确认页。
- 手动记账表单。
- 账单列表。
- 账单详情。
- 设置页。
- Watch 主界面。
- Watch 语音记账确认页。
- Watch 最近账单。

具体要求：

- 所有图标按钮必须有明确 label。
- 装饰性图标隐藏。
- 账单卡片合并为语义完整元素。
- OCR 结果提供自然语言摘要。
- 低置信度字段必须读出风险。
- 删除、保存、重新识别等危险操作必须读出后果。
- Watch 上按钮文案要短，但 VoiceOver label 可以更完整。

示例：

```text
账单卡片：
支出 28 元，餐饮，星巴克，今天 10:32，按钮

OCR 确认摘要：
已识别为支出 28 元，分类餐饮，商户星巴克，金额可信度较高，分类建议检查。

低置信度金额：
金额 28 元，可能不准确，请检查，文本框
```

### 6.3 Larger Text / Dynamic Type

要求：

- iPhone 主流程支持系统大字号。
- 核心文字至少支持到 Accessibility Large。
- 金额、分类、按钮不能重叠。
- 表单允许滚动。
- 按钮不被键盘遮挡。
- 账单卡片允许换行。
- Watch 上不追求超大信息密度，宁愿分页。

重点检查页面：

- OCR 确认页。
- 手动记账页。
- 账单详情页。
- 今日统计页。
- Watch 语音确认页。
- Watch 今日概览页。

### 6.4 Voice Control

要求：

- 主要按钮可以通过语音名称点击。
- 同屏多个“编辑”按钮必须区分。
- 表单字段 label 明确。
- Watch 端尽量减少同名按钮。

示例：

```text
点击一键记账
点击保存
点击金额
点击分类
点击重新识别
点击编辑金额
点击删除这笔账单
```

### 6.5 Sufficient Contrast

要求：

- 浅色模式与深色模式都检查。
- 金额、按钮、错误提示、警告提示对比度足够。
- 不能使用过浅灰色作为正文。
- 收入 / 支出颜色需要保持可读。
- Watch 小屏尤其要避免低对比。

### 6.6 Differentiate Without Color Alone

不能只靠颜色表达：

| 信息 | 不合格方式 | 合格方式 |
|------|------------|----------|
| 支出 | 只显示红色金额 | `支出 -28.00` + 红色 |
| 收入 | 只显示绿色金额 | `收入 +500.00` + 绿色 |
| OCR 低置信度 | 只显示黄色边框 | `建议检查` 文案 + 图标 |
| 同步失败 | 只变红 | `同步失败` 文案 + 重试按钮 |
| 删除危险 | 只用红色按钮 | `删除这笔账单` 明确文案 |

### 6.7 Dark Interface

要求：

- iPhone 全主流程支持暗色模式。
- Watch 全页面支持暗色模式。
- 自定义颜色统一走 design token。
- 图标在暗色模式下不能丢失。
- 输入框、分割线、卡片边界可辨识。

### 6.8 Reduced Motion

要求：

- 用户开启 Reduce Motion 后：
  - 关闭大幅缩放动画。
  - 关闭卡片飞入动画。
  - 降低数字跳动动画。
  - 避免连续闪烁。
  - 保留必要淡入淡出即可。

### 6.9 Switch Control 基础可用

最低目标：

- 核心按钮可聚焦。
- 表单字段顺序合理。
- 弹窗不会困住焦点。
- 保存 / 取消 / 删除等操作可被扫描到。
- Watch 端核心按钮可访问。

### 6.10 OCR 结果可解释

OCR 识别完成后，增加可读摘要：

```text
已识别为：
支出 28.00 元
分类：餐饮
商户：星巴克
日期：今天

金额可信度较高。
分类由商户名称推断，建议检查。
```

如果失败：

```text
没有识别到明确金额。
你可以重新拍摄，或手动输入金额。
```

如果非账单图片：

```text
这张图片看起来不像账单。
你仍然可以手动记录一笔账。
```

## 10. Track F：稳定性、数据与同步

### 10.1 稳定性目标

- iPhone 主流程不因 Watch 改造回退。
- Watch 端无明显崩溃。
- Watch 与 iPhone 同步失败可恢复。
- OCR 失败可以手动输入。
- 语音解析失败可以编辑保存。

### 10.2 数据策略

v1.4.x 内部线不建议大改 SQLite schema。

优先使用兼容字段：

- source。
- note。
- merchant。
- category。
- date。
- amount。
- createdAt。

本期不建议为了 Watch 强行修改主账本 schema。Watch 来源优先复用现有字段：

```text
语音记账：source = voice
快速手动记账：source = manual
原始语音或输入文本：优先写入 note 或 Watch 草稿元数据
Watch 同步状态：优先存在 Watch 本地 pending 队列，不进入主账本表
```

Watch pending 数据可以先存在 Watch 本地草稿队列，再由 iPhone 入库时转成现有账单结构。除非后续确认必须做跨端审计，否则不新增 `.watch` source，不新增主账本同步状态字段。

### 10.3 同步失败处理

Watch 保存失败时：

```text
已暂存
将在 iPhone 可用时同步
```

iPhone 收到重复草稿时：

- 使用 draft id 去重。
- 同一 draft 不重复入库。
- 重试不生成多笔账单。
