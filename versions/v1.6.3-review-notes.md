## 1. 审核定位

`v1.6.3` 完成的是酒店水单 C1 AutoLedger 专属收件箱的第一版 App/Core 工程骨架和审核材料，不是公开云端自动导入服务上线版本。

当前版本已冻结以下合同：

- 专属地址形态：`folio+<token>@getautoledger.app`。
- 云端候选模型：`CloudHotelFolioCandidate`。
- 云端候选来源：只处理发送到 AutoLedger 专属地址的邮件。
- App 本地转换链路：已下载 PDF -> PDFKit 文本提取 -> 本地脱敏 -> `HotelFolioParsePipeline` -> `HotelStayDraft(sourceType: .cloudWorker)`。
- 入账边界：用户确认后才生成 `HotelStayRecord` 和关联 `Transaction`。

当前版本不包含：

- 真实 Worker inbound email 服务。
- 真实对象存储写入、签名下载 URL 或过期清理任务。
- APNs 推送服务。
- 云端候选 API 或 App 云候选列表 UI。
- 订阅后端、订阅状态校验或专属收件地址管理 UI。
- Worker 识别 PDF、生成正式酒店消费记录或自动入账。

## 2. App Review 测试路径

审核员不需要登录真实邮箱，也不需要向真实 AutoLedger 专属邮箱发送邮件来测试当前版本。

可测试路径：

1. 打开 AutoLedger。
2. 进入“酒店消费”。
3. 点击右上角 `+`。
4. 选择“导入 PDF”或从系统分享面板将酒店水单 PDF 分享给 AutoLedger。
5. App 使用本地 PDFKit 提取文本，并进入酒店水单识别复核页。
6. 审核识别字段，确认后生成酒店消费记录和关联普通支出流水。

C1 cloud inbox 的当前可验证内容是工程合同和路由：

- `autoledger://hotel-cloud-candidates` 可定位到酒店消费入口。
- `autoledger://hotel-cloud-candidate/{candidateID}` 可打开酒店消费入口并记录待处理候选 ID。
- 已下载 PDF data 可以转换成 `.cloudWorker` 来源的 `HotelStayDraft`。

## 3. 隐私原则

C1 设计遵守以下隐私边界：

- Worker 不登录用户 QQ / IMAP / Gmail / Outlook 邮箱。
- Worker 不保存用户邮箱授权码。
- Worker 不扫描用户私人邮箱。
- Worker 只处理用户主动转发、自动转发或直接投递到 AutoLedger 专属地址的邮件。
- token 只以 hash 或不可逆形式进入索引、日志和对象 key。
- Message-ID 只保存 hash，不保存 raw Message-ID。
- 发件人和主题进入候选元数据前必须脱敏。
- APNs payload 只包含候选 ID / deep link 所需路由数据，不包含酒店名、金额、订单号、入住日期等敏感信息。
- App 仍在本地执行 PDFKit 文本提取、脱敏和酒店水单解析。
- 所有结果默认进入待确认状态，用户确认后才正式入账。

## 4. 云端数据处理边界

后续真实 C1 Worker 上线前需要保持以下约束：

- PDF 只做短期对象存储，默认过期删除。
- App 成功下载 / 转换为本地草稿后，可主动删除云端 PDF。
- 用户删除云端候选、本地草稿或正式酒店消费记录时，应提供可解释的云端清理语义。
- 日志不得记录 raw token、完整邮箱地址、完整 Message-ID、完整订单号、完整手机号、会员号、证件号或银行卡号。
- 附件去重使用 token hash + Message-ID hash + attachment hash。
- Worker 不调用酒店水单 LLM，不生成 `HotelStayDraft`、`HotelStayRecord` 或 `Transaction`。

## 5. 审核材料草稿

```text
AutoLedger includes a planned Hotel Folio Cloud Inbox flow. In this build, the cloud inbox is not publicly enabled yet. The build only includes local App/Core contracts and routing needed for a future user-controlled inbox address such as folio+<token>@getautoledger.app.

The future C1 flow will not log in to a user's personal mailbox and will not store QQ/IMAP/Gmail/Outlook authorization codes. The Worker only processes hotel folio emails that the user forwards or sends to an AutoLedger dedicated address. PDF attachments are intended to be stored temporarily and deleted after the App downloads/converts them or after expiration.

Reviewers do not need to log in to any real mailbox for this build. To test the user-facing hotel folio flow, open AutoLedger > Hotel Stays, tap +, import a hotel folio PDF or share a PDF to AutoLedger, review the locally extracted fields, and confirm before posting. All recognized hotel folios remain pending review until the user explicitly confirms them.
```

## 6. 发布前检查

- 提审说明必须明确 C1 专属收件箱在当前版本未公开启用。
- 若未来启用真实 Worker，需要补充测试专属地址或示例 PDF，不要求审核员登录真实邮箱。
- 若未来启用 APNs，需要验证推送文案不泄露酒店名、金额、订单号或入住日期。
- 若未来启用对象存储，需要验证 PDF 过期删除、用户删除和 App 转换后删除。
- 若未来启用订阅 gating，需要验证未订阅用户不会产生云端上传或处理。
