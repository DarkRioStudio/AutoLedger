# v1.5.1 回归基线

更新日期：2026-06-16

## 1. 目标

本基线承接 `v1.5.0` 已完成的 iPhone / iPad / Apple Watch / Mac Catalyst 主线能力，并把 `v1.5.1` 新增的最低系统需求优化、识别链路重构、外部辅助识别、编辑保存稳定性和 iCloud 同步修复纳入最终发布前回归。

本文件同时回答三个问题：

1. iOS / iPad 端是否还有未落地内容。
2. Mac Catalyst 目前有哪些测试覆盖。
3. 发布前需要哪些可重复测试用例。

## 2. 当前落地状态

| 平台 | 当前判断 | 已落地能力 | 仍需回归 |
|------|----------|------------|----------|
| iPhone / iOS | 主线已落地 | 截图 / 相机 / 剪贴板 / Share / Shortcuts / App Intent 记账、JSON Intent、外部辅助识别开关、编辑保存、iCloud 同步、桌面 / 负一屏小组件 | 真机 smoke、快捷指令端到端、外部辅助识别隐私文案、iCloud 大量账本同步卡顿复测 |
| iPad | 第一版工作台已落地 | 侧边栏工作台、总览、独立导入页、候选队列、批量识别、账本表格、分析页、数据清洗、设置页、iCloud 同步 | 真机 / iPadOS smoke、多文件导入、候选保存、清洗撤销、下拉刷新拉取 iCloud |
| Mac Catalyst | 第一版生产力工作流已落地 | Catalyst build、Mac 菜单栏、键盘快捷键、文件拖拽 / file importer、CSV 导入导出、JSON 备份导出 / 恢复入口、桌面账本表格、多选、批量修正、重复检查、Mac 截图导出 | Mac 桌面手工 smoke；目前无自动 UI 测试，只由 build、离线核心回归和截图导出覆盖 |
| Apple Watch / Widget | 第一版已落地但仍需真机复测 | 今日支出、最近支出、Watch 表盘小组件、iPhone 小组件 | iPhone 入账后表盘自动刷新、Watch 真机启动刷新 |
| tvOS / visionOS | 不进入当前落地范围 | target / 设计 / 构建评估 | 产品代码顺延到后续版本 |

结论：iOS / iPad / Mac 当前不是“缺主线代码”，而是缺最终发布前的端到端 smoke 记录，尤其 Mac 缺 UI 操作层面的回归证据。

## 3. 命令级回归

每次进入发布候选前至少执行：

```bash
git diff --check

bash scripts/run_offline_regression.sh
bash scripts/run_golden_regression.sh

xcodebuild -workspace AutoLedger/AutoLedger.xcworkspace \
  -scheme AutoLedger \
  -configuration Debug \
  -destination 'generic/platform=iOS' \
  build

xcodebuild -workspace AutoLedger/AutoLedger.xcworkspace \
  -scheme AutoLedger \
  -configuration Debug \
  -destination 'platform=macOS,variant=Mac Catalyst' \
  build
```

截图回归按需要执行：

```bash
bash tools/appstore-screenshots/scripts/export.sh --ios-only --locale zh-Hans
bash tools/appstore-screenshots/scripts/export.sh --watch-only --locale zh-Hans
bash tools/appstore-screenshots/scripts/export.sh --ipad-only --locale zh-Hans
bash tools/appstore-screenshots/scripts/export.sh --mac-only --locale zh-Hans
```

## 4. 自动 / 离线覆盖

| 能力 | 自动覆盖 | 说明 |
|------|----------|------|
| OCR 文本解析 / 金额 / 商户 / 分类 | `run_offline_regression.sh`、`run_golden_regression.sh` | 覆盖 Core parser、ReceiptParser、特殊支付场景、地铁储值卡、通知中心地铁样式 |
| JSON App Intent 结构化账单 | `verifyStructuredLedgerJSONParsing` | 覆盖金额、商户、分类、日期、备注、币种、置信度分流 |
| 外部辅助识别 | `verifyExternalReceiptAssist*` | 覆盖脱敏 payload、gate、provider preset、OpenAI-compatible codec、suggestion mapper |
| 候选队列 | `verifyBatchImportQueue` | 覆盖 raw input、candidate、reviewed、transaction、rejected 状态流 |
| 批量识别 | `verifyBatchImportRecognitionExecutor` | 覆盖文本输入、空输入、OCR 缺失、unsupported file、retry |
| 数据清洗 | `verifyDataCleaningPreviewPlanner`、`verifyLedgerImportFlow` | 覆盖商户别名、分类修正、重复检测、应用与撤销 |
| CSV | `verifyLedgerCSVCodec` | 覆盖 CSV round-trip、quoted note、无效行进入 review |
| JSON backup | `verifyBackupRoundTrip` | 覆盖 active / deleted / subscriptions / custom categories / aliases / corrections |
| iCloud 同步核心策略 | `verifySyncConflictResolver`、`verifyLedgerSyncPlanner`、SQLite remote sync cases | 覆盖 schema、planner、冲突、批量 remote apply summary |
| Mac Catalyst 构建 | `xcodebuild ... Mac Catalyst build` | 当前只证明编译、签名、资源和 Catalyst target 可构建，不证明菜单 / 拖拽 UI 真实可用 |

## 5. iPhone / iOS 手工测试用例

| Case | 步骤 | 期望 |
|------|------|------|
| IOS-001 手动记账 | 新增一笔手动账单，编辑商户 / 金额 / 分类后保存 | 保存按钮状态正常，账本展示与编辑内容一致 |
| IOS-002 支付截图导入 | 从相册导入一张支付截图 | 生成账单或确认提示，金额不被 LLM 覆盖规则金额 |
| IOS-003 快捷指令截图记账 | 通过快捷指令传入截图 | 成功入账后触发待推送标记，调试记录可复制 |
| IOS-004 JSON Intent 高置信 | Shortcuts / 剪贴板传入高置信 JSON | 自动保存为正式账单 |
| IOS-005 JSON Intent 中置信 | 传入中置信 JSON | 打开 App 内确认页，确认后入账 |
| IOS-006 外部辅助识别 | 开启外部辅助识别并配置 provider key | 调试记录显示 provider / model / 脱敏请求摘要，不输出 API key |
| IOS-007 地铁通知样式 | 导入“城市卡 + 地铁：CN¥金额 + 路线行”文本 / 截图 | 纯规则解析为 `地铁：起点→终点`，分类出行，不进入外部模型 |
| IOS-008 iCloud 同步 | iPhone 新增 / 编辑 / 删除账单后等待同步 | iPad / Mac 拉取后数据一致，无 UI 长时间卡死 |
| IOS-009 小组件刷新 | iPhone 新增今日账单后查看桌面 / 负一屏小组件 | 今日金额和最近商户更新或在合理延迟后更新 |

## 6. iPad 手工测试用例

| Case | 步骤 | 期望 |
|------|------|------|
| IPAD-001 工作台切换 | 在总览、导入、账本、分析、候选账单、数据清洗、设置之间切换 | 点击整行生效，进入二级页后切换其他 Tab 右侧页面会重建 |
| IPAD-002 独立导入页 | 打开导入页，分别使用相册、拍照、剪贴板、文件导入入口 | 导入操作和查看队列口径清楚，不出现重复标题或重复主按钮 |
| IPAD-003 批量队列识别 | 导入多条文本 / 文件后点击识别 | raw input 转 candidate，失败项保留原因，候选不进入正式账本统计 |
| IPAD-004 候选复核入账 | 选中候选账单，修正字段并保存 | 写入正式账本，队列状态变为 transaction |
| IPAD-005 候选忽略 / 重试 | 对失败或低置信候选执行忽略、重试 | 状态变化正确，不污染正式账本 |
| IPAD-006 账本表格 | 搜索、排序、选择账单并编辑 | 列表区域稳定，统计卡尺寸对齐，文字在卡片内自适应 |
| IPAD-007 数据清洗 | 应用商户统一、分类修正、疑似重复清理，再撤销 | 应用前有确认，撤销后账本恢复 |
| IPAD-008 iCloud 拉取 | iPhone 先新增账单，iPad 账本页下拉刷新 | iPad 拉取最新账单，不先覆盖本地未推送更改 |

## 7. Mac Catalyst 手工测试用例

| Case | 步骤 | 期望 |
|------|------|------|
| MAC-001 启动与窗口 | 运行 Mac Catalyst App，调整窗口大小 | 工作台布局不重叠，卡片 / 表格随窗口变化保持可读 |
| MAC-002 菜单栏导入文件 | 使用 `Import -> Import Files...` 或 `Shift-Command-I` | 路由到导入页并打开文件导入流程 |
| MAC-003 拖拽导入 | 从 Finder 拖入图片 / 文本 / CSV 到导入页 | 支持类型进入队列，不支持类型显示失败原因 |
| MAC-004 CSV 导入 | 使用 `Import -> Import CSV...` 或 `Option-Command-I` 选择 CSV | CSV 行进入候选队列；无效行标记需要处理 |
| MAC-005 CSV 导出 | 使用 `Export -> Export CSV...` 或 `Shift-Command-E` | 生成 CSV 文件，字段可被重新导入 |
| MAC-006 JSON 备份 | 使用 `Backup -> Export JSON Backup...` 或 `Option-Command-B` | 生成 JSON 备份；恢复 JSON 仍必须走页面内二次确认 |
| MAC-007 设置快捷键 | 使用 `Command-,` | 打开设置页；从设置二级页切换左侧其他 Tab 后右侧页面更新 |
| MAC-008 大表格批量选择 | 在账本页搜索、排序、多选、全选筛选结果 | 选择状态稳定，批量操作只影响选中 / 筛选范围 |
| MAC-009 批量商户 / 分类修正 | 对多选账单应用批量修正 | 二次确认展示影响范围；保存后 SQLite、Widget、iCloud 增量推送链路正常 |
| MAC-010 重复账单检查 | 准备同金额 / 近时间 / 相似备注账单并打开重复面板 | 显示疑似重复组；确认后较旧重复项进入最近删除；可回滚验证 |
| MAC-011 iCloud 同步 | iPhone / iPad 新增账单后 Mac 启动或刷新 | Mac 拉取到账本更新；同步期间 App 不长时间无响应 |

## 9. 发布前结论

- iOS / iPad：主线功能已经落地，重点转入真机 smoke 和同步 / 编辑 / 识别链路复测。
- Mac Catalyst：功能路径已经落地，当前有 build、Core 离线回归和截图导出基线；缺少自动 UI 测试，发布前必须按 `MAC-001` 到 `MAC-011` 做一轮手工 smoke。
- 当前不建议再扩 iOS / iPad / Mac 新能力；除非 smoke 发现 blocker，否则应进入最终 smoke、Xcode Cloud 和 ASC 收口。
