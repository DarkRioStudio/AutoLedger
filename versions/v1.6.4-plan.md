## 0. 文档分析结论

`docs/autoledger-personal-pro-design.md` 的核心判断是：AutoLedger 可以做订阅，但不能做“功能封锁型订阅”。

适合落地的产品原则：

- 免费版必须继续是一款完整可用的本地个人记账 App。
- 已经形成基础预期的能力不回收：手动记账、截图识别、基础 OCR、手动 PDF / 图片导入、手动复核、基础月报、基础订阅提醒、Widget / Share Extension 基础入口、JSON / CSV 备份恢复、查看 / 编辑 / 删除历史数据。
- Pro 售卖的是自动化效率：替用户查找、筛选、批量处理、去重、整理、生成结果和持续监控。
- 每个 Pro 自动化能力都必须有免费手动路径。
- Pro 到期后不锁历史数据；停止的是新的自动化能力。
- 既有 `Support Developer` 内购应继续作为赞助线，不能和 Pro 订阅权益混在一起。

对当前工程的影响：

- `v1.6.3` C1 专属收件箱和 `v1.6.2` 本地邮箱水单导入都需要一个清晰的 Pro entitlement 边界。
- 不能把“酒店消费 tab”“手动 PDF 导入”“查看酒店记录”放到付费墙后面。
- 可以把“邮箱自动扫描”“批量候选导入”“高级去重”“自动归档 / 月结包”等省时间能力作为 Pro。
- 第一版应先建立 StoreKit 订阅、权益判断、付费页、恢复购买、过期状态和邮箱自动化 gate，而不是一次实现全部 Pro v1 权益。
- 高级搜索、订阅异常提醒、月结导出包和高级规则自动应用不再作为 `v1.6.4` 的 P1 实现候选，只在 Pro 页面路线图预告；实际实现统一放到 `v1.7.0 / ASC 1.6.0`。

## 1. 版本定位

`v1.6.4` 聚焦 Personal Pro 的基础设施与第一批自动化权益边界。

本版本目标不是把 AutoLedger 改成订阅优先产品，而是给酒店 C1、邮箱自动化、批量导入和高级去重建立可审计、可回归、可撤回的 Pro 基座。非酒店模块 Pro 扩展只做路线图预告，实际实现顺延到 `v1.7.0 / ASC 1.6.0`。

一句话定位：

> 免费版手动完成，Pro 自动整理。

## 2. P0 范围：Pro 基础和邮箱自动化 gate

### 2.1 Free / Pro 边界冻结

目标：用代码和文档同时固定“基础能力不回收”的边界。

免费版必须继续可用：

- 手动新增、编辑、删除账单。
- 单张截图识别和手动确认。
- 手动 PDF / 图片导入酒店水单。
- 查看、编辑、删除酒店消费记录和原始 PDF。
- 基础订阅管理和提醒。
- 基础月报。
- 基础 Widget / Share Extension 入口。
- JSON / CSV 基础导入导出、备份恢复。
- 查看和编辑所有历史数据。

Pro P0 gate：

- 本地邮箱水单批量导入的无限额度；免费用户每月保留 1 次成功导入额度，扫描和候选预览不锁。
- 批量候选附件导入的无限额度。
- 高级去重自动拦截和解释。
- C1 专属收件箱自动导入入口。

### 2.2 ProEntitlementManager

目标：新增独立 Pro 订阅管理器，不改造现有 `Support Developer` 赞助内购。

建议职责：

- 拉取 Pro subscription products。
- 监听 StoreKit transaction updates。
- 判断 `isProActive`。
- 判断 `canUse(_ feature: ProFeature)`。
- 支持恢复购买。
- 暴露过期、宽限期、账单重试、未订阅等状态。
- 为 UI 提供可展示的订阅状态摘要。

建议商品：

```text
Subscription Group: AutoLedger Pro
Product ID: top.darkrio326.AutoLedger.pro.monthly
Product ID: top.darkrio326.AutoLedger.pro.yearly
```

首发价格建议沿用设计文档口径：

- Monthly：`$2.99 / month`
- Yearly Early Supporter：`$19.99 / year`

实际价格等级和本地化展示以 App Store Connect 为准。

### 2.3 ProFeature gate

目标：统一权益开关，避免各页面散落字符串判断。

建议第一版枚举：

```swift
enum ProFeature: String, CaseIterable {
    case emailFolioScan
    case batchCandidateImport
    case advancedDeduplication
    case cloudFolioInbox
    case advancedSearch
    case subscriptionAnomalyDetection
    case monthlyExportPackage
}
```

P0 只真正 gate：

- `emailFolioScan`
- `batchCandidateImport`
- `advancedDeduplication`
- `cloudFolioInbox`

其余 feature 先进入 Pro 页面路线图，不作为当前版本交付门槛，并统一归入 `v1.7.0 / ASC 1.6.0`。

### 2.4 Pro 页面与恢复购买

目标：让用户能理解 Pro 是自动化效率层，并能完成订阅、恢复购买和管理订阅。

页面要点：

- 标题：`AutoLedger Pro`
- 副标题：`自动整理账单和水单，少花时间做重复记账。`
- 当前权益卡片：本地邮箱扫描、专属水单收件箱、批量候选、高级去重。
- 路线图预告：高级搜索、订阅异常提醒、月结导出包、高级规则自动应用，标注 `v1.7.0 / ASC 1.6.0`，不暗示当前可用。
- 免费版说明：没有 Pro 也可以继续手动记账、手动导入水单和查看所有历史数据。
- 操作：订阅月付、订阅年付、恢复购买、管理订阅。

降级文案建议：

> 这项自动化能力属于 AutoLedger Pro。你仍然可以手动导入水单；升级 Pro 后，AutoLedger 可以从邮箱中自动查找并批量整理。

第一版工程落地（2026-06-29）：

- `AutoLedgerProView` 已接入月付 / 年付商品入口、恢复购买和管理订阅入口。
- Pro 页面新增订阅状态卡，区分未订阅、已订阅和 DEBUG override 状态。
- 已订阅状态展示当前 product、到期时间和最近校验时间；未订阅状态明确免费基础记账、手动水单导入和历史数据仍可使用。
- `ProEntitlementManager` 记录 active subscription snapshot、恢复购买 loading 状态和管理订阅 loading 状态。
- 管理订阅通过系统 App Store 订阅管理入口打开，不在 App 内自建取消 / 续订流程。
- `AutoLedgerSupport.storekit` 已补充 `AutoLedger Pro` subscription group、本地月付 `$2.99 / month` 和首发年付 `$19.99 / year`，继续与 `top.darkrio326.AutoLedger.pro.monthly` / `top.darkrio326.AutoLedger.pro.yearly` 保持一致。

### 2.5 邮箱授权引导重构

目标：把当前邮箱 IMAP 配置页从“技术表单”升级为可信任的授权流程。

流程建议：

1. 价值说明页：自动从邮箱查找水单。
2. 隐私说明页：邮箱授权只保存在本机。
3. 选择邮箱 provider。
4. 展示 provider 专属授权教程。
5. 输入邮箱地址与授权码 / 应用专用密码。
6. 本机连接测试。
7. 选择扫描范围。
8. 执行扫描。
9. 展示候选邮件 / 附件。
10. 批量导入待确认队列。

P0 必须强调：

- 授权码仅保存在本机 Keychain。
- 不上传邮箱授权码。
- 不上传完整邮箱内容。
- 扫描结果进入待确认队列，不自动入账。
- 可以随时移除本机授权。

字段命名：

- 使用 `授权码 / 应用专用密码`。
- 避免使用 `邮箱密码`。

连接测试应先做轻量验证，不立即扫描大量邮件。

### 2.6 免费体验与预览策略

目标：让免费用户看到 Pro 自动化价值，但不阻断手动路径。

建议 P0 策略：

- 免费用户可以查看邮箱 provider 教程。
- 免费用户可以进行连接测试。
- 免费用户可以预览候选数量或候选摘要。
- 免费用户可以每月成功导入 1 次本地邮箱水单候选，方便真实体验端到端流程。
- Pro 用户不限制本地邮箱水单导入次数。
- 超出免费月度额度后的继续导入、高级去重和 C1 专属收件箱自动导入需要 Pro。

第一版额度只在“成功生成待确认酒店水单草稿”后消耗；扫描、连接测试、候选预览和失败导入不会消耗额度。

### 2.7 Pro 到期和历史数据访问

目标：确保订阅状态变化不影响用户已有数据。

到期后仍可：

- 查看历史 Pro 导入的账单和酒店水单。
- 查看已保存的原始 PDF。
- 编辑历史账单和酒店消费记录。
- 删除自己的历史数据。
- 使用基础导出和备份恢复。

到期后暂停：

- 新的邮箱自动扫描。
- 新的批量候选导入。
- 新的高级去重任务。
- 新的 C1 专属收件箱自动处理。
- 后续高级月结包和订阅异常检测。

第一版工程落地（2026-06-29）：

- 设置页和 Pro 页面会展示当前 Pro 状态；到期或未订阅时只提示自动化能力暂停，不暗示历史账本或酒店记录被锁。
- `ProEntitlementManager.canUse(_:)` 继续作为自动化入口 gate；免费基础能力仍由 `AutoLedgerProAccessPolicy` 回归固定。
- 数据清洗 / 疑似重复处理工作区已接入 `.advancedDeduplication` gate：未订阅时展示 Pro 自动化说明，手动编辑历史账单仍保持免费。
- 当前状态文案已四语本地化，后续 StoreKit 生命周期测试会继续覆盖过期、恢复购买和订阅管理 smoke。

### 2.9 C1 专属收件箱与 Pro gate 工程落地状态（2026-06-29）

本轮将 `v1.6.3` 顺延的 C1 真实 Worker / 云候选 API / App 列表导入 / APNs 唤醒主链路接到 `v1.6.4` 的 Pro gate 基座。

命名原则：

- 规划文档可以继续使用 `C1` 表示阶段。
- 程序目录、包名、Worker 名称、代码变量、API 路径和数据库表不使用版本号、阶段号或 GOAL 号。
- 工程实现统一使用稳定业务域命名，例如 `hotel-folio-inbox`、`cloud-hotel-folio-candidates`、`cloudFolioInbox`。

已落地：

- App 侧新增 `ProEntitlementManager` 第一版，拉取 Pro subscription product、监听 StoreKit transaction updates、刷新当前 entitlement，并用 `AutoLedgerCapability.cloudFolioInbox` 判断云收件箱入口是否可用。
- 酒店消费 tab 右上角菜单新增云端酒店水单收件箱入口；未订阅 Pro 时展示自动化能力说明，手动 PDF 导入和历史酒店记录继续免费可用。
- App 侧新增 `HotelFolioInboxClient` 和 `HotelFolioInboxImportView`，支持自动向 Worker 领取 / 轮换专属收件箱 token、保存 endpoint / token、展示 `folio+<token>@getautoledger.app`、刷新云候选、批量下载 PDF、复用本地 PDFKit 和 `HotelFolioParsePipeline` 生成 `HotelStayDraft(sourceType: .cloudWorker)`。
- App 侧领取 / 保存专属收件箱配置后会请求通知权限、注册 APNs device token，并通过云候选 API 登记设备；通知点击后复用 deep link handoff，打开酒店消费候选导入页面。
- Worker 新增 `tools/worker/hotel-folio-inbox`，使用 Cloudflare Email Routing `email()` handler 接收发往 AutoLedger 专属地址的邮件。
- Worker 使用 `postal-mime` 解析 MIME，只提取 PDF 附件，计算附件 hash，写入 R2，并在 D1 创建 `cloud_hotel_folio_candidates`。
- Worker 提供 `POST /v1/cloud-hotel-folio-token` bootstrap provisioning API：App 传入本机 client id 后，Worker 生成随机 token、只保存 token hash、返回一次专属邮箱地址，并将同一 client 的旧 active token 标记为 rotated。
- Worker 使用 D1 `pro_inbox_tokens` 做服务端 Pro gate：token 必须 active，且 `pro_expires_at` 未过期；后续订阅后端接入时可在 token provisioning 前追加服务端 entitlement 校验。
- Worker 提供候选列表、PDF 下载、状态回写和设备登记 API；App 成功转换后可回写 `converted` 并删除云端 PDF。
- Worker 通过 Queue consumer 读取通知事件，按 `user_id` 查找已登记 APNs device token，发送只含隐私安全文案和 `autoledger://hotel-cloud-candidate/...` deep link 的推送。
- Worker 定时清理过期候选和对应 R2 PDF，默认短期暂存 7 天，可通过 `CANDIDATE_RETENTION_DAYS` 调整。
- 调试与回归路径保留云端候选下载、PDFKit 提取和草稿生成日志，方便定位云端导入失败点。

Cloudflare 部署状态：

- 已创建并部署 dev / staging / production 三套 Cloudflare 资源：R2 bucket、D1 database、Queue、Worker producer / consumer 和 daily cron。
- 已绑定 `https://folio.getautoledger.app` 到 production Worker，`https://staging-folio.getautoledger.app` 到 staging Worker。
- 已启用 `getautoledger.app` Email Routing，并创建 `folio@getautoledger.app -> autoledger-hotel-folio-inbox-production` 规则；catch-all 保持关闭并 drop 未匹配邮件。

仍属于部署 / 运营配置，不进入源码：

- APNs `APNS_KEY_ID`、`APNS_TEAM_ID`、`APNS_PRIVATE_KEY` 等密钥，通过 `wrangler secret put` 配置，不写入仓库。
- 服务端订阅 entitlement 校验、token 停用、Pro 到期续期同步和后台运营面板。
- App Store Connect Pro 商品、StoreKit 本地测试配置、购买页、恢复购买 UI 和审核截图。

明确非目标：

- Worker 不登录用户邮箱，不保存 QQ / IMAP / Gmail / Outlook 授权码。
- Worker 初版不识别 PDF，不调用酒店水单 LLM，不生成正式酒店消费记录，不生成普通账单。
- C1 不自动正式入账；所有云候选仍必须进入 App 待确认流程。
- 云端 PDF 不长期保存；App 成功下载 / 转换后优先删除，未处理候选按过期策略清理。

### 2.10 GOAL-2218 本地 IMAP 水单候选召回规则重审

目标：把本地邮箱水单扫描从“拉取足够多邮件后展示候选”收敛为可解释、可验证的水单候选召回任务，避免用户看到大量普通附件邮件。

当前问题：

- 仅按最近 N 天 / 最多 N 封邮件拉取，在真实邮箱中仍会混入大量 Xcode Cloud、TestFlight、Apple Developer、行程凭证和普通附件邮件。
- 仅按“有附件”判断过宽；但真实酒店水单也可能没有附件，只在邮件正文中给出账单内容。
- 固定 30 天 / 100 封在高频邮箱里可能覆盖不到目标日期；全量拉取又会带来性能、隐私和候选噪音问题。
- 不同 IMAP provider 对 `SEARCH`、附件标记、中文主题和 mailbox 选择支持不一致，需要形成 provider-safe 的降级策略。

P0 设计方向：

1. 保持用户主动触发扫描，不做后台自动读取。
2. 搜索窗口继续受日期范围和最大读取数约束；iPhone 端可保持默认固定值，Mac 端保留高级配置。
3. 先做服务端轻量 `SEARCH` / header fetch，尽量用日期、主题关键词和附件 hint 缩小范围；失败时降级为近期 header 扫描，不直接抓取完整正文。
4. 本地按邮件 header、发件人、主题、附件名和 MIME metadata 打分，只有候选达到阈值后才抓取正文或附件。
5. 附件邮件优先，但不是所有附件邮件都进入候选；PDF 附件、附件名和主题命中水单关键词时优先级最高。
6. 无附件邮件如果主题命中 `folio`、`账单`、`电子账单`、`hotel`、`Marriott` 等水单关键词，应进入正文水单候选，并复用正文转 PDF 后的本地 PDFKit 流程。
7. 候选列表展示命中原因，例如“PDF 附件 + Folio 主题”“无附件 + 账单主题”“酒店品牌命中”，便于用户判断为什么出现。
8. 默认勾选仅限高置信候选；低置信候选展示但不默认选中，避免批量误导入。

建议候选分层：

- A 级：PDF 附件 + 主题 / 附件名命中 `folio`、`账单`、`电子账单`、酒店名或酒店品牌。
- B 级：有 PDF 附件 + 发件人或正文摘要命中酒店 / OTA / 水单关键词。
- C 级：无附件 + 主题命中 `folio`、`账单`、`电子账单`、酒店品牌或酒店名；正文后续转为本地 PDF 候选。
- D 级：有附件但只命中弱信号，需要手动展开，不默认勾选。
- 排除 / 降权：Xcode Cloud、TestFlight、Apple Developer、普通验证码、系统通知、行程乘机凭证等明显非酒店水单邮件。

验收重点：

- 真实邮箱中 30 天内大量附件邮件不会全部展示为水单候选。
- 用户截图中的 `Moxy-Chongqing Folio账单`、`Beihai Marriott Resort 电子账单`、`Na Lotus Hotel ... 电子账单`、`Crowne Plaza ... 账单` 这类邮件应进入候选。
- 无 PDF 附件但主题包含 `folio` / `账单` 的邮件，应能进入候选，并在用户选择后走正文转 PDF -> PDFKit -> `HotelFolioParsePipeline`。
- 候选输出必须保留本地隐私原则：授权码只在 Keychain，完整邮箱内容不上传云端，识别前仍走脱敏和用户复核。
- 第一版工程落地（2026-06-29）：已在 Core 新增候选分层、命中原因、得分和默认勾选合同；App 本地 IMAP 扫描接入候选过滤、Pro gate、候选命中原因展示和默认勾选策略；离线回归覆盖普通附件噪音排除、酒店水单召回和正文水单候选。
- 后续深化方向：继续用真实邮箱样例收紧 provider-safe 的 `SEARCH` / header fetch / MIME 轻量预筛，避免为低置信邮件提前抓取完整正文。

## 3. v1.7.0 / ASC 1.6.0 路线图预告：Pro 权益扩展

这些能力属于 `docs/autoledger-personal-pro-design.md` 推荐的 Pro v1 权益，但当前不再作为 `v1.6.4` 的实现范围。`v1.6.4` 只在 Pro 页面做路线图预告；实际产品实现、gate、回归和审核材料统一放到 `v1.7.0 / ASC 1.6.0`。

### 3.1 高级搜索

支持按金额区间、日期、商户、酒店、邮箱、附件、备注、分类、来源组合搜索。

免费版保留基础搜索。

目标版本：`v1.7.0 / ASC 1.6.0`。

### 3.2 订阅异常提醒

检测订阅涨价、重复扣费、周期异常和未来 7 / 30 / 90 天续费压力。

免费版保留基础订阅记录和提醒。

目标版本：`v1.7.0 / ASC 1.6.0`。

### 3.3 月结导出包

生成当月 Excel / PDF 月结包，包含账单明细、分类统计、商户排行、水单附件索引。

免费版保留基础 CSV / JSON 导出和备份恢复。

目标版本：`v1.7.0 / ASC 1.6.0`。

### 3.4 高级规则自动应用

支持商户别名合并、关键词规则、分类规则、历史记录一键应用和低置信度集中复核。

免费版保留单条商户 / 分类修改。

目标版本：`v1.7.0 / ASC 1.6.0`。

## 4. Later：更高档位或未来路线

以下不进入 `v1.6.4`：

- 团队版 / Business。
- 会计协作。
- 云端保存用户邮箱授权码。
- Worker 登录用户邮箱自动扫描。
- 云端 AI 自动生成正式账单。
- 自动正式入账。
- 长期云端保存用户酒店水单 PDF。
- 把历史数据锁进 Pro。
- 把基础导出和备份恢复改成付费。
