# v1.6.4 版本计划：个人 Pro 订阅基础与自动化权益边界

更新日期：2026-06-29
文档状态：Active / GOAL-2200 已完成；C1 专属收件箱代码主链路已落地
内部开发线：v1.6.4
App Store 对外版本：默认继续沿用 ASC 1.5.0 资产策略；如启用订阅商品，需要在提审前补齐 IAP / Subscription 审核说明、隐私政策和 StoreKit 截图
承接版本：v1.6.3
关联文档：`docs/autoledger-personal-pro-design.md`、`docs/iap-support.md`、`versions/v1.6.3-plan.md`

## 0. 文档分析结论

`docs/autoledger-personal-pro-design.md` 的核心判断是：AutoLedger 可以做订阅，但不能做“功能封锁型订阅”。

适合落地的产品原则：

- 免费版必须继续是一款完整可用的本地个人记账 App。
- 已经形成基础预期的能力不回收：手动记账、截图识别、基础 OCR、手动 PDF / 图片导入、手动复核、基础月报、基础订阅提醒、Widget / Share Extension 基础入口、JSON / CSV 备份恢复、查看 / 编辑 / 删除历史数据。
- Pro 售卖的是自动化效率：替用户查找、筛选、批量处理、去重、整理、生成结果和持续监控。
- 每个 Pro 自动化能力都必须有免费手动路径。
- Pro 到期后不锁历史数据；停止的是新的自动化能力。
- 既有 `Support Developer` 内购应继续作为赞助线，不能和 Pro 订阅权益混在一起。

对当前工程的影响：

- `v1.6.3` C1 专属收件箱和 `v1.6.2` 本地邮箱水单导入都需要一个清晰的 Pro entitlement 边界。
- 不能把“酒店消费 tab”“手动 PDF 导入”“查看酒店记录”放到付费墙后面。
- 可以把“邮箱自动扫描”“批量候选导入”“高级去重”“自动归档 / 月结包”等省时间能力作为 Pro。
- 第一版应先建立 StoreKit 订阅、权益判断、付费页、恢复购买、过期状态和邮箱自动化 gate，而不是一次实现全部 Pro v1 权益。

## 1. 版本定位

`v1.6.4` 聚焦 Personal Pro 的基础设施与第一批自动化权益边界。

本版本目标不是把 AutoLedger 改成订阅优先产品，而是给酒店 C1、邮箱自动化、批量导入、月结包和订阅异常提醒建立可审计、可回归、可撤回的 Pro 基座。

一句话定位：

> 免费版手动完成，Pro 自动整理。

## 2. P0 范围：Pro 基础和邮箱自动化 gate

### 2.1 Free / Pro 边界冻结

目标：用代码和文档同时固定“基础能力不回收”的边界。

免费版必须继续可用：

- 手动新增、编辑、删除账单。
- 单张截图识别和手动确认。
- 手动 PDF / 图片导入酒店水单。
- 查看、编辑、删除酒店消费记录和原始 PDF。
- 基础订阅管理和提醒。
- 基础月报。
- 基础 Widget / Share Extension 入口。
- JSON / CSV 基础导入导出、备份恢复。
- 查看和编辑所有历史数据。

Pro P0 gate：

- 本地邮箱水单扫描。
- 批量候选附件导入。
- 高级去重自动拦截和解释。
- C1 专属收件箱自动导入入口。

### 2.2 ProEntitlementManager

目标：新增独立 Pro 订阅管理器，不改造现有 `Support Developer` 赞助内购。

建议职责：

- 拉取 Pro subscription products。
- 监听 StoreKit transaction updates。
- 判断 `isProActive`。
- 判断 `canUse(_ feature: ProFeature)`。
- 支持恢复购买。
- 暴露过期、宽限期、账单重试、未订阅等状态。
- 为 UI 提供可展示的订阅状态摘要。

建议商品：

```text
Subscription Group: AutoLedger Pro
Product ID: top.darkrio326.AutoLedger.pro.monthly
Product ID: top.darkrio326.AutoLedger.pro.yearly
```

首发价格建议沿用设计文档口径：

- Monthly：`$2.99 / month`
- Yearly Early Supporter：`$19.99 / year`

实际价格等级和本地化展示以 App Store Connect 为准。

### 2.3 ProFeature gate

目标：统一权益开关，避免各页面散落字符串判断。

建议第一版枚举：

```swift
enum ProFeature: String, CaseIterable {
    case emailFolioScan
    case batchCandidateImport
    case advancedDeduplication
    case cloudFolioInbox
    case advancedSearch
    case subscriptionAnomalyDetection
    case monthlyExportPackage
}
```

P0 只真正 gate：

- `emailFolioScan`
- `batchCandidateImport`
- `advancedDeduplication`
- `cloudFolioInbox`

其余 feature 先进入 Pro 页面路线图，不作为当前版本交付门槛。

### 2.4 Pro 页面与恢复购买

目标：让用户能理解 Pro 是自动化效率层，并能完成订阅、恢复购买和管理订阅。

页面要点：

- 标题：`AutoLedger Pro`
- 副标题：`自动整理账单和水单，少花时间做重复记账。`
- 权益卡片：邮箱水单自动扫描、批量导入与复核、智能去重、订阅异常提醒、月结导出包。
- 免费版说明：没有 Pro 也可以继续手动记账、手动导入水单和查看所有历史数据。
- 操作：订阅月付、订阅年付、恢复购买、管理订阅。

降级文案建议：

> 这项自动化能力属于 AutoLedger Pro。你仍然可以手动导入水单；升级 Pro 后，AutoLedger 可以从邮箱中自动查找并批量整理。

### 2.5 邮箱授权引导重构

目标：把当前邮箱 IMAP 配置页从“技术表单”升级为可信任的授权流程。

流程建议：

1. 价值说明页：自动从邮箱查找水单。
2. 隐私说明页：邮箱授权只保存在本机。
3. 选择邮箱 provider。
4. 展示 provider 专属授权教程。
5. 输入邮箱地址与授权码 / 应用专用密码。
6. 本机连接测试。
7. 选择扫描范围。
8. 执行扫描。
9. 展示候选邮件 / 附件。
10. 批量导入待确认队列。

P0 必须强调：

- 授权码仅保存在本机 Keychain。
- 不上传邮箱授权码。
- 不上传完整邮箱内容。
- 扫描结果进入待确认队列，不自动入账。
- 可以随时移除本机授权。

字段命名：

- 使用 `授权码 / 应用专用密码`。
- 避免使用 `邮箱密码`。

连接测试应先做轻量验证，不立即扫描大量邮件。

### 2.6 免费体验与预览策略

目标：让免费用户看到 Pro 自动化价值，但不阻断手动路径。

建议 P0 策略：

- 免费用户可以查看邮箱 provider 教程。
- 免费用户可以进行连接测试。
- 免费用户可以预览候选数量或候选摘要。
- 批量扫描、批量导入、高级去重和 C1 专属收件箱自动导入需要 Pro。

如果需要更保守的策略，可在第一版只开放“候选预览”，不开放每月免费扫描次数，避免额度逻辑过早复杂化。

### 2.7 Pro 到期和历史数据访问

目标：确保订阅状态变化不影响用户已有数据。

到期后仍可：

- 查看历史 Pro 导入的账单和酒店水单。
- 查看已保存的原始 PDF。
- 编辑历史账单和酒店消费记录。
- 删除自己的历史数据。
- 使用基础导出和备份恢复。

到期后暂停：

- 新的邮箱自动扫描。
- 新的批量候选导入。
- 新的高级去重任务。
- 新的 C1 专属收件箱自动处理。
- 后续高级月结包和订阅异常检测。

### 2.8 GOAL-2200 工程落地状态（2026-06-29）

本轮完成 `GOAL-2200`，将 Free / Pro 边界从产品文档落到平台无关层合同。

已落地：

- 新增 `AutoLedgerCapability`，枚举基础免费能力、P0 Pro 自动化能力和后续 Pro 自动化能力。
- 新增 `ProAccessTier`，区分 `freeCore`、`proAutomationP0` 和 `proAutomationLater`。
- 新增 `AutoLedgerProAccessPolicy.current`，提供统一判断：
  - `isAvailableWithoutPro(_:)`
  - `requiresActiveProInCurrentRelease(_:)`
  - `isPlannedProAutomation(_:)`
  - `remainsAvailableAfterProExpiration(_:)`
  - `manualFallbacks(for:)`
- 离线回归固定免费基础能力清单：手动记账、单张截图识别、手动酒店水单导入、酒店消费历史查看、基础订阅管理、基础月报、基础 Widget / Share Extension、基础导出备份、历史数据查看编辑删除和 `Support Developer` 赞助入口。
- 离线回归固定当前 P0 Pro 自动化 gate：本地邮箱水单扫描、批量候选导入、高级去重和 C1 专属收件箱。
- 离线回归固定 P1 / Later 能力当前不进入 P0 gate：高级搜索、订阅异常提醒、月结导出包和高级规则自动应用。
- 离线回归固定 Pro 到期后不锁历史数据：酒店消费历史、历史账单编辑、基础导出备份继续可用。

仍需后续 UI / 审核收口：

- 未实现 StoreKit 购买页、恢复购买按钮、订阅状态摘要页或本地 StoreKit configuration。
- 未新增 UI 付费墙、Pro 页面或订阅状态页面。
- 未把本地邮箱扫描、批量导入或去重接入实际 UI gate。
- 未修改 `Support Developer` 赞助内购。
- 未修改 SQLite / CloudKit schema、signing、entitlements、Xcode Cloud 脚本或 `MARKETING_VERSION`。

### 2.9 C1 专属收件箱与 Pro gate 工程落地状态（2026-06-29）

本轮将 `v1.6.3` 顺延的 C1 真实 Worker / 云候选 API / App 列表导入 / APNs 唤醒主链路接到 `v1.6.4` 的 Pro gate 基座。

命名原则：

- 规划文档可以继续使用 `C1` 表示阶段。
- 程序目录、包名、Worker 名称、代码变量、API 路径和数据库表不使用版本号、阶段号或 GOAL 号。
- 工程实现统一使用稳定业务域命名，例如 `hotel-folio-inbox`、`cloud-hotel-folio-candidates`、`cloudFolioInbox`。

已落地：

- App 侧新增 `ProEntitlementManager` 第一版，拉取 Pro subscription product、监听 StoreKit transaction updates、刷新当前 entitlement，并用 `AutoLedgerCapability.cloudFolioInbox` 判断云收件箱入口是否可用。
- 酒店消费 tab 右上角菜单新增云端酒店水单收件箱入口；未订阅 Pro 时展示自动化能力说明，手动 PDF 导入和历史酒店记录继续免费可用。
- App 侧新增 `HotelFolioInboxClient` 和 `HotelFolioInboxImportView`，支持保存专属收件箱 endpoint / token、展示 `folio+<token>@getautoledger.app`、刷新云候选、批量下载 PDF、复用本地 PDFKit 和 `HotelFolioParsePipeline` 生成 `HotelStayDraft(sourceType: .cloudWorker)`。
- App 侧保存专属收件箱配置后会请求通知权限、注册 APNs device token，并通过云候选 API 登记设备；通知点击后复用 deep link handoff，打开酒店消费候选导入页面。
- Worker 新增 `tools/worker/hotel-folio-inbox`，使用 Cloudflare Email Routing `email()` handler 接收发往 AutoLedger 专属地址的邮件。
- Worker 使用 `postal-mime` 解析 MIME，只提取 PDF 附件，计算附件 hash，写入 R2，并在 D1 创建 `cloud_hotel_folio_candidates`。
- Worker 使用 D1 `pro_inbox_tokens` 做服务端 Pro gate：token 必须 active，且 `pro_expires_at` 未过期。
- Worker 提供候选列表、PDF 下载、状态回写和设备登记 API；App 成功转换后可回写 `converted` 并删除云端 PDF。
- Worker 通过 Queue consumer 读取通知事件，按 `user_id` 查找已登记 APNs device token，发送只含隐私安全文案和 `autoledger://hotel-cloud-candidate/...` deep link 的推送。
- Worker 定时清理过期候选和对应 R2 PDF，默认短期暂存 7 天，可通过 `CANDIDATE_RETENTION_DAYS` 调整。
- 调试与回归路径保留云端候选下载、PDFKit 提取和草稿生成日志，方便定位云端导入失败点。

Cloudflare 部署状态：

- 已创建并部署 dev / staging / production 三套 Cloudflare 资源：R2 bucket、D1 database、Queue、Worker producer / consumer 和 daily cron。
- 已绑定 `https://folio.getautoledger.app` 到 production Worker，`https://staging-folio.getautoledger.app` 到 staging Worker。
- 已启用 `getautoledger.app` Email Routing，并创建 `folio@getautoledger.app -> autoledger-hotel-folio-inbox-production` 规则；catch-all 保持关闭并 drop 未匹配邮件。

仍属于部署 / 运营配置，不进入源码：

- APNs `APNS_KEY_ID`、`APNS_TEAM_ID`、`APNS_PRIVATE_KEY` 等密钥，通过 `wrangler secret put` 配置，不写入仓库。
- 订阅用户 token 生成、轮换、停用、Pro 到期续期同步和后台运营面板。
- App Store Connect Pro 商品、StoreKit 本地测试配置、购买页、恢复购买 UI 和审核截图。

明确非目标：

- Worker 不登录用户邮箱，不保存 QQ / IMAP / Gmail / Outlook 授权码。
- Worker 初版不识别 PDF，不调用酒店水单 LLM，不生成正式酒店消费记录，不生成普通账单。
- C1 不自动正式入账；所有云候选仍必须进入 App 待确认流程。
- 云端 PDF 不长期保存；App 成功下载 / 转换后优先删除，未处理候选按过期策略清理。

## 3. P1 范围：Pro v1 权益扩展

这些能力属于 `docs/autoledger-personal-pro-design.md` 推荐的 Pro v1 权益，但不建议全部塞进 `v1.6.4` P0。

### 3.1 高级搜索

支持按金额区间、日期、商户、酒店、邮箱、附件、备注、分类、来源组合搜索。

免费版保留基础搜索。

### 3.2 订阅异常提醒

检测订阅涨价、重复扣费、周期异常和未来 7 / 30 / 90 天续费压力。

免费版保留基础订阅记录和提醒。

### 3.3 月结导出包

生成当月 Excel / PDF 月结包，包含账单明细、分类统计、商户排行、水单附件索引。

免费版保留基础 CSV / JSON 导出和备份恢复。

### 3.4 高级规则自动应用

支持商户别名合并、关键词规则、分类规则、历史记录一键应用和低置信度集中复核。

免费版保留单条商户 / 分类修改。

## 4. Later：更高档位或未来路线

以下不进入 `v1.6.4`：

- 团队版 / Business。
- 会计协作。
- 云端保存用户邮箱授权码。
- Worker 登录用户邮箱自动扫描。
- 云端 AI 自动生成正式账单。
- 自动正式入账。
- 长期云端保存用户酒店水单 PDF。
- 把历史数据锁进 Pro。
- 把基础导出和备份恢复改成付费。

## 6. 测试与验收

自动回归建议：

- StoreKit configuration 覆盖月付、年付、恢复购买、取消、过期、宽限期和账单重试。
- `ProEntitlementManager` 离线单元测试覆盖 `isProActive` 和 `canUse(_:)`。
- Pro gate smoke 确认手动 PDF 导入、手动记账、历史查看、基础导出不被 gate。
- 邮箱扫描 gate 确认非 Pro 用户看到免费替代路径和 Pro 说明。
- Pro 用户可以进入邮箱扫描、批量候选导入和高级去重。
- C1 Worker smoke 覆盖专属地址解析、token hash、PDF 附件识别、候选 DTO、APNs 私密 payload 和队列 payload 校验。
- C1 App smoke 覆盖 endpoint / token 保存、设备 token 登记、候选刷新、PDF 下载、PDFKit 文本提取、`HotelStayDraft(sourceType: .cloudWorker)` 生成和状态回写。
- Pro 到期后历史酒店消费、原始 PDF、账单编辑和基础导出仍可使用。
- 本地化覆盖简体、繁体、英文、日文 Pro 文案。

## 7. 非目标

- 不回收既有免费能力。
- 不实现团队版或会计协作。
- 不保存用户邮箱授权码到云端。
- 不让 Worker 登录用户邮箱。
- 不自动正式入账。
- 不把酒店消费模块整体放到付费墙后。
- 不把基础导出、备份恢复或历史数据查看改成付费。
- 不把 `Support Developer` 赞助内购改造成 Pro 权益。
