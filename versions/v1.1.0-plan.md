# v1.1.0 版本计划

更新日期：2026-04-10
文档状态：Draft

## 1. 版本定位

- 版本号：v1.1.0
- 承接版本：v1.0.0
- 版本主题：订阅识别 + 扣费提醒 + 分类学习 + 用户反馈 + 去重增强
- 核心目标：在 v1.0.0 多渠道导入 + LLM 混合解析基础上，增加智能分析层——自动识别周期性订阅扣费、预测下次扣费并发送本地提醒、基于用户修正反馈优化分类准确率、增强去重策略减少误判/漏判；同时建立用户→开发者的反馈闭环，支持分级日志导出与邮件发送。

## 2. 承接输入

- 宏观 IDEA（必填）：IDEA-002（订阅识别与扣费提醒）、IDEA-003 部分（异常分析前置——周期检测）、IDEA-015（用户反馈：分级日志导出 + 邮件发送）
- 业务评审结论来源：README Roadmap v1.1.0
- 上一版本遗留项：
  - v1.0.0 TestFlight 外测反馈（待收集，视反馈内容可能追加 In Scope）
  - Foundation Models 国行不可用——纯规则路径已兜底，本版暂不追加云端推理
- 新增约束：
  - 本地通知需申请 `UNUserNotificationCenter` 权限（首次触发时弹窗）
  - 订阅检测算法完全离线，不依赖服务端
  - 分类学习数据存储在 App Group SQLite 中，不新增外部依赖
  - 去重策略变更需向后兼容已有账本数据

## 2.1 协作模型

- 协作模式：单人
- 前端负责人：项目发起者
- 后端负责人：无（核心逻辑在客户端）
- 测试统筹负责人：项目发起者
- AI 协作方式：同文档并行，AI 辅助方案设计、代码草稿与文档生成

## 3. In Scope / Out of Scope

### In Scope

**Phase 1 — 订阅识别引擎**
- 新增订阅入口：用户可上传"订阅续期邮件"截图，走 OCR → 订阅字段提取（商户、方案名、周期、金额、生效日）→ 生成订阅草稿/自动入库
- 新建 `SubscriptionDetector` 服务：扫描历史交易，按商户聚合，检测周期性模式（月付/年付/周付）
- 周期检测算法：基于时间间隔方差 + 金额稳定性判断是否为订阅
- 自动续期高置信判定：命中"自动续期/订阅将以 ¥X/月 续期/你的订阅续期"等强特征时，直接按订阅处理（高置信路径），不降级为普通交易
- 输出 `Subscription` 模型：商户名、周期类型（weekly/monthly/yearly）、金额、上次扣费日期、下次预测日期
- 已有订阅去重：同商户 + 同方案 + 同周期 + 同金额命中时合并更新，不重复新增订阅记录
- 订阅列表持久化到 SQLite `subscriptions` 表

**Phase 2 — 扣费提醒**
- 计算下次预测扣费日期，提前 1 天发送本地通知
- 设置页新增"订阅提醒"开关（默认开启）
- 首页新增"即将扣费"提示卡片（未来 7 天内有预测扣费时显示）
- `UNUserNotificationCenter` 权限申请（首次触发时）

**Phase 3 — 分类学习**
- 记录用户在 `TransactionEditorView` 中的分类修正操作（原分类 → 修正分类 + 商户名）
- 新建 `category_corrections` 表存储修正记录
- `TransactionCategory.infer()` 优先查询修正历史：同商户有修正记录时直接使用用户偏好分类
- 设置页新增"分类学习"入口，展示已学习的商户→分类映射，支持删除

**Phase 4 — 用户反馈闭环（App 端 + 协议 + 服务端自动 Issue）**

*A 层 — App 端（iOS 客户端）*
- 设置页新增"问题反馈"按钮，点击后组装日志 → 预览 → 调起 `MFMailComposeViewController` 发送邮件
- 日志分三级（用户自选）：
  - **L1 标准反馈（默认）**：App 版本 / 设备型号 / iOS 版本 / 最近 N 条脱敏操作日志（商户名/金额以占位符替代）/ 崩溃栈摘要
  - **L2 增强调试**：+ 结构化解析结果（OCR 片段、规则/LLM 命中路径）、`trace.log`、`redacted_ocr_context.txt`；敏感字段自动正则脱敏
  - **L3 完整诊断**：+ `full_ocr_text.txt`、原始截图缩略图；需用户二次确认，仅内部/高级测试者开启
- 发送前弹出预览页，展示即将发送的全部内容，用户确认后才发送
- 未配置邮件账户时降级：复制到剪切板 / 系统分享
- DebugView 入口重构：从设置页直达改为"多次点击当前版本号"后显示（类似开发者选项），普通用户不可见
- DebugView 内容升级（开发者模式 ≥ L3，无脱敏限制）：
  - 实时 SQLite 数据浏览（transactions / subscriptions / category_corrections / debug_events）
  - OCR 原始识别全文（不脱敏）
  - 规则/LLM 解析路径 + 置信度
  - 最近 N 次导入完整 trace（时间戳 + 耗时）
  - App Group 容器文件列表与大小
  - 当前内存/磁盘使用概况
  - 一键导出完整诊断包（等同 L3，不走邮件，直接 share sheet）

*B 层 — 邮件/附件协议（App 输出规范，参考 `feedback_log_email_bundle_templates.md`）*
- 邮件标题：`[AutoLedger][L{n}][iOS][{version}({build})][{issue_type}] 简短摘要`
- 邮件正文：自然语言描述 + `AUTOLEDGER_FEEDBACK_META` 机器可解析区块
- 附件 bundle：`AutoLedger_Feedback_{level}_{feedback_id}.zip`，内含 `issue_bundle.json` / `summary.txt` / `metadata.json`，L2/L3 逐级追加调试文件
- 问题类型枚举 14 种：`feedback` / `ocr_parse_wrong` / `merchant_parse_wrong` / ... / `crash` / `other`
- Feedback ID：`AL-{vendorID_short6}-{yyyyMMddHHmmss}-{seq}`（全局唯一，服务端以此幂等去重）

*C 层 — 服务端自动处理（DevOps，参考 `tools_feedback_README_template.md`）*
- 邮件路由：`support@darkrio326.top` → Cloudflare Email Routing → Gmail
- GitHub Actions 定时任务（每 15 分钟）：拉取 Gmail 未读反馈邮件（IMAP）
- `tools/feedback/email_to_issue.py`：解析邮件 + bundle → 二次脱敏 → GitHub REST API 创建 Issue（含 label）→ 标记邮件已读
- 当前不做：自动上传原始截图、自动 PR/merge

**Phase 5 — 去重增强 + 版本收口**
- 去重策略从「60s 窗口 + 同商户同金额」升级：增加 OCR 文本相似度比对（Jaccard 系数 > 0.8 视为同一来源）
- 新增去重日志：被跳过的交易记录到 `debug_events`，方便用户在调试页查看
- 回归基线更新，覆盖订阅检测 / 提醒 / 分类学习 / 用户反馈 / 去重场景
- v1.1.0 发布门禁判定

### Out of Scope（本版不做）

- 云端 AI / 远程推理
- iCloud 多设备同步
- Apple Watch 支持
- 订阅管理（取消订阅引导、费用优化建议）——属于 v1.2.0
- 异常消费检测与个性化建议——属于 v1.2.0
- 多笔账单拆分
- 预算设定与超支预警
- 自动删除已识别截图
- 新支付平台适配（云闪付、银联等）——属于 v1.2.0

## 4. 阶段拆分

| 阶段 | 目标 | 输出物 | 风险 |
|---|---|---|---|
| Phase 1 | 订阅识别引擎（含续期邮件截图导入） | `SubscriptionDetector`、`Subscription` 模型、`subscriptions` SQLite 表、续期邮件 OCR 提取规则 | 周期检测算法对不规则扣费（如按天计费 / 金额浮动）可能误判；需设定合理阈值 |
| Phase 2 | 扣费预醒 + 首页卡片 | 本地通知调度、设置页开关、首页"即将扣费"卡片 | 通知权限被拒后需优雅降级（仅展示卡片，不弹通知）；预测日期偏差需容错 |
| Phase 3 | 分类学习 | `category_corrections` 表、`infer()` 优先查修正历史、设置页管理入口 | 用户修正数据稀疏时学习效果有限；需避免单次误修正污染后续推断 |
| Phase 4 | 用户反馈闭环 | A 层：`FeedbackService`、L1/L2/L3 日志导出、预览页、DebugView 入口隐藏；B 层：邮件/bundle 协议规范；C 层：`tools/feedback/email_to_issue.py`、GitHub Actions workflow | A 层：`MFMailComposeViewController` 无邮件账户 fallback、附件超限；B 层：协议变更需双端同步；C 层：Gmail IMAP / Cloudflare / GitHub API 任一故障中断 |
| Phase 5 | 去重增强 + 版本收口 | OCR 文本相似度去重、去重日志、回归基线、发布门禁 | 相似度阈值过低导致漏去重 / 过高导致误合并；需在真实数据上调参 |

## 7. 验收与回滚

- **验收标准**：
  - 上传订阅续期邮件截图后，可清晰新增 1 条订阅（字段完整：商户/方案/周期/金额/生效日）
  - 命中"自动续期"强特征的邮件，必须走高置信订阅路径，不落入普通交易
  - 已有订阅再次识别时执行去重合并，不产生重复订阅
  - 在真实历史数据上，月付订阅（如 Apple Developer Program、iCloud 订阅）可被自动识别
  - 订阅扣费前 1 天收到本地通知（真机验证）
  - 在 TransactionEditorView 修改分类后，同商户后续交易自动使用修正分类
  - 相同截图重复导入被正确拦截，去重日志可在调试页查看
  - 设置页点击"问题反馈"可导出 L1 标准脱敏日志并预览，确认后发送邮件
  - 用户可逐级勾选 L2/L3，预览页如实展示附加内容
  - 邮件标题、正文、附件 bundle 结构符合 `feedback_log_email_bundle_templates.md` 协议规范
  - 附件 zip 内含 `issue_bundle.json` + `summary.txt` + `metadata.json`，L2/L3 逐级追加文件
  - 无邮件账户时降级为剪切板复制或系统分享
  - DebugView 仅在多次点击版本号后显示，普通用户不可见
  - DebugView 内容 ≥ L3：可浏览 SQLite 表数据、OCR 原始全文、解析路径、导入 trace、容器文件、内存磁盘概况；可一键导出完整诊断包
  - Feedback ID 全局唯一（含设备指纹短哈希），服务端以 `feedback_id` 幂等去重，相同 ID 不重复建 Issue
  - 发送 L1 测试邮件到 `support@darkrio326.top` 后，15 分钟内自动在 GitHub 创建 Issue（含 `feedback` + `L1` label）
  - Issue 正文包含 `issue_bundle.json` 中的结构化故障数据，敏感字段已二次脱敏
  - 邮件处理后被标记已读，不重复创建 Issue
  - v1.0.0 全部回归项无功能回退

- **回归范围**：
  - v1.0.0 回归基线全项
  - v1.1.0 新增场景：订阅识别准确性 / 提醒触发 / 分类学习生效 / 用户反馈日志导出 / 邮件→Issue 自动化 / 去重增强

- **回滚策略**：
  - 订阅识别 / 分类学习为独立模块，可单独回退不影响核心记账链路
  - 新增 SQLite 表采用 `CREATE TABLE IF NOT EXISTS`，回退版本不会因表存在而崩溃
  - 通知权限回退不影响 App 功能，仅丧失提醒能力
  - FeedbackService 为独立模块，删除后设置页隐藏入口即可，不影响核心功能
  - 服务端 `tools/feedback/` 与 GitHub Actions 为独立基础设施，停用不影响 App 功能（用户仍可正常发送邮件，仅失去自动建 Issue 能力）
