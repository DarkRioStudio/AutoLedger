# v1.3.2 版本设计与落地计划

更新日期：2026-04-27
文档状态：Implemented（工程低风险落地版）
关联设计：`docs/LedgerTextInterpreter.md`

## 1. 版本定位

- 版本号：v1.3.2
- 承接版本：v1.3.1
- 当前 App Store 线上定位：v1.2.0
- 版本主题：统一“文本转账单”解析入口
- 核心目标：把图片 OCR、剪切板、分享、订阅邮件、语音转文本、Siri 文本和账本页一句话输入之后的结构化流程，收敛到统一的 `LedgerTextInterpreter`，再由账本入库层负责保存、去重、调试记录、Widget 刷新和自动备份。

## 2. 设计来源与工程取舍

`docs/LedgerTextInterpreter.md` 给出的目标架构是：

```text
raw text + source context
  -> LedgerTextInterpreter
  -> TransactionDraft
  -> LedgerStore.createTransaction
```

v1.3.2 的工程落地保持这个方向，但做了低风险取舍：

- 本版先新增解释器编排层，不重写现有解析器。
- OCR/支付截图继续复用 `ReceiptParser`、`SmartReceiptParser`、`OCRTextCleaner`、`SubscriptionDetector`。
- 语音和一句话继续复用 `VoiceLedgerParser`，但通过 `LedgerTextInterpreter` 的 `.voice` 分支进入统一解释层。
- 当前输出不是全新的 `TransactionDraft` 类型，而是兼容现有链路的 `LedgerTextInterpretation`：
  - `.voice(VoiceLedgerParseResult, normalizedText, source)`
  - `.subscription(Subscription, normalizedText, source)`
  - `.transaction(SmartReceiptParser.SmartResult, normalizedText, source, multiReceiptDetected)`
  - `.multiItemTotalMissing(SmartReceiptParser.SmartResult, normalizedText, source)`
  - `.parseFailed(normalizedText, source)`
- `TransactionDraft`、`LedgerSourceContext`、平台无关 `BillParserCore` 和 Worker API 留作后续架构演进，不在本轮引入新模型和新服务边界。

## 3. 职责边界

`LedgerTextInterpreter` 负责：

- 原始文本标准化。
- 来源推断或尊重调用方传入的 `preferredSource`。
- 语音/一句话短句分流到 `VoiceLedgerParser`。
- 订阅文本检测。
- OCR 文本清洗。
- 多账单检测。
- `SmartReceiptParser` 的 LLM/规则解析编排。
- 多商品小票“未可靠命中总金额”的拒绝结果输出。
- 返回结构化解释结果，不直接写库。

`LedgerTextInterpreter` 不负责：

- SQLite 写入。
- UI 状态。
- 商户别名学习。
- 分类学习持久化。
- 重复账单判断。
- Debug record 持久化。
- Widget 刷新。
- iCloud 自动备份。

这些仍由 `LedgerStore` 的入库链路负责。

## 4. 当前输入输出设计

### 输入：`LedgerTextInterpretationInput`

- `text`：原始文本。
- `preferredSource`：调用方已知来源，例如 `.voice`、`.wechat`、`.alipay`。
- `fallbackMerchant`：截图/来源标题等兜底商户名。
- `ocrMinConfidence`：OCR 结果最低置信度，用于智能解析判定。
- `categoryCorrections`：用户分类纠正规则，当前主要供语音/一句话短句解析使用。

### 输出：`LedgerTextInterpretation`

- `voice`：语音/一句话文本解析结果，保留 `VoiceLedgerParseResult` 的 high / needsReview / failed 置信度。
- `subscription`：订阅文本结果，由 `LedgerStore.upsertSubscription` 保存。
- `transaction`：普通账单结果，由 `LedgerStore.createTransaction(from:)` 保存。
- `multiItemTotalMissing`：多商品小票未识别可靠总金额，提示用户重拍或补齐合计区域。
- `parseFailed`：未解析出可入账字段，记录调试信息。

## 6. 本版 In Scope

- 新增 `LedgerTextInterpreter`。
- `LedgerStore.importRecognizedText` 改为调用统一解释器。
- 新增 `LedgerStore.interpretVoiceText`，供首页语音快捷记账和账本页一句话记账实时生成草稿。
- `VoiceLedgerIntent` 改为通过统一解释器的 `.voice` 分支解析 Siri 文本。
- 新增 `LedgerStore.createTransaction(from:)` 作为 App 内结构化账单入库入口。
- 保留既有 `persistReceipt` 作为内部兼容实现，避免一次性大改去重、调试和备份链路。
- 离线回归覆盖：
  - OCR 样例解析。
  - 语音一句话解析。
  - 多商品小票不可靠总金额拒绝。
  - 商户别名历史账单回刷。
  - 高置信账单编辑后自动学习商户别名。
  - 备份恢复继承。

## 7. 本版 Out of Scope

- 不重写 OCR 或语音识别。
- 不把 `VoiceLedgerParser` 与小票解析器合并为一个大解析器。
- 不新增 `TransactionDraft` 公共模型。
- 不抽离平台无关 `BillParserCore`。
- 不新增 Worker API 或云端解析。
- 不做多账单拆分。
- 不做收入、转账、报销入账。
- 不改变 SQLite schema。
- 不改变 Siri 入口的轻量直写保存方式，只统一其文本解析入口。

## 9. 当前落地状态

- `LedgerTextInterpreter` 已新增为 App 层解释器编排服务。
- OCR 图片、剪切板、相册、拍照、订阅邮件等调用 `importRecognizedText` 的入口，已通过统一解释器生成结构化结果。
- 首页语音快捷记账和账本页“一句话记账”已通过 `LedgerStore.interpretVoiceText` 接入统一解释器的 `.voice` 分支。
- Siri `VoiceLedgerIntent` 已接入统一解释器的 `.voice` 分支，保存仍保持 AppIntent 内轻量直写 SQLite。
- `LedgerStore.importRecognizedText` 已从“解析编排 + 入库”收敛为“调用解释器 + 根据结果入库/失败提示”。
- App 内 OCR 结构化账单与语音/一句话结构化账单均通过 `createTransaction(from:)` 进入原有入库链路。
- 商户别名更新会回刷当前账本中完全匹配原商户名的历史账单。
- 用户编辑高置信自动生成账单并将长商户名改为短别名时，会自动学习商户别名规则。

## 12. 风险与回滚

- 风险：解释器编排改变可能影响 `lastImportSummary` 或调试记录文案顺序。
- 风险：语音/一句话实时解析变为异步解释器调用，需要真机确认连续输入、长按松手识别和自动保存手感。
- 风险：Siri 文本解析已统一，但保存仍是 AppIntent 内轻量直写，后续若要完全统一入库，需要抽出不依赖 UI 生命周期的保存适配器。
- 回滚方式：
  - 将 `LedgerStore.importRecognizedText` 恢复为内联解析逻辑。
  - 让语音 UI 和 `VoiceLedgerIntent` 恢复直接调用 `VoiceLedgerParser`。
  - 保留 `LedgerTextInterpreter.swift` 不引用即可，不影响数据结构。

## 13. 后续演进

- 引入稳定的 `TransactionDraft` 模型，统一 OCR 与语音输出形态。
- 引入 `LedgerSourceContext`，替代分散的 `preferredSource`、`fallbackMerchant`、`ocrMinConfidence` 参数。
- 将可测试的纯解析规则逐步抽到平台无关 `BillParserCore`。
- 建立 Golden Cases 文件集，覆盖多入口文本、期望字段、置信度与 warning。
- 评估 Worker API，仅用于批量测试、规则调优和 Golden Case 回归，不作为当前端侧 MVP 的必要依赖。
