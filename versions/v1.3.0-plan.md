# v1.3.0 版本计划

更新日期：2026-04-26
文档状态：Implemented（代码门禁 PASS；真机 iCloud 验证待执行）

## 1. 版本定位

- 版本号：v1.3.0
- 承接版本：v1.2.0
- 版本主题：数据备份 + 手动迁移 + iCloud 轻量恢复
- 核心目标：在 v1.2.0 已完成本地 SQLite 持久化、软删除、订阅增强与用户自定义配置的基础上，补齐"数据可带走、可恢复、不怕卸载"能力。通过统一 `BackupBundle` 实现手动 JSON 导出/导入、iCloud Drive 单文件自动备份、重装/换机时提示恢复，并为后续真正多设备同步预留 schema 与冲突处理基础。

## 2. 承接输入

- 宏观 IDEA：
  - 根目录 `autoledger_icloud_backup_design.md`：iCloud 单文件备份、`BackupBundle`、手动导入导出、重装提示恢复、轻量跨设备恢复。
  - v1.0.0 / v1.1.0 / v1.2.0 多次 Out of Scope：iCloud 或多设备同步。
- 业务评审结论来源：
  - `autoledger_icloud_backup_design.md`
  - `versions/v1.2.0-plan.md`
  - `versions/v1.2.0-RELEASE(draft).md`
  - `process/iteration-log.md`
- 上一版本遗留项：
  - v1.2.0 发布门禁仍待真机验证；若出现阻断，v1.3.0 启动前需先追加 v1.2.0 修复迭代。
  - `customCategories`、`customSources`、`merchantAliases` 仍在 `UserDefaults`。
  - 订阅年付价与备注仍在 `UserDefaults` 侧表，不在 `subscriptions` 表结构内。
  - 软删除已落入 SQLite `deleted_at`，备份导出需要保留删除状态。
- 新增约束：
  - 本版不做 CloudKit 结构化实时同步，不引入账号体系。
  - 自动备份仅写 iCloud Drive / ubiquity container 中的单一 JSON 文件，不把 iCloud 文件当主数据库。
  - 任意自动恢复都必须经过用户确认，不静默覆盖本地数据。
  - 备份包不得包含原始支付截图、完整 OCR 原文、L3 诊断包、Gemma 模型文件或其他高敏调试材料。
  - 导入必须可回滚：正式覆盖前先生成本地临时备份，失败时恢复原数据。

## 3. In Scope / Out of Scope

### In Scope

**Phase 0 — 备份 schema 与数据映射设计**
- 定义 `BackupBundle` v1，字段覆盖：
  - `transactions`：含 `deletedAt`，支持最近删除跨会话恢复。
  - `subscriptions`：订阅基础表数据。
  - `categoryCorrections`：分类学习记录。
  - `customCategories` / `customSources`：当前 UserDefaults 自定义标签。
  - `merchantAliases`：商户别名映射。
  - `subscriptionMetadata`：订阅年付价、备注等 UserDefaults 侧表。
  - `appSettings`：仅导出低风险设置，例如订阅提醒开关、异常检测阈值、LLM 增强开关；不导出调试日志、反馈包、模型性能样本。
- 建立 schema 版本、导出 App 版本、设备摘要、数据摘要、导入校验错误模型。
- 明确 `schemaVersion == 1` 的兼容策略：未知字段忽略、缺失可选字段用默认值、必需字段缺失则拒绝导入。

**Phase 1 — 手动 JSON 导出**
- 新增 `BackupService` / `BackupBundleBuilder`：
  - 从 SQLite 和 UserDefaults 汇总当前可备份数据。
  - JSON 使用稳定缩进格式，便于人工检查和问题反馈。
  - 文件名：`AutoLedger_backup_YYYY-MM-DD_HHmmss.json`。
- 设置页新增"数据管理"入口：
  - 导出 JSON 备份。
  - 显示备份摘要：账单数、订阅数、自定义分类/来源数、商户别名数、导出时间。
- 调起系统 share sheet，让用户保存到 Files / iCloud Drive / AirDrop。
- 离线回归新增导出断言，覆盖 SQLite + UserDefaults 混合数据。

**Phase 2 — 手动导入与覆盖恢复**
- 新增 JSON 文件选择与导入预览：
  - 校验 `schemaVersion`、必需字段、ID 唯一性、引用完整性。
  - 展示备份摘要和风险提示。
- MVP 恢复策略采用"覆盖恢复"：
  - 导入前生成本地安全备份。
  - 清空或替换可恢复数据。
  - 按依赖顺序恢复：自定义分类/来源 → 商户别名 → 分类学习 → 订阅 → 交易 → 订阅侧表/设置。
- 导入失败时回滚到导入前状态，并展示错误原因。
- 离线回归覆盖：导出 → 清空 → 导入 → 数据一致性校验。

**Phase 3 — iCloud 单文件自动备份**
- 为主 App 配置 iCloud Documents capability / entitlements。
- iCloud 文件路径：
  - `Documents/AutoLedgerBackup.json`
  - 写入时先生成 `AutoLedgerBackup.tmp`，再原子替换。
- 设置页"数据管理"支持：
  - iCloud 自动备份开关。
  - 立即备份。
  - 上次备份时间、备份摘要、最近错误。
- 自动触发时机：
  - 新增/修改/删除/恢复/彻底删除账单后。
  - 自定义分类、来源、商户别名变更后。
  - 订阅编辑、删除、扫描更新后。
  - 分类学习记录变更后。
  - App 进入后台时。
  - 每日首次启动后。
- 写入节流：数据变化后 debounce 10-30 秒合并写入，避免高频覆盖。

**Phase 4 — 重装/换机恢复提示 + 冲突防护**
- 首次启动检测：
  - 本地核心数据为空。
  - iCloud 存在 `AutoLedgerBackup.json`。
  - 弹窗展示摘要，用户选择"立即恢复"或"暂不恢复"。
- 本地不为空时：
  - 不自动覆盖。
  - 若 iCloud 备份 `exportedAt` 晚于本地 `lastBackupAt`，仅在数据管理页提示"发现较新的 iCloud 备份"。
- 冲突 MVP 规则：
  - 不做双向合并。
  - 覆盖恢复需用户二次确认。
  - 保留 `bundleId`、`exportedAt`、`lastBackupBundleId`，为 v1.4+ 合并策略预留。

**Phase 5 — 回归基线 + 发布门禁**
- 新增 `versions/v1.3.0-regression-baseline.md`。
- 新增 `versions/v1.3.0-RELEASE(draft).md`。
- 回归覆盖：
  - v1.2.0 主路径继承。
  - 手动导出/导入。
  - UserDefaults 侧表恢复。
  - 软删除恢复。
  - iCloud 开关、立即备份、后台自动备份。
  - 重装/空库恢复提示。
  - 导入失败回滚。

### Out of Scope（本版不做）

- CloudKit 结构化同步。
- 多设备实时双向合并。
- 多历史快照与版本浏览。
- 端到端加密或用户自定义密码保护。
- 备份原始支付截图、OCR 全文、DebugView 诊断包、反馈邮件附件、Gemma 模型文件。
- 云端账号体系、服务端备份、Web 管理台。
- 自动静默覆盖本地数据。
- 自动解决多设备同时写入冲突。

## 4. 阶段拆分

| 阶段 | 目标 | 输出物 | 风险 |
|---|---|---|---|
| Phase 0 | 备份 schema 与数据映射 | `BackupBundle`、`BackupTransaction`、`BackupSubscription`、导入校验模型、字段映射文档 | 当前数据分散在 SQLite 与 UserDefaults，容易漏字段 |
| Phase 1 | 手动 JSON 导出 | `BackupService`、导出 share sheet、数据管理入口、导出离线回归 | JSON 体积随账单增长；需避免导出敏感调试材料 |
| Phase 2 | 手动导入与覆盖恢复 | 文件选择、导入预览、覆盖恢复、失败回滚、导入离线回归 | 覆盖导入若中途失败可能破坏本地数据，必须先做安全备份 |
| Phase 3 | iCloud 自动备份 | iCloud entitlement、自动备份调度、状态 UI、立即备份 | iCloud capability / 容器配置需真机和 Apple ID 验证 |
| Phase 4 | 重装恢复与冲突防护 | 空库启动恢复提示、较新备份提示、冲突处理文案 | 多设备同时写仍可能覆盖，MVP 需明确提示而非自动合并 |
| Phase 5 | 回归与发布收口 | v1.3.0 回归基线、RELEASE 草稿、CHANGELOG、迭代日志 | iCloud 真机验证链路较长，可能阻断发布判定 |

## 7. 验收与回滚

- **验收标准**：
  - 设置页出现"数据管理"入口。
  - 手动导出生成合法 `BackupBundle` JSON，摘要与本地数据一致。
  - 导出文件不包含原始截图、OCR 全文、Debug 诊断包、Gemma 模型或模型性能样本。
  - 手动导入前展示备份时间、App 版本、账单数、订阅数、自定义标签数、商户别名数。
  - 覆盖恢复前有二次确认，并先生成本地安全备份。
  - 覆盖恢复后交易、最近删除、订阅、自定义分类/来源、商户别名、分类学习、订阅年付价与备注均恢复。
  - 非法 JSON、schema 不兼容、引用损坏时拒绝导入，不改变本地数据。
  - 开启 iCloud 自动备份后，本地数据变更会在 debounce 后写入 `AutoLedgerBackup.json`。
  - App 进入后台或每日首次启动会尝试补备份。
  - 删除 App / 空库启动后，检测到 iCloud 备份时提示恢复，不静默导入。
  - 本地已有数据时，检测到较新 iCloud 备份只提示，不自动覆盖。
  - v1.2.0 主路径回归无功能回退。

- **回归范围**：
  - v1.2.0 回归基线全项。
  - v1.3.0 新增场景：手动导出、手动导入、导入失败回滚、UserDefaults 侧表恢复、软删除恢复、iCloud 立即备份、自动备份、空库恢复提示、非空库冲突提示。

- **回滚策略**：
  - 手动导出为只读能力，回滚时隐藏数据管理入口即可。
  - 手动导入必须保留导入前安全备份；若导入后发现问题，使用安全备份恢复本地状态。
  - iCloud 自动备份可通过远端配置或本地开关禁用；已生成的 `AutoLedgerBackup.json` 保留，不影响本地 SQLite 主数据库。
  - 若 iCloud entitlement 导致构建或审核风险，v1.3.0 可降级为"手动 JSON 导入导出版"，将自动 iCloud 备份延期到 v1.3.1。
