# v1.5.1 版本计划

更新日期：2026-06-09
文档状态：开发中
内部开发线：v1.5.1
App Store 对外版本：v1.4.0
承接版本：`v1.5.0` 开发基线
关联文档：`versions/v1.5.0-plan.md`、`versions/v1.5.0-regression-baseline.md`、`versions/v1.5.0-review-notes.md`、`docs/minimum-platform-baseline-reduction-plan.md`

## 1. 版本定位

`v1.5.1` 不再只是 `v1.5.0` 的补丁号，而是当前开发线正式承接版本。

本轮决策调整如下：

1. `v1.5.0` 已完成 iPhone / iPad / Apple Watch / Mac Catalyst 的主线能力铺设，以及截图、回归资料、Review Notes 等发布前基础准备。
2. `v1.5.0` 不单独做最终 smoke、Xcode Cloud 收口和提审动作；这些门禁延后到 `v1.5.1` 全部内容完成之后统一执行。
3. `v1.5.1` 承接两类任务：
   - `v1.5.0` 遗留的最终收口、smoke、Xcode Cloud 和 App Store Connect 动作
   - 全平台内容补齐与最低系统需求优化
4. 多账本继续顺延，不进入 `v1.5.1` 当前实现范围。

因此，`v1.5.1` 的真实角色是：

- `v1.5.0` 主线成果的整合版
- 全平台第一阶段闭环版
- 最低系统需求下调的实施版
- App Store `1.4.0` 的最终候选开发线

## 2. 当前承接内容

### 2.1 从 `v1.5.0` 承接的遗留收口项

以下事项不再在 `v1.5.0` 单独收口，而是在 `v1.5.1` 完成后统一执行：

1. 全量 smoke
2. 最终真机回归
3. Xcode Cloud validation / archive / TestFlight 验证
4. App Store Connect 最终 Review Notes、截图和提审动作
5. Watch 后台刷新与复杂场景复测
6. IAP 真机 / 沙盒购买复测

### 2.2 从 `v1.5.0` 继承的已完成基线

`v1.5.1` 不需要重新定义这些方向，而是在其上继续落地：

- iPhone / iPad / Apple Watch / Mac Catalyst 主线
- iCloud 同步基础链路
- iPad 工作台
- Mac Catalyst 生产力工作流
- iPhone / Watch / iPad / Mac 截图导出基线
- tvOS / visionOS 的 target、设计稿和实现评估

## 3. `v1.5.1` 目标矩阵

### 3.1 平台与最低系统目标

| 平台 / Target | `v1.5.1` 目标最低版本 | 说明 |
|---|---:|---|
| Main App / iPhone / iPad | `iOS 17.0` 优先 | 若共享 Core 当前仍强依赖 `iOS 18` API，则先拆出 `CoreBase`，保证基础记账链路可在 `iOS 17` 编译 |
| Mac Catalyst | `macOS 14` 对应线 | 跟随 `iOS 17` 主线，不另起一套高版本基线 |
| Watch App / Watch Widget | `watchOS 10.0` | 保留今日支出、最近支出、Widget 与表盘能力 |
| tvOS App | `tvOS 17.0` | 实现第一版只读账本看板 |
| visionOS App | `visionOS 1.0` | 实现第一版空间展示版 |
| ControlWidgetExtension | `iOS 18.0` | 允许单独保留高版本，不反向拖住主 App |
| Foundation Models / Apple Intelligence | `iOS 26+` optional enhancement | 只能作为增强层存在，不得污染主 App、`CoreBase`、ViewModel 和通用数据模型 |

### 3.2 结构原则

- 不允许为了通过低系统编译，把主流程、主页面、核心数据类型整体标记为 `@available(iOS 26.0, *)`
- 低系统主链路必须通过 `CoreBase / Adapter / Extension / FeatureGate` 分层实现
- 如果 `AutoLedgerCore` 当前仍被 `ClipboardImportIntent` 这类高层能力抬高版本，则应优先拆分：
  - `CoreBase`：Foundation / SQLite / 通用模型 / 通用服务
  - `Intent Adapter`：`AppIntents`、控制组件等高层入口
  - `FeatureGate`：Apple Foundation Models、Apple Intelligence 等增强能力

## 4. `v1.5.1` 核心目标

### 4.1 当前主线平台稳定收口

- iPhone / iPad / Apple Watch / Mac Catalyst 继续消化已知交互、同步、后台刷新和截图问题
- 把 `v1.5.0` 的回归资料转为 `v1.5.1` 最终提审基线
- 将最终 smoke、Xcode Cloud、ASC 提交动作统一后置到本版本末尾

### 4.2 tvOS 第一版落代码

按已有设计与评估文档，完成 tvOS 只读账本看板第一版：

- 总览
- 分类占比
- 最近消费趋势
- 年度 / 月度摘要
- 家庭大屏只读模式

边界：

- 只读
- 单一正式账本
- 不做导入 / 编辑 / 清洗 / 多账本切换

### 4.3 visionOS 第一版落代码

按已有设计与评估文档，完成 visionOS 第一版展示：

- 月度支出空间看板
- 分类支出卡片漂浮展示
- 年度消费时间线墙
- 最近账单悬浮列表

边界：

- 首版以 `WindowGroup + SwiftUI` 为主
- 不把 immersive space 作为首版硬门槛
- 只读、单一正式账本

### 4.4 最低系统需求优化实施

按 `docs/minimum-platform-baseline-reduction-plan.md` 执行：

1. 梳理 `AutoLedgerCore` 的平台依赖
2. 必要时拆出 `CoreBase`
3. 下调主 App / Watch / tvOS / visionOS 的 deployment target
4. 保留 `ControlWidgetExtension` 的 `iOS 18`
5. 保留 Apple Foundation Models 的 `iOS 26+` 增强路径

### 4.5 全平台发布资产与 smoke 延后收口

本轮版本结束前，再统一处理：

- iPhone / iPad / Watch / Mac / tvOS / visionOS 截图资产
- 全平台 smoke
- `iOS 17` / `iOS 18` / `iOS 26` 构建验证
- Xcode Cloud validation build
- App Store Connect 最终提交资料

### 4.6 Shortcuts 结构化账单导入补充

为当前单账本主线补一条自动化入口：

- Shortcuts / 剪贴板可传入结构化账单 JSON
- App Intent 解析金额、商户、分类、日期、备注、币种和置信度
- 高置信度自动保存
- 中置信度打开确认页复核
- 低置信度或缺少关键字段返回错误，不写入账本

边界：

- 只支持单笔账单 JSON，不做批量 JSON 数组
- 不保存原始 JSON、截图、小票图片或 OCR 全文
- 不修改正式账本 SQLite schema
- `currency` 暂存入备注，不新增币种字段

## 5. 非目标

`v1.5.1` 暂不包含：

- 多账本正式模型
- `Ledger` / `ledger_id` 迁移
- 账本切换、账本归档、默认账本管理 UI
- 预算、投资、报销、协作账本
- 服务端账户系统
- 用高版本 availability 包住整个主链路来“假装支持低系统”

多账本继续顺延到 `v1.6.0+` 再重启评审。

## 6. 推荐实施顺序

### Phase A：版本与平台边界收口

- `v1.5.0` 标记为实现基线
- `v1.5.1` 接管当前开发线
- 把多账本从当前执行队列中继续排除

### Phase B：最低系统下调准备

- 审核 `AutoLedgerCore`
- 判断是否必须拆 `CoreBase`
- 列出每个 target 的 deployment target 修改清单
- 标出 `Apple Foundation Models` / `ControlWidget` 的 feature gate 边界

### Phase C：tvOS 第一版代码

- 先做总览页骨架
- 再补齐分类 / 趋势 / 摘要
- 接稳定只读数据入口

### Phase D：visionOS 第一版代码

- 先做 `WindowGroup` 骨架
- 再补四区展示
- 最后评估是否需要空间增强层

### Phase E：全平台截图与最终 smoke

- 补齐 tvOS / visionOS 截图资产
- 统一跑全平台 smoke
- 执行 Xcode Cloud / ASC 最终收口

## 8. 版本门禁

`v1.5.1` 结束时，最终输出必须能回答以下问题：

1. 每个 target 的最终 deployment target 是多少
2. 为降版本改了哪些文件
3. `iOS 17` / `iOS 18` / `iOS 26` 的模拟器或 generic build 结果如何
4. `ControlWidgetExtension` 是否仍稳定留在 `iOS 18`
5. Apple Foundation Models / SmartReceiptParser 的 `iOS 26+` 增强能力是否仍完整保留
6. tvOS / visionOS 是否已有第一版可构建、可演示的产品代码
7. `v1.5.0` 遗留 smoke 是否已全部被 `v1.5.1` 吸收并完成

## 9. 当前结论

`v1.5.1` 现在应被视为：

- 当前开发主线
- `v1.5.0` 遗留内容的统一收口版本
- 全平台内容补齐版本
- 最低系统需求优化版本

多账本继续 delay，不作为本轮 blocker。
