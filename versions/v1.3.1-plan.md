# v1.3.1 版本计划

更新日期：2026-04-26
文档状态：Draft（承接语音 / Siri 设计草案；尚未进入代码实现）

## 1. 版本定位

- 版本号：v1.3.1
- 承接版本：v1.3.0
- 版本主题：语音记账 MVP + Siri 快捷入口
- 核心目标：在截图记账、剪切板记账、JSON/iCloud 备份恢复之后，补齐"没有支付截图时的一句话记账"能力。v1.3.1 只处理"一句话 → 一笔支出"，Siri 场景高置信度直接保存，App 内场景承载确认、修改和补全。

---

## 2. 承接输入

- 根目录 `autoledger_voice_siri_design.md`：
  - 语音记账不是聊天机器人，也不替代截图记账。
  - 当前版本只支持支出，不支持收入、转账、报销。
  - 规则优先，AI 兜底只作为后续增强，不能拖慢 Siri 主链路。
  - Siri 场景必须快速明确：高置信度直接保存，中低置信度直接失败并提示重试。
  - App 内场景允许中低置信度进入确认页。
- 现有工程基础：
  - 已有 `QuickLedgerIntent` 与 `AutoLedgerShortcuts`，可复用 AppIntent、后台 SQLite 写入、成功通知与 Widget 刷新模式。
  - `SQLiteTransactionStore` 已支持交易保存、去重查询、调试事件记录、备份导出与覆盖恢复。
  - `Transaction` 已支持内置或自定义来源字符串；v1.3.1 可新增内置 `.voice` 来源，也可保留字符串兼容。
  - `TransactionCategory.infer(from:corrections:)` 已有基础关键词分类，可作为语音规则分类的第一版兜底。
  - v1.3.0 `BackupBundle` 会把语音生成的交易作为普通交易备份，不需要单独引入备份 schema 破坏性变更。

## 2.1 设计约束

- 不做开放式语音聊天或财务问答。
- 不做自研录音转写链路；MVP 依赖 Siri/AppIntents 参数和系统键盘听写能力。
- 不引入云端语音识别或云端 LLM。
- Siri 主链路不等待 Gemma、本地大模型或多轮确认。
- 不自动保存不明确、多个金额、收入、转账、报销语句。
- 所有语音入账必须可被备份、可在账本中识别来源，并可进入现有删除/恢复/导出流程。

## 3. In Scope / Out of Scope

### In Scope

**Phase 0 — 语音数据模型与来源对齐**
- 新增或明确 `ReceiptSource.voice`：
  - title：`语音`
  - shortTitle：`语音`
  - 用于交易来源筛选、账本展示、手动编辑来源列表。
- 新增语音入账 note 约定：
  - 成功保存：`语音记账`
  - 可选保留原始文本摘要：`语音记账：午饭 28 元`
- 调试事件新增语音入口标识：
  - `ImageSource.voiceIntent` 或等价来源标签，用于区分截图快捷指令与语音快捷指令。
- 明确备份兼容：
  - `source = voice` 的交易跟随 `BackupBundle.transactions` 导出/恢复。
  - 不把完整语音音频、系统转写音频或任何录音文件写入备份。

**Phase 1 — `VoiceLedgerParser` 规则解析**
- 新增 `VoiceLedgerParser` / `VoiceLedgerParseResult`：
  - 输入：短文本。
  - 输出：金额、商户/描述、分类、发生时间、置信度、失败原因、原始文本。
- 支持金额：
  - `28`、`28元`、`28 块`、`36.5`、`36.50`、`¥18`。
  - 必须有且只有一个明确金额。
  - 金额必须大于 0。
- 支持描述：
  - 去掉金额和单位后的剩余文本作为 merchant。
  - 清理"花了"、"记一笔"、"帮我记"等轻噪声。
  - 描述为空或过短时降为需要复核。
- 支持日期：
  - 默认当前时间。
  - MVP 支持"今天"、"昨天"、"前天"、"刚刚"。
  - "中午"、"晚上"仅作为文本提示，不强行推断精确小时。
- 支持分类：
  - 先走现有 `TransactionCategory.infer` 与用户分类修正规则。
  - 补充语音常见词：停车费、打车、地铁、公交、咖啡、奶茶、水果、便利店、早餐、午饭、晚饭。
  - 无法判断时使用 `.other`，但不因此阻断高置信度。
- 明确失败原因：
  - 无金额。
  - 多个金额。
  - 收入/工资/报销/转账/还款/收款等不支持语义。
  - 文本过长或结构冲突。

**Phase 2 — `VoiceLedgerIntent` Siri 入口**
- 新增 AppIntent：
  - 名称：`VoiceLedgerIntent`
  - 参数：`content: String`
  - 快捷短语示例：
    - `用 AutoLedger 语音记账`
    - `用 AutoLedger 记一笔午饭 28 元`
    - `AutoLedger 记一笔`
- 行为：
  - 调用 `VoiceLedgerParser`。
  - 仅 `.high` 置信度直接写入 SQLite。
  - 写入后刷新 Widget，并发送 `NotificationService.didSaveTransactionFromIntent`。
  - 中低置信度不保存，只返回明确失败文案。
- 去重：
  - 复用现有同商户、同金额、60 秒窗口的去重规则。
  - 语音原始文本相同且短时间重复时返回重复提示。

**Phase 3 — App 内语音/文本确认入口**
- 在记账页新增轻量入口：
  - "语音记账"按钮或输入卡片。
  - MVP 优先使用文本输入框 + 系统键盘听写按钮，不新增录音权限。
- 新增确认 Sheet：
  - 金额、名称、分类、时间、来源。
  - 用户可修改字段后保存。
  - 中置信度默认进入确认页。
  - 低置信度若无金额，要求补充金额后才能保存。
- 保存后：
  - 调用现有 `LedgerStore` 保存交易路径，保证内存列表、SQLite、备份调度、月报刷新一致。

**Phase 4 — 本地化、调试与回归**
- 新增本地化 key：
  - `voice_ledger_title`
  - `voice_ledger_example`
  - `voice_ledger_success`
  - `voice_ledger_unclear`
  - `voice_ledger_no_amount`
  - `voice_ledger_multiple_amounts`
  - `voice_ledger_income_not_supported`
  - `voice_ledger_review_required`
  - `voice_ledger_duplicate`
- DebugView 能看到语音入账调试记录：
  - 原始文本。
  - 解析结果。
  - 置信度/失败原因。
  - 是否保存成功或被判重复。
- 离线回归新增语音解析与持久化断言。

**Phase 5 — v1.3.1 回归基线与发布收口**
- 新增 `versions/v1.3.1-regression-baseline.md`。
- 新增 `versions/v1.3.1-RELEASE(draft).md`。
- 回归覆盖：
  - v1.3.0 备份恢复主路径继承。
  - `VoiceLedgerParser` 常见句式、失败句式。
  - Siri/AppIntent 高置信直写。
  - App 内确认与修改保存。
  - 语音来源交易参与 JSON/iCloud 备份恢复。

### Out of Scope（本版不做）

- 收入、工资、报销、转账、还款、收款入账。
- 一句话多笔支出拆分。
- 复杂自然语言日期，例如"上周五晚上"、"下个月"。
- 多轮 Siri 对话确认。
- 自研录音 UI、Speech framework 转写、录音文件存储。
- 云端语音识别、云端 LLM、联网解析。
- Apple Watch 语音记账。
- 订阅/周期账单的语音创建。
- 预算、账户、支付方式等新维度。

## 4. 阶段拆分

| 阶段 | 目标 | 输出物 | 风险 |
|---|---|---|---|
| Phase 0 | 来源、note、调试与备份兼容对齐 | `.voice` 来源、语音调试来源、数据约定 | 来源枚举会影响设置页、编辑页、备份展示，需要完整本地化 |
| Phase 1 | 规则解析引擎 | `VoiceLedgerParser`、结果模型、失败原因、单元/离线回归 | 中文短句很自由，必须控制 MVP 范围，避免误存 |
| Phase 2 | Siri/AppIntent 入账 | `VoiceLedgerIntent`、AppShortcuts 短语、SQLite 写入、去重、通知刷新 | Siri 参数传递和短语发现需真机验证 |
| Phase 3 | App 内确认入口 | 语音/文本输入入口、确认 Sheet、可编辑字段、保存路径 | UI 容易过重；MVP 应保持比截图入口更轻 |
| Phase 4 | 本地化与调试 | 文案 key、DebugView 展示、回归样本 | 调试记录不能收集音频或隐私过量文本 |
| Phase 5 | 回归与发布收口 | 回归基线、发布草稿、README/CHANGELOG 同步 | Siri 真机验证不可由 generic build 完全替代 |

## 6. 验收标准

- Siri 输入"午饭 28 元"后保存一笔支出：
  - merchant：`午饭`
  - amount：`28`
  - category：`dining`
  - source：`voice`
  - note：`语音记账`
- Siri 输入"昨天打车 23.8"后保存一笔昨天的出行支出。
- Siri 输入"星巴克 32"后保存一笔餐饮/咖啡相关支出。
- Siri 输入"今天花了 20 和 30"不保存，并提示只说一笔支出。
- Siri 输入"收到报销 200"不保存，并提示当前语音记账仅支持支出。
- Siri 输入"午饭"不保存，并提示没有识别到明确金额。
- App 内输入同样文本时，中低置信度进入确认页而不是静默失败。
- App 内确认页可修改金额、商户、分类、时间并保存。
- 语音交易出现在账本、月报、来源管理、最近删除、JSON/iCloud 备份恢复链路中。
- 离线回归覆盖解析、失败原因、持久化、备份恢复。

## 7. 测试计划

- 单元/离线解析样本：
  - `午饭 28`
  - `咖啡 18 元`
  - `打车 36.5`
  - `昨天停车费 12`
  - `买水果 23`
  - `今天花了 20 和 30`
  - `收到工资 8000`
  - `朋友转我 50`
  - `午饭`
- 持久化测试：
  - 高置信解析结果保存到 SQLite。
  - 60 秒内重复语音不重复入账。
  - `source = voice` 交易可删除、恢复、彻底删除。
- 备份测试：
  - 导出包含语音交易。
  - 覆盖恢复后来源、note、分类、时间保持一致。
- 构建测试：
  - `bash scripts/run_offline_regression.sh`
  - `xcodebuild -workspace AutoLedger.xcworkspace -scheme AutoLedger -destination 'generic/platform=iOS' build`
- 真机测试：
  - Siri 能发现 `VoiceLedgerIntent`。
  - Siri 短语触发后不打开 App 也能写入。
  - App 回到前台能刷新出语音入账记录。

## 8. 风险与回滚

- **Siri 参数传递风险**：不同系统版本对 AppIntent 参数短语支持不一致；若真机体验不稳定，保留 App 内入口，将 Siri 自动直写降级为打开 App 确认。
- **误识别误保存风险**：Siri 只允许 high 置信度保存；多个金额、收入转账、无描述、无金额都不保存。
- **UI 入口膨胀风险**：App 内 MVP 只做文本/系统听写 + 确认 Sheet，不新增完整录音转写工作台。
- **数据兼容风险**：新增 `.voice` 来源是向后兼容枚举扩展；若回滚，交易仍可作为自定义来源字符串显示，不破坏 SQLite。
- **回滚方式**：
  - 移除 `VoiceLedgerIntent` 的 AppShortcut 注册。
  - 隐藏 App 内语音入口。
  - 保留已生成的 `source = voice` 交易，按普通交易继续显示、备份和删除。
  - 若解析误存，用户可通过账本删除或最近删除恢复流程处理。
