`v1.6.2` 已进入开发阶段。`v1.6.0` 和 `v1.6.1` 已标记完成，剩余项目不再作为旧版本 blocker，而是分为两类处理：

| 类型 | 内容 | 处理方式 |
|---|---|---|
| 测试 / 人工证据 | Device Hub Resize Mode、iPhone Mirroring 连续 resize、visionOS 真机、日文母语审校、平台素材最终目检 | 作为 `v1.6.2` release smoke 或人工验收记录，不一定需要新增业务代码 |

当前建议先从 `GOAL-1910 / GOAL-1911` 开始，完成 SDK 阶段二主界面交互 polish；如果优先想验证酒店邮箱公共用户链路，则从 `GOAL-1930` 开始也可以。

## 1. 版本定位

`v1.6.2` 承接 `v1.6.1` 已完成的酒店水单 A 阶段、酒店水单 B 阶段首版、多账本基础能力、日文支持、跨平台图标重绘和新版本 SDK 适配阶段一。

本版本不作为新的数据模型大重构版本，而是把 `v1.6.1` 的后延项收束成可交付、可验证、可回滚的下一条开发线：

1. 新版本 SDK 适配阶段二：在阶段一可拉伸布局基础上，补齐系统化导航、toolbar、Material、列表手势、表单宽屏体验和状态保持 smoke。
2. 酒店水单 B 阶段工程收口：让本地邮箱手动扫描从“可走通”变成公共用户可测试的安全链路，补待确认队列、去重、拒绝记录、Demo Mode 和审核材料。
3. Widget、基础 App Intents 与 deep link 第一版：先建立稳定入口和可测试路由，不做依赖 Apple Intelligence 的任意自然语言问答。
4. 数据可靠性和工程质量第一段：围绕导入导出、备份恢复、长列表性能、辅助功能、深色模式和 iOS 17 / 26 / 27 回归建立门禁。
5. 多语言和日文发布素材收口：对 `ja` 文案、截图、ASC metadata、Review Notes 和多语言识别 golden cases 做人工审校前的工程准备。

## 2. 当前优先级

### P0：当前版本必须优先完成

- SDK 适配阶段二的主界面 polish：系统导航栏、系统 Tab / sidebar 行为、toolbar 主次操作分层、表单宽度、列表侧滑操作和可拉伸状态保持。
- 酒店邮箱导入 B 阶段收口：持久化待确认草稿、邮箱 / 附件去重、拒绝记录、失败重试、Demo Mode 和隐私审核说明。
- Deep link 和 Router 基线：通过 `autoledger://` 打开账单、酒店消费、账本管理和统计页面时复用现有 `AutoLedgerNavigationState`，不销毁当前上下文。
- 回归基线：建立 `v1.6.2-regression-baseline.md`，记录 iOS 17 fallback、iOS 27 resize、Mac Catalyst、Widget / App Intent、酒店邮箱导入和多语言的最小门禁。

### P1：可在本版本推进，但允许拆分

- Widget 第一段：本月支出、预算剩余、最近账单、即将续费和快速记一笔入口。
- 基础 App Intents 第一段：快速添加支出、打开本月统计、打开某一账本、启动收据扫描。
- 多账本展示端口径：Widget / Watch / tvOS / visionOS 先保持只读，优先明确默认写入账本、本地账本和全部账本的展示策略。
- 数据可靠性第一段：CSV / JSON 导入导出、备份恢复 smoke、长列表性能检查、Dynamic Type、VoiceOver、深色模式和大字体。
- 日文发布材料审校：术语表、截图文案、ASC metadata、TestFlight notes 和 Review Notes 的人工审校清单。

### Later：只记录路线，不作为 v1.6.2 交付门禁

- 酒店水单 C 阶段 Worker 云端自动化。
- 邮箱后台自动持续扫描。
- 云端保存邮箱授权或代拉完整邮箱。
- 依赖 Apple Intelligence 的任意账本自然语言问答。
- 完整的多账本 Widget / Watch / tvOS / visionOS 编辑能力。
- 远程语言包热更新和社区语言包分发后台。

## 3. 设计原则

- 继续保持本地优先。正式账本、酒店水单、邮箱授权码、原始 PDF 和用户纠错数据默认保留在本机或用户可控存储中。
- 所有导入和识别结果默认进入待确认状态。酒店水单、邮箱附件和 Widget 快速记账都不得绕过用户确认直接污染正式账本。
- 新版本 SDK 适配继续基于容器尺寸、size class、safe area 和 scene geometry，不恢复 phone / pad idiom、方向或固定屏幕宽高布局分支。
- Deep link、Widget、App Intents 只能打开入口、填充草稿或进入复核，不直接执行高风险删除、同步或自动入账。
- 酒店识别管线继续来源无关：手动 PDF、本地邮箱 IMAP、Share Extension 或未来 Worker 都进入统一 import pipeline 和 `HotelFolioParsePipeline`。
- 账单识别继续以确定性校验为主。金额、日期、币种、账户、账本归属等关键字段不得由模型单独决定。
- 多语言识别语言包保持可扩展，但社区共享必须 opt-in、脱敏、可撤回，并经过审核后才能进入 reviewed pack。

## 4. 主线设计

### 4.1 SDK 适配阶段二：新版界面和交互

目标：在 `v1.6.1` 阶段一可拉伸布局已完成的基础上，让 AutoLedger 在 iPhone Mirroring、iPad 宽屏、Mac Catalyst 和 iOS 27 sidebar 环境下更像一个真正的自适应生产力 App。

功能范围：

- 尽量使用系统导航栏、系统 toolbar、系统 Material 和标准控件，减少自绘背景与硬编码透明度。
- 主操作保持稳定可见，例如“新增账单”“导入”“扫描”“保存”等。
- 次要操作进入 toolbar overflow menu，例如导出、批量操作、调试入口和低频设置。
- 账本列表补充侧滑编辑、删除、移动账本、标记报销等操作，确保窄屏和宽屏行为一致。
- 周期账单列表补充暂停、恢复、编辑和删除的可发现操作。
- 设置页、编辑页、酒店消费复核页继续限制最大宽度，避免宽窗口表单横向铺满。
- 首页卡片、账户、分类等拖动排序作为候选，不作为阶段二硬门槛。

验收标准：

- iOS 17-26 fallback 仍保留底部 Tab Bar，且行为不回退。
- iOS 27 及以上在空间足够时继续可进入 sidebar tab 行为。
- resize 过程中当前 Tab、账本选择、账单详情、周期账单详情和 sheet 状态不丢失。
- 主要页面没有明显文本重叠、按钮挤压、表单过宽或列表空详情不可理解的问题。
- 静态布局门禁继续通过。

### 4.2 Widget、App Intents 与 deep link 第一版

目标：先建立稳定、可测试的系统入口，让 Widget、Shortcuts、Spotlight 和 URL scheme 可以把用户带回正确上下文。

Deep link 建议：

```text
autoledger://ledger
autoledger://ledger/today
autoledger://transaction/{id}
autoledger://hotel-stay/{id}
autoledger://subscriptions
autoledger://settings/ledger-profiles
autoledger://scan
```

App Intents 第一段：

- 快速添加支出。
- 打开本月统计。
- 打开某一账本。
- 启动收据扫描。
- 启动酒店水单导入或酒店水单待确认列表。

Widget 第一段：

- 本月支出 / 预算剩余。
- 即将续费的订阅。
- 最近账单。
- 快速记一笔按钮。
- 评估 iOS 27 更大的纵向 Widget family，用于 iPad 或大尺寸环境展示完整财务概览。

边界：

- Widget 不直接写 SQLite；快速操作进入 App Intent 或主 App 复核链路。
- App Intent 新增账单仍要经过确定性校验；低置信或字段不完整时进入复核。
- Deep link 打开不存在或已删除的数据时，需要有恢复性的空状态。
- 不在本版本做“询问任意账本问题”的自然语言智能助理。

### 4.3 酒店水单 B 阶段收口

目标：把 `v1.6.1` 已走通的本地邮箱手动扫描链路整理为公共用户可测试的安全闭环。

功能范围：

- `HotelStayDraft` 待确认队列持久化，邮箱扫描结果可跨 App 会话保留。
- 本地邮箱扫描去重：`Message-ID` hash、附件 hash、文件名、邮件日期和来源邮箱 metadata。
- 用户拒绝某个候选后，后续扫描不应立即重复打扰。
- PDFKit 空文本、IMAP 登录失败、授权码失效、附件下载失败和模型未配置都进入可恢复状态。
- 酒店消费列表区分正式记录和待确认草稿。
- 支持批量清理 rejected / stale draft。
- Demo Mode 使用虚构邮箱、虚构酒店、虚构订单号和虚构 PDF 文本，不连接真实 IMAP。
- Review Notes 中提供 Demo Mode 操作步骤，避免审核员必须登录真实邮箱。

当前落地状态：

- `GOAL-1930` 已完成：`HotelStayDraft` 新增 SQLite 持久化队列表，手动 PDF / 本地邮箱生成的草稿会保存到待确认队列，酒店消费列表区分“待确认酒店水单”和正式酒店消费记录，确认入账成功后删除对应草稿；同时预留 rejected / posted stale draft 清理接口。
- `GOAL-1931` 已完成：`HotelStayDraft` 持久化邮箱 UID、邮件日期、Message-ID hash 和附件 hash；`LedgerStore.saveHotelStayDraft` 会基于附件 hash、Message-ID hash、原始 PDF 数据和已入账酒店记录拦截重复导入；pending / rejected / posted 三类重复均不会再次进入待确认队列，清理 rejected stale draft 后可重新导入同一水单；缺授权码、IMAP 错误、连接失败、附件不支持和 PDFKit 空文本继续沿用现有可恢复错误态。
- `GOAL-1932` 已完成：邮箱导入页新增 `Demo Mode`，可加载虚构候选邮件和本机生成的虚构 PDF，不连接真实 IMAP、不读取 Keychain 授权码；Demo 仍需要用户选择 PDF 附件并进入既有复核页；新增审核说明草稿和静态隐私检查，确保 Demo fixture / Review Notes 使用 `example.test` 保留域名，不包含真实邮箱域名、明文密码或完整银行卡号。

隐私要求：

- 邮箱授权码只保存在本地 Keychain。
- 不允许把邮箱授权码上传云端。
- 不允许把完整邮箱内容上传云端。
- 只对候选 PDF 提取必要文本，并在云模型识别前尽量脱敏。
- 日志、调试信息、崩溃上下文中不得出现授权码、完整邮件正文、完整会员号、证件号、银行卡号或未脱敏邮箱。

### 4.4 数据可靠性和工程质量第一段

目标：为后续更复杂的导入、Widget、深链和多账本能力建立可靠门禁。

功能范围：

- CSV / JSON 导入导出格式复核，确保 `ledgerId`、`hotelStayRecordId`、同步 metadata 和删除 tombstone 不丢失。
- 备份恢复 smoke 覆盖多账本、酒店消费、关联普通流水、订阅、商户别名和分类修正。
- 长账单列表滚动性能检查，重点观察多账本过滤、最近删除、数据清洗预览和酒店消费列表。
- Dynamic Type、VoiceOver、深色模式、大字体和 Reduce Motion 基础 smoke。
- iOS 17、iOS 26、iOS 27 三组回归策略成文；iOS 27 重点记录连续 resize 和状态保持。
- 有云同步或后端接口变更时再评估 App Attest；本版本不强行引入。

### 4.5 多语言与识别语言包收口

目标：把 `v1.6.1` 的日文支持和平台无关识别语言包继续向可发布状态推进。

功能范围：

- 日文术语表人工审校，重点检查账本、酒店水单、房晚、确认号、默认写入账本、待确认、复核、外部辅助识别。
- 日文截图文案和 ASC metadata 人工审校前的工程清单。
- App Intents / Shortcuts / Widget 的 `ja` 文案覆盖。
- 多语言账单识别 golden cases 按语言维度覆盖金额、商户、分类、日期、非账单拦截和低置信复核。
- 用户纠错本地覆盖继续优先，不在本版本实现远程语言包热更新。

## 6. 数据与迁移边界

- 当前版本不默认引入破坏性 schema 迁移。
- 若 `HotelStayDraft` 需要持久化表，应以向后兼容迁移实现，旧数据缺字段时必须可读取。
- Deep link 和 Widget 不新增正式账单字段；只复用既有 `Transaction`、`LedgerProfile`、`HotelStayRecord` 和订阅模型。
- Widget 若需要新的 App Group 快照字段，应保持旧 Widget 读取兼容。
- 多账本 Widget 口径必须先成文，再实现 UI。建议第一段默认展示默认写入账本或本地账本，并在文案中明确来源。
- 所有可选字段导入导出必须保留未知 / nil 兼容，避免旧备份无法恢复。
