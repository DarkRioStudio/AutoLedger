## 3. 残留分类

### 3.1 解析规则与 OCR 样例

代表文件：

- `AutoLedger/AutoLedger/Domain/Services/ReceiptParser.swift`
- `AutoLedger/AutoLedger/Domain/Services/SmartReceiptParser.swift`

这些中文字符串主要是支付截图、小票、支付宝 / 微信 / 银联账单的识别关键词、排除词、日志标签或 OCR 样例，不属于界面文案。当前不应简单本地化，否则会影响中文账单解析准确性。

### 3.2 Debug、诊断与真机回归辅助

代表文件：

- `AutoLedger/AutoLedger/Features/Settings/DebugView.swift`
- `AutoLedger/AutoLedger/App/LedgerStore.swift` 的 iCloud 同步日志与调试摘要
- `FeedbackBundleBuilder` 相关导出文案

这类文案主要面向开发者、审核辅助或用户主动导出的诊断包。当前仍有中文硬编码，建议单独定义 Debug / diagnostics 本地化策略后集中处理，避免与主 App 交易路径混在一个提交中。

### 3.3 历史 `lastImportSummary` 用户提示

代表文件：

- `AutoLedger/AutoLedger/App/LedgerStore.swift`

除本轮已修复的多账本移动提示外，`lastImportSummary` 仍包含删除、恢复、手动记账、批量更新、数据清洗、备份恢复、iCloud 同步等历史用户可见提示。它们数量较多且覆盖导入、清洗、同步等高频路径，建议作为后续独立 GOAL 逐组迁移，并给每组补最小回归或 smoke。

### 3.4 默认账本名与数据默认值

代表文件：

- `AutoLedger/AutoLedgerCore/Sources/AutoLedgerCore/Models/TodaySpendingSummary.swift`
- `AutoLedger/AutoLedgerCore/Sources/AutoLedgerCore/Models/LedgerProfile.swift`

`本地账本` 是当前默认账本的持久化数据名，不只是 UI 文案。是否为新安装用户按语言生成默认名称、是否迁移既有 `ledger_profiles.name`，需要单独设计，不能在硬编码审计中静默改名。

### 3.5 截图模式演示文案

代表文件：

- `AutoLedger/AutoLedger/Screenshots/ScreenshotHostView.swift`

截图模式已有自己的 copy helper 和 scene 文案体系。本轮只记录，不改变截图导出策略；日文截图文案与 ASC 元数据归入 `GOAL-1852`。

## 4. 后续建议

- 后续 `L10N` GOAL 可优先迁移 `LedgerStore.lastImportSummary` 中高频用户提示，按删除 / 恢复、手动记账、批量编辑、数据清洗、iCloud 同步分组提交。
- 明确 Debug / diagnostics 是否需要完整四语，还是保持中文开发者辅助文案并在审核说明中提供 Demo Mode。
- 单独决策默认账本名称本地化策略，避免影响既有数据库、备份和 CloudKit 同步中的账本名称。
- `GOAL-1852` 继续补日文术语表、截图文案、ASC metadata、TestFlight notes 和 Review Notes 草稿，并标记人工审校要求。
