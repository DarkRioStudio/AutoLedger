# v1.6.0 版本计划

更新日期：2026-06-19
文档状态：第一版推进中 / Active
内部开发线：v1.6.0
App Store 对外版本：1.5.0
承接版本：v1.5.1 release candidate
关联文档：`versions/v1.5.1-plan.md`、`versions/v1.5.1-regression-baseline.md`、`docs/recognition-learning-cache-design.md`

## 1. 版本定位

`v1.6.0` 承接 `v1.5.1` 已完成的 iPhone / iPad / Apple Watch / Mac Catalyst 发布基线，不在本版本重做主线架构。

本版本优先处理四类增量：

1. 订阅管理补强
2. 外部辅助识别后的商户 / 分类 / 订阅倾向学习缓存
3. tvOS / visionOS 展示版进入可运行版本
4. Mac 与全平台体验继续打磨

多账本继续顺延到后续版本，不进入 `v1.6.0` 实现范围。

## 2. 设计原则

- 继续保持本地优先，正式账单数据仍以本机和用户 iCloud 为主。
- 外部辅助识别继续默认关闭，由用户手动配置 API key 后启用。
- 外部模型不得决定金额和是否自动保存，只能辅助商户、分类、订阅倾向等候选信息。
- 识别缓存只缓存用户确认过的低风险结果，不缓存整张 OCR 到完整账单的强绑定结果。
- 新增订阅能力必须用户确认后写入订阅管理，不做静默自动创建。
- tvOS / visionOS 首版以只读展示为主，不承载导入、编辑、清洗、多账本等复杂流程。

## 3. 核心范围

### 3.1 订阅管理补强

目标：让订阅管理从“识别和展示”升级为可维护的基础功能。

计划能力：

- 手动新增订阅
- 编辑订阅
- 暂停 / 取消订阅
- 从账单详情一键创建订阅
- 从识别结果提示“这可能是订阅”
- 下次扣费日期、周期、金额、服务名可编辑
- 订阅列表按即将扣费排序
- 保留提醒和统计入口

边界：

- 不自动把模型判断结果写入订阅
- 不自动扣减、预测或修改正式账单
- 不做多账本订阅归属

### 3.2 AI 订阅判断

目标：在外部辅助识别已经可用的基础上，让模型辅助判断当前账单是否可能是订阅项目。

计划扩展字段：

- `subscriptionHint.isSubscription`
- `subscriptionHint.serviceName`
- `subscriptionHint.billingCycle`
- `subscriptionHint.confidence`

使用策略：

- 高置信时在入账后提示用户是否加入订阅管理
- 中低置信只进入调试记录或候选提示
- 用户确认后才创建订阅
- 调试记录记录是否走外部模型、模型耗时、订阅判断结果和置信度

### 3.3 识别学习缓存

目标：降低重复商户识别成本，提高常见消费场景稳定性。

设计文档：`docs/recognition-learning-cache-design.md`

允许缓存：

- 用户确认过的商户别名
- 商户默认分类
- 商户是否常见订阅服务
- 外部模型返回的商户候选摘要
- 同一脱敏 OCR hash 的短期外部辅助结果

禁止缓存：

- 完整原始 OCR
- 原始截图
- 完整支付截图文本
- 金额、时间、订单号、卡号等会随交易变化的字段
- “整张 OCR 直接复用完整账单”的结果

建议策略：

- merchant-level cache 优先
- OCR hash cache 只作为短期性能优化，默认 TTL 较短
- 缓存命中只能作为候选增强，不得覆盖金额和日期
- 用户编辑商户 / 分类后更新学习结果

### 3.4 tvOS 只读看板

目标：完成第一版可运行的 Apple TV 只读账本展示。

首版能力：

- 本月支出总览
- 分类占比
- 最近消费趋势
- 年度 / 月度摘要
- 家庭大屏看板

边界：

- 只读
- 单一正式账本
- 不做导入 / 编辑 / 清洗
- 不做多账本切换

### 3.5 visionOS 展示版

目标：完成第一版可运行的 visionOS 空间展示体验。

首版能力：

- 月度支出空间看板
- 分类支出卡片漂浮展示
- 年度消费时间线墙
- 最近账单悬浮列表

边界：

- 首版以 SwiftUI WindowGroup 为主
- immersive space 不作为硬门槛
- 只读
- 单一正式账本

### 3.6 Mac 与全平台体验打磨

目标：继续消化 v1.5.1 发布后发现的桌面端和多端细节问题。

候选项：

- Mac 默认窗口与表格布局继续优化
- Mac 导入 / 导出 / 批量编辑 smoke 自动化记录
- iPad 工作台二级页面切换稳定性继续观察
- Watch App 与 Widget 数据刷新链路继续复测
- iCloud 同步性能继续观察 P50 / P90
- 截图管线继续覆盖全平台素材

`v1.6.0` 当前作为 App Store 1.5.0 的开发线推进。最终是否提交 App Store 发布，取决于以下条件：

- 订阅管理基础功能没有账单数据风险

- 多账本仍然不作为本版本 blocker

## 7. 当前结论

`v1.6.0` 已切换为 App Store 1.5.0 的下一条开发线，优先补强订阅管理和识别学习能力，同时推进 tvOS / visionOS 展示版。

本版本不改变 `v1.5.1` 当前提审判断；`v1.5.1` 可继续按当前 release candidate 进入 ASC 审核。

### 8.5 GOAL-1730 商户 / 分类 / 订阅倾向学习缓存设计（2026-06-19）

状态：DONE。

本轮冻结识别学习缓存边界，新增 `docs/recognition-learning-cache-design.md`。设计将缓存拆成三层：L1 用户确认规则、L2 商户级低风险画像、L3 短期脱敏 OCR hash 缓存。缓存只用于候选增强，不覆盖金额和日期，不自动保存账单，不自动创建订阅。

设计结论：

- L1 继续复用现有 `merchantAliases`、`categoryCorrections` 和用户确认后的 `subscriptions`。
- L2 未来可新增商户级低风险画像，只保存商户、别名、分类投票和订阅倾向统计。
- L3 短期脱敏 OCR hash 缓存顺延到 `GOAL-1735`，默认不进入 iCloud、不进入 JSON 备份。
- 金额、时间、订单号、卡号、手机号、地址、原始 OCR、截图和完整支付文本都不得进入学习缓存。
- 外部模型候选只有在用户最终保存或确认后，才能进入长期学习结果。

未改动范围：

- 本轮不实现运行时代码。
- 不新增 SQLite schema。
- 不改变 iCloud 同步 schema。
- 不修改 Bundle ID、DEVELOPMENT_TEAM、App Group、iCloud Container、entitlements、Xcode Cloud 脚本或 App Store Connect 配置。

### 8.6 GOAL-1735 外部辅助识别短期结果缓存（2026-06-19）

状态：DONE。

本轮实现外部 Assist 的 L3 短期结果缓存。缓存以脱敏 OCR 文本的 SHA-256 指纹、来源、provider、model 和 endpoint 指纹共同组成 key；缓存值只保存模型候选结果，不保存原始 OCR、脱敏 OCR 原文、截图、金额、日期、订单号、卡号、手机号或地址。缓存默认 TTL 为 24 小时，最多保留 80 条，provider / endpoint / model / API key 变化时会主动清理。

改动范围：

- `ExternalReceiptAssistCache.swift`：新增 Core 层缓存记录和策略，覆盖 cache key、TTL、过期判定和 prune 逻辑。
- `ExternalReceiptAssistClient.swift`：在请求外部 provider 前读取短期缓存，网络成功后写入缓存；缓存仅存本机 `UserDefaults` 专用 key，不进入现有备份和 iCloud 配置快照。
