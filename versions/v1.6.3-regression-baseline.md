## 1. 范围

本 baseline 用于 `v1.6.3` 酒店水单 C1 专属收件箱第一版工程骨架的最小回归门禁。

已完成范围：

- `GOAL-2000`：C1 / C2 边界冻结。
- `GOAL-2010`：专属收件地址、token normalize、token hash 和对象存储前缀合同。
- `GOAL-2011`：云候选 metadata、MIME 解析结果到候选合同的 factory、附件 hash 和脱敏来源。
- `GOAL-2012`：候选状态机、状态转换 helper 和 cloud candidate deep link。
- `GOAL-2013`：App 侧已下载 PDF data -> PDFKit 文本提取 -> `.cloudWorker` 草稿转换服务。
- `GOAL-2014`：复用既有 `HotelStayDraft -> User Review -> HotelStayRecord + Transaction` 链路的入账边界。
- `GOAL-2015`：隐私说明、审核材料和 release smoke 文档收口。

明确不属于当前完成范围：

- 真实 Worker inbound email 服务。
- 对象存储、签名下载 URL、过期清理任务。
- APNs 推送。
- 云端候选 API、App 云候选列表 UI、手动刷新云候选列表。
- 订阅后端和专属地址管理 UI。
- Worker PDF 识别、自动生成正式账单或自动入账。

## 3. C1 专项断言

自动回归应覆盖：

- `folio+<token>@getautoledger.app` 地址生成和规范化。
- raw token 不进入对象存储 key。
- token hash 可作为索引 / prefix，但不作为安全签名。
- raw Message-ID 不保存，只保存 Message-ID hash。
- 邮件主题和发件人进入候选前脱敏。
- PDF 附件 hash 稳定。
- 候选状态包含 `received`、`stored`、`notified`、`downloaded`、`converted`、`expired`、`deleted`、`failed`。
- downloaded / converted / deleted / failed 状态转换可回归。
- 已下载 PDF data 能生成 `HotelStayDraft(sourceType: .cloudWorker)`。
- 生成的草稿保留 source PDF data、来源文件名、附件 hash 和来源 metadata。
- `autoledger://hotel-cloud-candidates` 与 `autoledger://hotel-cloud-candidate/{candidateID}` deep link 被静态门禁覆盖。

## 5. 已知非阻塞项

- `v1.6.3` 当前完成口径是 App/Core 第一版工程骨架和审核 / 回归文档，不是公开云端导入服务上线。
- Xcode 构建可能仍保留项目既有 Swift warning；只要没有新增错误，不阻塞当前文档收口。
- `sourceEmailUID` 暂作为 cloud candidate ID 的兼容承载字段，后续如需独立 `cloudCandidateID` 字段，应作为 SQLite / CloudKit schema 升级单独处理。
