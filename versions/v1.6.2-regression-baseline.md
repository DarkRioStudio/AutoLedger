# v1.6.2 Regression Baseline

更新日期：2026-06-27
内部开发线：v1.6.2
App Store / ASC 对外版本：默认沿用 ASC 1.5.0 资产策略

## 1. 范围

本 baseline 用于 `v1.6.2` 开发阶段的最小回归门禁。`v1.6.2` 承接 `v1.6.1` 的完成态，重点覆盖：

- SDK 适配阶段二：系统导航、toolbar、Material、列表侧滑、表单宽屏和状态保持。
- 酒店水单 B 阶段收口：草稿队列、邮箱去重、拒绝记录、失败重试、Demo Mode 和隐私审核材料。
- Deep link / Widget / App Intents 第一段。
- 数据可靠性：CSV / JSON、备份恢复、长列表性能、辅助功能和多系统回归。
- 多语言：日文审校、Widget / App Intents 文案和多语言识别 golden cases。

## 3. 功能专项回归

### 3.1 SDK 适配阶段二

- `GOAL-1910 / GOAL-1911` 已执行自动回归：自适应布局静态门禁、本地化覆盖、离线回归、Golden 回归和主 App iOS generic build 均通过。
- iOS 17-26 保持底部 Tab Bar fallback。
- iOS 27 及以上在空间足够时保持 sidebar tab 行为。
- 账本和周期账单在窄屏 / 宽屏切换后保留选择状态。
- 宽 iPhone / iPhone Mirroring 双栏下账本列表应比默认系统列宽更宽，避免商户名和金额过度换行。
- iPhone / iPad / Mac 账本主线应复用 `LedgerView`：regular 保存后保留右侧详情，compact 保存后可返回列表。
- toolbar 主操作可见，低频操作进入 overflow。
- 设置页、编辑页和酒店复核页宽屏不横向铺满。
- 列表侧滑操作在窄屏和宽屏行为一致。
- `scripts/check_accessibility_smoke.py` 覆盖生产视图不锁 Dynamic Type、主路径 VoiceOver / Reduce Motion / 宽屏包装关键点。
- Device Hub Resize Mode / iPhone Mirroring 连续 resize 需要人工截图或视频 evidence。

### 3.2 酒店水单 B 阶段收口

- `GOAL-1930` 已完成工程基线：`hotel_stay_drafts` SQLite 表、`LedgerStore.hotelStayDrafts` 启动加载、导入后保存待确认草稿、酒店消费列表区分正式记录和待确认草稿、点击草稿重新复核、确认入账后移除草稿；离线回归覆盖 SQLite 跨会话保存、原始 PDF 数据保留和确认后清理。
- `GOAL-1931` 已完成工程基线：本地邮箱草稿持久化邮箱 UID、邮件日期、Message-ID hash 和附件 hash；`LedgerStore.saveHotelStayDraft` 会拦截同一附件 hash、同一 Message-ID hash、同一原始 PDF 数据或已入账酒店记录对应的重复水单；pending / rejected / posted 三类重复均有回归覆盖，清理 rejected stale draft 后可重新导入。
- `GOAL-1932` 已完成工程基线：邮箱导入页提供 `Demo Mode`，加载虚构候选邮件和本机生成的虚构 PDF，不连接 IMAP、不读取 Keychain；候选仍需要用户选择 PDF 后进入复核链路；`versions/v1.6.2-hotel-email-review-notes.md` 提供审核步骤，`scripts/check_hotel_email_demo_privacy.py` 纳入离线回归，检查 Demo fixture / Review Notes 使用 `example.test` 保留域名且不包含真实邮箱域名、明文密码或完整银行卡号。
- 不输入邮箱授权码时不能扫描。
- 授权码只进入 Keychain，不进入 SQLite、UserDefaults、CloudKit、日志或崩溃上下文。
- 用户主动点击后才扫描 IMAP，不做后台自动读取。
- 同一 Message-ID / PDF 附件 hash 不重复生成待确认草稿，已入账酒店水单不会因再次扫描同一附件而重复入账。
- rejected 候选不会在下一次扫描立即重复打扰；显式清理 rejected stale draft 后才允许重新导入同一水单。
- PDFKit 空文本、IMAP 登录失败、授权码失效、附件下载失败和模型未配置都有可恢复状态。
- Demo Mode 不连接真实邮箱，也能演示“候选邮件 -> PDF -> 待确认 -> 入账”；公共版本默认保留 `HotelFolioEmailDemoMode.isAvailable` 作为审核和用户演示入口。

### 3.3 Deep Link / Widget / App Intents

- `GOAL-1920` 已完成工程基线：`autoledger` URL scheme 注册、集中 deep link 解析、根级 `.onOpenURL`、账本详情选择、酒店详情选择、设置页账本管理 / 订阅列表路由、Mac Catalyst 工作台路由同步和 `scripts/check_deep_link_smoke.py` 静态门禁。
- `GOAL-1921` 已完成工程基线：新增导航类 App Intents，覆盖打开本月统计、打开某一账本、启动收据扫描和酒店待确认入口；`LedgerProfileEntityQuery` 从本地 SQLite 账本 profile 提供候选；Intent 通过本地 handoff 让主 App 激活后切换 tab / 账本；`AutoLedgerShortcuts` 注册本月统计、指定账本和收据扫描推荐短语，并通过 `scripts/check_app_intents_smoke.py` 固化 intent 存在、handoff 消费、本地化 key 和 AppShortcut 不超过 10 个的门禁。
- `xcrun simctl openurl` 可打开 `autoledger://ledger`、`autoledger://transaction/{id}`、`autoledger://hotel-stay/{id}`、`autoledger://settings/ledger-profiles` 和 `autoledger://scan`。
- 无效或已删除 ID 显示恢复性空状态，不崩溃。
- Widget 不直接写 SQLite；快速操作进入 App Intent 或主 App 复核链路。
- App Intents 低置信或字段不完整时进入复核，不直接自动入账。
- 酒店待确认入口当前作为 AppIntent 存在但不注册为 AppShortcut 推荐短语，避免超过系统 10 个 AppShortcut metadata 上限；后续如要上推荐短语，需要替换掉低频旧 shortcut 或合并入口。
- Widget 多账本显示口径在 UI 文案和数据查询中一致。

### 3.4 数据可靠性和辅助功能

- CSV / JSON 导入导出保留 `ledgerId`、`hotelStayRecordId`、sync metadata 和 tombstone。
- 备份恢复覆盖多账本、酒店消费、关联流水、订阅、商户别名和分类修正。
- 长列表滚动检查覆盖账本列表、最近删除、数据清洗预览、酒店消费列表和订阅列表。
- Dynamic Type、大字体、VoiceOver、深色模式和 Reduce Motion 至少完成主路径 smoke；工程侧通过 `scripts/check_accessibility_smoke.py` 固化静态门禁，人工侧仍需真机 / Device Hub 目检。

### 3.5 多语言和日文

- `zh-Hans` / `zh-Hant` / `en` / `ja` key 集合一致。
- Widget / App Intents / Shortcuts 新文案覆盖日文。
- 日文截图、ASC metadata、TestFlight notes 和 Review Notes 经过人工审校后再进入发布材料。
- 多语言识别 golden cases 覆盖金额、商户、分类、日期、非账单拦截和低置信复核。
