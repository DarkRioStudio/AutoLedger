## 0. 版本定位

`v1.6.3` 聚焦酒店水单 C 阶段的第一条可公开路线：C1 AutoLedger 专属收件箱自动导入。

C1 的真实定位：

- 面向订阅用户提供 AutoLedger 专属酒店水单导入邮箱，例如 `folio+<token>@getautoledger.app`。
- 用户可以手动转发酒店水单邮件，也可以在自己的邮箱里设置自动转发规则，或把该地址作为酒店 / OTA 账单收件地址。
- Worker 只处理发送到 AutoLedger 专属地址的邮件。
- Worker 不登录用户邮箱，不保存用户 QQ / IMAP / Gmail / Outlook 授权码。
- Worker 不在初版识别 PDF，不生成正式酒店消费记录，不生成正式账单，不自动入账。
- App 下载候选 PDF 后，仍在本地执行 PDFKit 文本提取、脱敏和 `HotelFolioParsePipeline` 识别。
- 用户确认后才生成 `HotelStayRecord` 和关联 `Transaction`。

C2 Worker 登录用户邮箱自动扫描只作为个人自用或未来实验路线，不作为 `v1.6.3` 公开订阅主线。

## 1. 设计原则

- 来源无关：C1 只改变 PDF 来源，不改变酒店水单解析、复核、确认和入账主链路。
- 本地识别优先：PDF 文本提取、脱敏、LLM 解析和复核仍由 App 执行。
- 最小云端数据：Worker 只保存候选元数据、附件 hash、对象存储 key、过期时间、订阅用户映射和投递状态。
- 不碰用户邮箱授权：云端不保存邮箱授权码、不连接用户邮箱、不读取完整邮箱。
- 不自动入账：任何云端候选只进入 App 待确认队列，用户确认后才入账。
- 可撤回：用户应能轮换 / 停用 `folio+<token>@getautoledger.app` token，删除云端候选和本地草稿。
- 短期暂存：PDF 在云端只做短期对象存储，默认过期删除；App 成功下载 / 转换后可主动删除云端 PDF。
- 锁屏隐私：APNs 推送只提示“新的酒店消费待入账 / 待识别”，不展示酒店名、订单号、金额等敏感信息。

## 2. P0 范围：C1 最小可测试闭环

### 2.1 专属收件地址与 token

目标：为订阅用户生成可轮换的 AutoLedger 酒店水单导入地址。

功能范围：

- 生成 `folio+<token>@getautoledger.app`。
- token 与用户 / 设备 / 订阅状态建立映射。
- 支持复制地址、轮换 token、停用 token。
- 停用后的 token 不再接受新候选。
- token 只以 hash 或不可逆形式进入日志与索引。

非目标：

- 不实现 Worker 登录用户邮箱。
- 不实现 OAuth / IMAP 授权。
- 不把用户私人邮箱作为云端扫描目标。

### 2.2 Worker 入站邮件处理

目标：Worker 只处理发往 AutoLedger 专属地址的邮件，生成 cloud hotel folio candidate。

功能范围：

- 接收 inbound email。
- 校验收件地址 token、用户映射和订阅状态。
- 解析 MIME，提取 PDF 附件。
- 忽略无 PDF 附件邮件或记录为不可导入候选。
- 计算 PDF 附件 hash。
- 将 PDF 写入对象存储。
- 创建 cloud hotel folio candidate。
- 记录候选状态：`received`、`stored`、`notified`、`downloaded`、`converted`、`expired`、`deleted`、`failed`。
- 对同一 token + Message-ID hash + 附件 hash 做去重。

候选元数据建议：

```text
CloudHotelFolioCandidate
- id
- userID
- tokenHash
- sourceEmailFromRedacted
- sourceEmailSubjectRedacted
- messageIDHash
- attachmentFileName
- attachmentHash
- objectStorageKey
- objectByteSize
- mimeType
- status
- receivedAt
- expiresAt
- downloadedAt
- convertedAt
- deletedAt
- failureReason
```

非目标：

- Worker 不识别 PDF。
- Worker 不调用酒店水单 LLM。
- Worker 不生成 `HotelStayDraft`。
- Worker 不生成 `HotelStayRecord`。
- Worker 不生成 `Transaction`。

### 2.3 APNs 推送与 App 唤醒

目标：收到新候选后，让用户知道有待确认酒店消费。

功能范围：

- Worker 通过 APNs 推送到用户设备。
- 推送 payload 只包含候选 ID / deep link 所需的最小路由数据。
- 推送文案避免展示酒店名、金额、订单号、入住日期等敏感信息。
- 用户点通知后打开 App，并路由到酒店消费候选详情。
- App 若离线或未收到推送，应能在酒店消费页手动刷新云端候选。

建议 deep link：

```text
autoledger://hotel-cloud-candidate/{candidateID}
autoledger://hotel-cloud-candidates
```

### 2.4 App 下载 PDF 与本地识别

目标：App 从云端候选下载 PDF 后，复用现有本地酒店水单识别链路。

统一链路：

```text
CloudHotelFolioCandidate
-> App downloads PDF
-> PDFKit text extraction
-> local redaction
-> HotelFolioParsePipeline
-> HotelStayDraft(sourceType: .cloudWorker)
-> User Review
-> HotelStayRecord + Transaction
```

功能范围：

- App 展示云端候选列表和候选详情。
- 用户点击候选后下载 PDF。
- 下载成功后本地执行 PDFKit 文本提取。
- 文本脱敏后进入现有 `HotelFolioParsePipeline`。
- 生成 `HotelStayDraft(sourceType: .cloudWorker)`。
- 待确认页继续展示本地化识别结果、原始文本和来源信息。
- 用户确认后生成 `HotelStayRecord` 和关联 `Transaction`。
- 记录 cloud candidate ID、附件 hash、来源文件名和转换状态。
- App 成功下载 / 转换后通知 Worker 可删除云端 PDF。

本地数据建议：

- `HotelStayDraft.sourceType = .cloudWorker`
- `HotelStayDraft.sourceFileName`
- `HotelStayDraft.sourceEmailSubject`
- `HotelStayDraft.sourceEmailFrom`
- `HotelStayDraft.rawText`
- `HotelStayDraft.parsedPayload`
- `HotelStayDraft.sourcePDFData`
- `HotelStayDraft.cloudCandidateID`
- `HotelStayDraft.attachmentHash`

### 2.5 云端清理与失败恢复

目标：让云端 PDF 短期暂存、可回收、可恢复。

功能范围：

- PDF 默认设置过期时间。
- App 下载成功后可触发云端 PDF 删除。
- App 转换为本地草稿后可触发候选状态 `converted`。
- 用户删除候选或草稿时，可同步删除云端对象。
- 过期候选由 Worker 定期清理。
- APNs 推送失败不影响候选保存；App 刷新候选列表仍可看到。
- 下载失败、PDF 损坏、PDFKit 空文本、对象已过期都需要可恢复提示。

## 2.6 第一版工程落地状态（2026-06-29）

本轮完成 `GOAL-2000` 至 `GOAL-2014` 的第一版 App/Core 骨架，目标是先冻结 C1 合同并让 App 可复用现有本地酒店水单链路。它不是完整云端上线版本，未实现真实 Worker、对象存储、APNs 或订阅后端。

已落地：

- `HotelCloudFolioInboxAddress`：生成并规范化 `folio+<token>@getautoledger.app`，为云端索引提供 token hash 和对象存储前缀，避免日志 / key 泄露 raw token。
- `CloudHotelFolioCandidate`：定义 C1 云候选合同，覆盖候选 ID、token hash、脱敏邮件主题 / 发件人、Message-ID hash、附件 hash、对象存储 key、PDF 大小、MIME、状态和过期时间。
- `CloudHotelFolioCandidateStatus`：第一版状态包含 `received`、`stored`、`notified`、`downloaded`、`converted`、`expired`、`deleted`、`failed`，并提供下载、转换、删除、失败的状态转换 helper。
- `CloudHotelFolioCandidateFactory`：复用本地邮箱 MIME 解析结果生成云候选 fixture / contract，不保存完整邮箱授权、不保存 raw Message-ID，不把 raw token 写入对象 key。
- `HotelCloudFolioDraftFactory`：将已下载 PDF 和 PDFKit 提取文本转换为 `HotelStayDraft(sourceType: .cloudWorker)`，保留 PDF data、候选 ID、附件 hash、来源文件名和脱敏来源 metadata。
- App 侧 `HotelFolioCloudCandidatePDFImporter`：为未来云候选下载后接入 PDFKit 文本提取和 `.cloudWorker` Draft 生成预留服务，复用现有酒店水单解析 / 复核 / 入账链路。
- Deep link：新增 `autoledger://hotel-cloud-candidate/{candidateID}` 与 `autoledger://hotel-cloud-candidates` 路由，打开酒店消费 tab 并记录待处理候选 ID。
- 回归：`scripts/run_offline_regression.sh` 覆盖 cloud inbox 地址、候选合同、hash / 脱敏、状态转换和 cloudWorker Draft 生成；`scripts/check_deep_link_smoke.py` 覆盖 cloud candidate deep link。

尚未落地：

- 真实 Worker inbound email / MIME 入口、token 订阅校验、对象存储写入和过期清理。
- 云端候选 API、短期签名下载 URL、App 云候选列表 UI、手动刷新云候选列表。
- APNs 推送、通知点击后的候选详情下载流程。
- App 成功转换后回写 Worker `downloaded` / `converted` / `deleted` 状态。
- C1 隐私说明、审核材料、测试专属地址和云端日志脱敏验证。

## 3. P1 范围：C1 公共用户可用性补强

- 常见酒店 / OTA 邮件样式兼容：多 PDF 附件、HTML 正文、转发邮件嵌套、中文 / 英文 / 日文主题。
- 投递反馈：无 PDF、token 失效、订阅不可用、附件过大时给用户可理解反馈。
- 反滥用：附件大小限制、每用户每日候选上限、token rate limit、失败次数阈值。
- 安全：对象存储私有读写、短期签名下载 URL、日志脱敏、异常报警。
- 隐私 UI：App 内展示来源、云端暂存状态、过期时间、删除入口和隐私说明。
- 审核材料：提供无需真实邮箱登录的测试路径、示例 PDF、测试专属收件地址或 Demo Mode。
- 订阅体验：未订阅用户看到功能说明和升级入口，但不能悄悄上传或处理邮件。

## 4. Later：C2 个人自用 / 实验路线

C2 = Worker 登录用户邮箱自动扫描。它不属于 `v1.6.3` 公开订阅主线。

C2 仅作为个人自用或未来实验能力，必须单独评估：

- 云端保存邮箱授权的合规风险。
- QQ / IMAP / Gmail / Outlook 授权失效和风控。
- 邮箱全量扫描带来的隐私风险。
- 重复邮件、历史邮件、垃圾邮件和附件格式差异。
- App Store 审核解释成本。
- 用户撤权、数据删除和安全审计。

即使未来进入 C2，也不得自动正式入账，只能生成待确认候选。

## 6. 测试与验收

自动回归建议：

- Worker MIME fixture：纯 PDF、多个 PDF、无 PDF、转发嵌套、中文 / 英文 / 日文主题。
- 附件 hash 与去重：同一附件重复投递不重复推送、不重复生成候选。
- token 状态：有效、停用、轮换、未知 token、订阅失效。
- 对象存储：写入、短期签名下载、过期删除、App 下载后删除。
- APNs payload：只包含候选 ID / 路由，不包含酒店名、金额、订单号。
- App cloud candidate：下载 PDF、PDFKit 文本提取、脱敏、生成 `.cloudWorker` 草稿。
- 入账闭环：确认后生成 `HotelStayRecord + Transaction`，并继承默认写入账本 / 当前酒店分类策略。
- 删除闭环：删除候选、草稿或正式酒店记录时，本地与云端状态可解释。
- iCloud / JSON：云端候选转换后的酒店草稿 / 正式记录继续参与本机已有同步与备份策略。

人工 smoke 建议：

- 用测试专属地址转发真实格式的虚构酒店水单 PDF。
- 点 APNs 通知进入候选详情。
- App 冷启动 / 后台 / 前台三种状态下都能定位到酒店消费候选。
- PDF 过期、下载失败、PDFKit 空文本时提示可恢复。
- 深色模式、大字体、VoiceOver 下候选列表与复核页可读。

## 7. 非目标

- 不实现 Worker 登录用户邮箱作为公开功能。
- 不保存用户 QQ / IMAP / Gmail / Outlook 授权码。
- 不自动扫描用户完整邮箱。
- 不在 Worker 初版识别 PDF。
- 不在云端调用酒店水单 LLM 生成正式结构化消费。
- 不自动生成正式酒店记录。
- 不自动生成正式普通账单。
- 不长期保存用户酒店水单 PDF。
- 不把 C1 做成通用邮件归档 / CRM / 差旅管理系统。
