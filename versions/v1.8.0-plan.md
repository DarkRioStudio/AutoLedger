## Product Theme

`v1.8.0` 的主题是：

> **Review & Close / 账本闭环。**

目标不是增加更多记账入口，而是让用户能回答三个问题：

1. 还有什么没有处理？
2. 为什么需要处理，处理后会发生什么？
3. 这个月是否已经可以放心归档？

产品主循环收敛为：

> 导入或发现 -> 进入待处理 -> 复核 / 忽略 / 延后 -> 规则反哺 -> 月结检查 -> 完成本月。

## Release Positioning

- 免费版继续提供完整的手动记账、单张识别、逐条复核、基础月报、基础导出和历史数据访问。
- Pro 提供集中待处理、批量安全操作、自动检查、月结资料包和可解释的整理建议。
- 语言识别和 UI 本地化属于免费基础体验，不进入 Pro gate。
- 云端不可用时，本地账本、逐条复核、规则和月结检查必须继续可用。
- 当前酒店水单能力作为凭证归档的差异化来源进入统一工作流，但本版本不扩张为企业报销系统。

## P0 Scope

### 1. Persistent Pending Actions

当前 `PendingActionCenterSnapshot` 只聚合分类和数量。`v1.8.0` 先冻结真实待处理条目合同，建议至少包含：

- 稳定 ID；
- kind / category；
- source type 与 source ID；
- reason code 与可本地化解释；
- priority；
- `pending / deferred / resolved / dismissed` 状态；
- created / updated / resolved 时间；
- 是否属于 Pro 自动化；
- 可执行动作集合与目标入口。

来源范围：

- OCR / 截图待确认；
- 酒店水单草稿；
- 本地邮箱候选；
- 云收件箱候选；
- 疑似重复；
- 订阅异常；
- 本地与 hash-only 云端数据清洗建议；
- 月结前缺资料项；
- 需要用户处理的同步冲突。

事实边界：原始账单、订阅、水单草稿和同步记录仍是业务真源。待处理表只保存引用、原因和用户决策，不复制完整账本、PDF、OCR 原文或邮箱正文。

### 2. Review Lifecycle

- iPhone 提供逐条复核、稍后处理、确认和忽略路径，并能从首页看见剩余数量。
- iPad / Mac 提供多选、分组和批量操作；只有可逆且可预览的动作允许批量执行。
- 在来源模块处理后，待处理中心必须同步消失；从待处理中心处理后，来源模块状态也必须更新。
- 已解决或已忽略条目不能因重启、重新分析或 CloudKit 拉取无条件复活。
- 忽略和撤销必须有清晰的作用范围，不能污染未来无关交易。

### 3. Human-Readable Sync State

把当前面向调试的长文本同步日志收敛成稳定状态模型：

- disabled；
- checkingAccount；
- syncing；
- waitingToUpload；
- upToDate；
- offline；
- needsConflictReview；
- failedWithLocalDataSafe。

用户界面只展示人能理解的状态、上次成功时间、是否有待上传内容和是否需要处理冲突。完整计数与阶段日志继续留在开发者诊断，不作为普通用户的主状态文案。

### 4. Month Close MVP

月结检查从现有待处理事实生成，不建立第二套不一致的异常扫描：

- 未确认记录；
- 疑似重复；
- 订阅异常；
- 未归档酒店水单；
- 低置信度或分类待确认；
- 缺失凭证；
- 月结包是否生成。

用户可以完成本月、查看完成时间和重新打开。完成本月不是锁账，不阻止后续编辑，也不能替代备份。

### 5. Spanish And Brazilian Portuguese Cohort

本版本新增：

- App UI：西班牙语 `es`、巴西葡语 `pt-BR`；
- ASC metadata：Spanish (Spain)、Spanish (Mexico)、Portuguese (Brazil)；
- 识别 profile：`es-ES`、`es-MX` / 拉美 fallback、`pt-BR`；
- 西语重点：EUR / MXN / 拉美币种、IVA、propina、comprobante、factura、服务费；
- 巴葡重点：BRL、PIX、cartão、CNPJ / CPF 脱敏、NF-e、subtotal、服务费和小数逗号；
- 每种 UI 语言 20-50 条脱敏或高拟真样本，覆盖支付、小票、订阅和酒店水单。

六项语言门禁以 [v1.8.0-i18n-release-matrix.md](v1.8.0-i18n-release-matrix.md) 为版本验收源。

## P1 Scope

P1 只有在 P0 合同、语言组和性能基线稳定后才能进入：

- 云端别名建议成功响应缓存；
- 持久化 cooldown / failure backoff；
- Worker 配额和最小日志策略；
- 规则来源、最近命中和影响范围的只读解释；
- 现有 AL Dashboard 增加匿名聚合的待处理产生 / 解决、月结开始 / 完成、同步结果和建议采纳漏斗。

完整规则中心、Saved Views 和订阅省钱看板保留给 `v1.9.0`，不能因 P0 提前完成而扩入本版本。

## Data And Sync Contract

实施前必须先回答：

1. 哪些待处理条目可以从来源确定性重建？
2. 哪些用户决策必须持久化，避免已处理事项复活？
3. 哪些决策需要跨设备同步，哪些只属于单设备临时状态？
4. 忽略、解决和撤销如何与来源对象的 revision 对齐？
5. 过期来源或已删除来源如何清理待处理引用？

推荐原则：

- 可重建的建议本体不直接跨设备同步；
- 用户的解决 / 忽略决策以稳定 source identity 和 revision 作为边界；
- 任何新的 SQLite table、CloudKit record type / field / index 都必须有迁移、旧备份兼容、离线回归和 Production schema 部署证据；
- 不能用云端同步状态阻塞本机手动记账。

最终 schema 只有在设计评审和迁移测试通过后才能写入本文档，不在 Planning 阶段假定具体表结构。

## English Primary Language Carry-Forward

- Xcode `developmentRegion = en`；

## Acceptance

### Functional

- 同一来源只产生一个有效待处理事项，状态迁移可解释。
- App 重启后 pending / deferred / resolved / dismissed 结果保持一致。
- 来源模块和待处理中心无双重状态或孤立引用。
- 用户能从一个入口处理完所有 P0 待处理类型并达到 empty state。
- 月结完成后仍可编辑账本并重新打开检查。

### Reliability And Performance

- 20,000 条隔离账本下，待处理中心打开和 Tab 切换不低于 TS 117 已验证体感基线。
- 待处理分析和月结检查不在 SwiftUI `body` 或 UI actor 重复扫描全量账本。
- iCloud 离线、401、超时和冲突时，本机账本与逐条处理保持可用。
- 解决后的同步冲突和待处理事项不会因 stale remote metadata 复活。

### Localization

- 英语、简中、繁中、日语、韩语基线不回退。
- 西语和巴葡完成所有 target key 覆盖、识别包、样本、地区专项、截图、ASC metadata 和人工审校。
- 西语 / 巴葡未 Ready 时，不能在 App Store 描述中宣称完整支持。

### Privacy And Entitlement

- 待处理持久化不新增原始 PDF、OCR、邮箱正文或精确账本数据的云端副本。
- 匿名观测只上传 allow-list 内的操作、结果、数量和耗时 bucket，不上传用户标识或原始待处理条目。
- Free 用户能逐条完成全部基础处理；Pro 只提升集中、批量和自动检查效率。

## Product Evidence

现有 AL Dashboard 只增加聚合口径：

- pending generated / resolved / dismissed count；
- unresolved age bucket；
- month close started / completed count；
- suggestion shown / accepted / later rule-hit count；
- sync completed / failed / conflict-review count；
- pending center open duration bucket。

不引入稳定用户 ID，因此不能把事件次数解释为 DAU、留存率或用户级转化率。

## Non-Goals

- 不新增第六种以上的第三个 UI 语言；本版本语言组固定为西语和巴葡。
- 不做银行账户直连、预算、投资组合、信用评分或财务建议。
- 不做通用 AI 聊天首页或让模型直接计算金额、执行规则、完成月结。
- 不完成全量附件保险箱、公开分享网页或团队协作。
- 不为 tvOS / visionOS 增加新的可写业务能力。
- 不新增 Worker 服务；P1 优先复用现有 folio Worker 和 Common API 职责边界。
- 不改变 StoreKit Product ID、历史数据访问权或基础识别免费承诺。

## Execution Order

1. 完成 `v1.7.0` 发布决定和语言 / ASC 证据归档。
2. 冻结 PendingAction、月结和同步状态合同，同时锁定西语 / 巴葡样本与术语表。
3. 先写 Core / persistence 回归，再实现持久化和迁移。
4. iPhone 逐条复核与 iPad / Mac 批量工作台并行，但共用同一状态机。
5. 产品文案冻结后完成全 target 翻译、识别包、截图和 ASC metadata。
6. 最后接匿名聚合指标、真实设备性能、CloudKit Production schema 和发布材料。

## Risks

- 待处理状态持久化与来源确定性重建如果边界不清，会产生重复、复活和孤立记录。
- 跨设备同步全部建议会放大 stale state；只同步用户决策也需要稳定 source identity。
- 西语地区差异大，不能用一个 `es` 词表假设西班牙、墨西哥和全部拉美票据一致。
- 巴西 PIX / NF-e 和隐私字段需要独立脱敏规则，不能只翻译英文 receipt 样例。
- 两种新语言会增加截图与审核成本；若资源不足，应削减 P1，而不是降低语言门禁。

## Rollback

- 每个 GOAL 必须可独立回滚；语言包保持纯数据和 fallback-friendly。
- schema 变更必须提供向前迁移和旧备份恢复测试，不能依赖删除数据库回滚。
- 云端辅助增强可以服务端关闭，且不影响本机建议。
- 若新语言未通过审校，保留工程内测试资源但不加入 ASC 公开 locale，不能伪装为 Ready。
