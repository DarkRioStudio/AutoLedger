# AutoLedger tvOS 只读看板设计

更新日期：2026-06-06
适用目标：`GOAL-1580`
当前状态：设计完成，待进入 `GOAL-1581` 实现评估

## 1. 目标

tvOS 首版不是“客厅里的记账 App”，而是“客厅里的账本总览屏”。

它承担的职责只有三件事：

1. 用远距离可读的方式展示本月消费状态。
2. 让家庭成员快速浏览分类占比、趋势和摘要。
3. 在不暴露过多隐私细节的前提下，作为只读展示端复用主账本数据。

它不承担导入、编辑、删除、恢复、批量清洗、CSV / JSON 操作或任何写入账本动作。

## 2. 产品边界

### 2.1 只读边界

- 不新增账单。
- 不导入文件。
- 不编辑分类、商户、备注或金额。
- 不展示候选账单、识别队列、最近删除、调试日志。
- 不提供 iCloud 手动同步按钮、备份恢复按钮或设置页中的危险操作。

### 2.2 数据边界

- 首版只读取“单一正式账本”的稳定展示快照。
- 候选账单、待复核账单、最近删除、OCR 原文、截图原图和调试记录不进入 tvOS 展示。
- 统计口径与 iPhone / iPad / Mac 保持一致：
  - 今日口径复用 `TodaySpendingSummary`
  - 月度口径复用 `MonthlySnapshot`
  - 分类 / Top 商户 / 趋势只基于正式活跃账单

### 2.3 隐私边界

- 默认进入“摘要优先”模式，不默认展示完整最近账单明细列表。
- 提供显式“隐私隐藏”开关：
  - 隐藏金额
  - 隐藏商户名
  - 隐藏最近账单列表
- 在隐私隐藏开启时，保留趋势、占比和相对变化，不显示具体消费对象与金额。

## 3. 信息架构

tvOS 首版建议采用单场景、一屏一主题、遥控器左右切换的结构。

### 3.1 一级导航

建议保留 4 个主页面：

1. 总览
2. 分类
3. 趋势
4. 摘要

不建议首版做复杂侧边栏，也不建议在 tvOS 首页复用 iPad / Mac 工作台结构。

### 3.2 页面职责

#### 总览

- 本月总支出
- 本月账单数
- 日均支出
- 与上月对比
- 今日支出摘要
- 数据更新时间 / 是否过期

这是默认进入页，也是大多数家庭场景下最常驻的一页。

#### 分类

- 本月分类占比
- Top 3 分类金额
- 各分类金额条形图
- 可切换“金额排序 / 占比排序”

分类页重点是“看结构”，不是看明细。

#### 趋势

- 最近 7 天趋势
- 最近 30 天趋势
- 月内按周分布
- 异常高消费日提示

趋势页重点是“看变化”，不是看每笔交易。

#### 摘要

- 年度累计支出
- 月度对比卡片
- Top 商户
- Top 分类
- 最近账单只读摘要

摘要页允许出现有限度的最近账单信息，但应保持低密度。

## 4. 页面布局草案

### 4.1 总览页

屏幕分成三块：

- 顶部：月份标题、数据更新时间、隐私模式状态
- 中部主视觉：本月总支出大数字 + 本月账单数 + 与上月对比
- 底部辅助区：今日支出、日均支出、Top 分类、Top 商户四张大卡

远距离阅读优先级：

1. 本月总支出
2. 与上月对比
3. 今日支出
4. Top 分类 / Top 商户

### 4.2 分类页

- 左侧大面积 donut / ring 或水平条形图
- 右侧列出 Top 分类卡片
- 底部提供排序模式切换和时间范围切换

避免首版上太多分类标签。默认只展示前 5 类，其余合并为“其他”。

### 4.3 趋势页

- 中部主图：最近 30 天趋势
- 下方次图：最近 7 天趋势或周视图
- 右侧或底部：异常日、最高消费日、最低消费日摘要

首版不要堆太多统计学解释，重点是让用户一眼看出“最近花得多还是少”。

### 4.4 摘要页

- 顶部：年度累计和本月累计
- 中部：Top 商户 / Top 分类
- 底部：最近账单摘要列表，默认最多 5 条

最近账单条目建议只显示：

- 商户或分类 fallback
- 金额
- 日期 / 时间简写

不显示长备注，不显示原始来源文案，不显示 OCR 信息。

## 5. 遥控器与焦点导航

tvOS 首版应把焦点模型做得极简。

### 5.1 焦点原则

- 默认焦点始终落在当前页的主切换控件上。
- 同屏最多只保留一层主要焦点区域。
- 不做深层嵌套焦点迷宫。

### 5.2 推荐交互

- 左右：切换一级页面或切换时间范围
- 上下：在当前页卡片 / 图表 / 列表间移动焦点
- 点击：展开只读详情卡
- Menu / Back：关闭详情，返回当前页主焦点

### 5.3 首版不做

- 不做复杂筛选弹层
- 不做多层 drill-down
- 不做键盘输入
- 不做搜索

## 6. 同步与快照口径

tvOS 首版展示数据必须来自“稳定快照”，不能直接把临时内存状态当作展示真相。

### 6.1 快照要求

- 只展示正式活跃账单
- 必须带 `updatedAt`
- 必须能表达 `isSnapshotStale`
- 必须能区分“没有数据”和“数据未同步”

### 6.2 状态分层

建议 UI 明确区分以下状态：

- `empty`
  - 当前正式账本没有数据
- `fresh`
  - 已拿到最新快照
- `stale`
  - 有快照，但同步可能过期
- `unavailable`
  - 当前无法读取任何有效快照

### 6.3 实现建议给 GOAL-1581

- 由 tvOS target 读取只读展示快照，而不是复用 iPad / Mac 的可写工作台状态。
- 若直接复用 CloudKit / 本地 SQLite 成本过高，应优先评估“派生 dashboard snapshot”的方式。
- tvOS 不单独发明统计逻辑；图表和指标应由共享读模型构建。

## 7. 隐私模式

隐私模式必须是一等功能，不是角落里的小开关。

### 7.1 建议模式

- 标准模式
  - 显示金额、商户、分类、趋势
- 家庭展示模式
  - 显示金额与分类，不显示最近商户列表
- 完全隐藏模式
  - 金额与商户都打码，仅保留趋势、占比和变化方向

### 7.2 打码规则

- 金额：显示为 `***`
- 商户：显示为“已隐藏”
- 最近账单：整块替换为隐私提示卡

## 8. 首版成功标准

`GOAL-1580` 完成后，我们至少应达成：

1. tvOS 首版只读边界明确，不再和 iPad / Mac 工作台职责混淆。
2. 一级导航、页面职责、焦点模型和隐私模式有清晰定义。
3. 数据口径明确复用正式账本稳定快照，不把候选区或调试数据带入展示端。
4. `GOAL-1581` 可以直接基于本设计做 target / scene / 焦点和展示数据入口评估。

## 9. 非目标

本设计不包含以下内容：

- tvOS 实际 SwiftUI 代码
- tvOS build / simulator smoke
- tvOS App Store Connect 平台接入
- tvOS 截图导出
- tvOS 数据写入、编辑或导入能力

## 10. 下一步

进入 `GOAL-1581` 时，建议只做三件事：

1. 评估 `AutoLedgerTV` target 的最小 scene 结构与焦点导航。
2. 明确 tvOS 读取展示快照的最小可实现路径。
3. 用极小 UI smoke 验证“总览 / 分类 / 趋势 / 摘要”四页是否适合 tvOS 遥控器浏览。
